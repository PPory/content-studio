# Supabase + 飞书数据规则

这份规则描述迁移完成后的目标。切换前 D1 仍然服务线上请求，Supabase 只接收可重复的影子导入；核对完成后再一次性切换，避免长期双写。

## 数据放在哪里

- Supabase 是业务真源：灵感、选题、稿件正文与版本、素材、标签、关系、发布反馈、同步状态和冲突记录。
- 飞书是可编辑的协作映射：稿件、洞察、知识卡片、计划、网页笔记和复盘用文档；灵感、选题、素材、发布数据用多维表格。飞书不是唯一副本。
- Supabase Storage 保存工作台插入的图片；飞书文档保存上传后的飞书图片副本和映射。
- Obsidian 只做可读归档，不参与双向同步，也不承载运行状态。
- 书架和有版权限制的原始文件保留本地，不进入飞书。
- 洞察抓取原料、D1 稿件/素材/灵感的 Markdown 归档只是可读副本，不再作为独立文档重复导入；洞察成品、计划、知识卡片和网页批注才进入 `content_documents`。

## 同步边界

- 正文按业务 ID 一一映射，标题不是身份；重命名不会生成第二篇。
- 工作台保存先写 Supabase，再异步同步飞书；飞书变更通过事件回调进入同步队列。
- 两边都改过时不自动覆盖，写入冲突记录，由用户选择保留工作台、保留飞书或合并。
- 图片正文只保存稳定资产引用，不保存临时签名链接。
- AI 助手经工作台领域接口读取 Supabase 内容；它只能提出候选，不能绕过确认修改正文或业务状态。

## 飞书知识库结构

```text
01 创作项目 / 年份 / 项目 / 主稿与平台版本
02 洞察 / 年份
03 知识卡片 / 年份
04 每日计划 / 年 / 月
05 网页批注 / 来源站点
06 工作台数据 / 灵感、选题、素材、发布数据
07 月度复盘
08 已发布索引
99 回收站
```

## 切换门槛

1. D1 全表影子导入的行数、主键、关系和正文哈希一致。
2. 工作台通过 `/wb/*` 在 Supabase 读写通过；不让前端直连数据库。
3. 至少一篇带图稿件完成工作台 → Supabase → 飞书 → 工作台回读。
4. 完成最终短暂停写和增量核对后，Supabase 才升为业务真源；D1 保留只读回退期，不长期双写。
