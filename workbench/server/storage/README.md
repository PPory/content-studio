# 本地工作区存储基础

本目录是本地工作区的数据与领域基础。只有显式调用 `openWorkspace()` 或
`startWorkspaceRuntime()` 时才会创建目录和数据库；测试必须传入系统临时目录，
避免写入真实的 `Documents/Xenho`。

## 约束

- 默认根目录为 `Documents/Xenho`，测试必须显式传入系统临时目录。
- 业务记录使用 SQLite，启用外键、WAL、完整同步和版本化 migration。
- 删除先写 `deleted_at`，本层不提供硬删除接口。
- 图片、书籍、附件和导入文件保存真实字节；数据库只记录哈希、相对路径和稳定的 `asset://<id>`。
- 导入必须通过批次和逐项结果留下对账记录。
- 已发布 migration 不得修改；新增变更只能追加连续版本。

阶段 2 已追加领域模型、业务状态机、真实性硬闸和本地持久任务队列。

- `openWorkspace()` 只打开存储，不注册或执行任务，供迁移、恢复和只读检查安全使用。
- `startWorkspaceRuntime()` 必须由运行时显式调用，并为每种计划任务提供允许列表中的处理器；持续轮询可停止，未知任务不会按成功处理。
- 领域写操作必须由受信调用方显式传入 `actor`。AI 写操作只能重放已确认且版本、目标、内容完全一致的候选。
- 后台生成处理器只能产出候选，不能直接写正文、状态或发布记录。

Vite 本地启动入口已经显式打开工作区并运行候选输入扫描。阶段 3 再让页面、AI 和扩展消费本地接口，并把扫描输入转成待确认候选；阶段 4 才导入现有业务数据。
