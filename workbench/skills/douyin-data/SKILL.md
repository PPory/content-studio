# 抖音账号数据

把抖音创作者后台的数字搬进创作工作台的「数据」页，让它和其他平台画在同一张趋势图上。

## 为什么是这个做法

抖音开放平台要企业资质，个人号拿不到 API。爬 App 端接口风控极严且违反条款。**唯一稳妥的路是用机主自己已登录的浏览器，下载平台自己提供的导出文件**——数据是平台给的，只是换个地方看。

## 硬约束（越过任何一条就停下问人）

- **只碰机主本人的账号**，用他自己已授权的浏览器会话。绝不登录、绝不输密码、绝不碰别人的号。
- **遇到验证码、滑块、二次验证：立刻停**，告诉他需要手动过一下，不要尝试绕过。
- **不改后台任何设置**，不发布、不删除、不回复评论。只读 + 下载。
- **频率上限一天一次**。数据本来就是按天更新的，抓得再勤也没有新信息。
- 下载的文件放 `creator-workbench/data/douyin/`，不要进 vault（那是知识库，不是运行数据）。

## 工作流

### 1. 打开后台

用 Claude in Chrome（`mcp__claude-in-chrome__*`）。先 `tabs_context_mcp` 看现有标签，再 `tabs_create_mcp` 开新标签，导航到 `https://creator.douyin.com/creator-micro/data-center/content`。

**没登录就停**——告诉他去登录，别自己尝试。

### 2. 取数

优先走**官方导出**：数据中心里能下 Excel/CSV 的地方就下，落到 `data/douyin/YYYY-MM-DD-<类型>.xlsx`。

导出不可用时，退回读页面上可见的汇总数字（粉丝总数、近 7 天播放量），用 `read_page` 或 `get_page_text` 取，**不要**截图后靠肉眼认数字。

### 3. 写进工作台

**优先走内容级**：下到的导出文件里有「一条视频一行」的话，直接让用户在工作台「数据 → 数据来源」里把文件拖进去——那条路会走预览确认，列名认错了他当场看得出来。**不要绕过预览直接 POST**：解析器只能靠列名认字段，认错了不报错，只会让一列数字安静地进错格子。

只拿到账号级汇总数字（粉丝总数、近 7 天播放量）时，才 POST 到 metrics（工作台得开着，`npm run dev`）：

```bash
curl -X POST http://127.0.0.1:5180/api/metrics \
  -H "content-type: application/json" \
  -d '{"date":"2026-08-10","platform":"抖音","followers":12345,"views":67890,"note":"后台导出"}'
```

> Windows 上中文 JSON 别用 curl（Git Bash 会按 GBK 编码），用 `python -X utf8` 或 node 发请求。

写完在「数据 → 数据来源」里就能看到粉丝趋势线，和其他平台画在同一张图上。

**不新建页面、不自己解析 Excel**：内容级走工作台的导入（它认得 xlsx 和 csv），账号级走 metrics 接口，原始导出文件留在 `data/douyin/` 供以后深挖。

### 4. 回执

告诉他：抓了哪天的数据、粉丝/播放各是多少、原始文件存在哪。如果中途停了（验证码、没登录、导出按钮找不到），**如实说停在哪一步**，不要用页面上别的数字凑数。

## 状态

⚠️ **这份 skill 还没有端到端跑通过**——写它的时候 Claude in Chrome 扩展没连上（`tabs_context_mcp` 报 "Browser extension is not connected"）。第一次用之前先确认扩展已连接，跑的时候留意实际的页面结构和上面描述的是否一致，对不上就改这个文件。
