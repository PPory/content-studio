## 1. 分析目标

把大量社媒和行业材料压缩成四个问题的答案：

1. **注意什么？** 哪些变化、新信号和问题值得进入注意力范围？
2. **学什么？** 哪些知识缺口会提高理解这个领域的杠杆？
3. **想什么？** 哪些冲突、反例或跨领域连接值得形成自己的判断？
4. **写什么？** 哪里存在真实需求但优质解释供给不足？

报告不是“本周新闻摘要”，也不是“热门话题排行榜”。最终价值在于改变创作者接下来的注意、学习、研究或写作安排。

## 2. 从证据到洞察的层级

严格区分以下层级：

### Observation

材料中可以直接看到的内容，例如某些作者开始反复讨论 eval、某个评论区持续追问出处、多个帖子围绕同一争议。

### Pattern

跨证据出现的结构，例如讨论重点从“生成能力”迁移到“可靠性”，或同一概念在不同圈层独立出现。

### Interpretation

对模式的解释，例如“生成逐渐商品化后，验证成为瓶颈”。这是分析，不是原始事实。

### Implication

该解释对学习或内容创作意味着什么，例如应该补齐 evaluation methodology，或出现一类新的选题窗口。

### Action

将其放入 Watch、Explore、Learn、Write 或 Ignore，并给出具体下一步。

不要跨级跳跃。每个 Top Insight 至少形成：

`Evidence → Pattern → Interpretation → Implication → Action`

## 3. 十一个必检雷达

### 3.1 Emerging Signals：值得关注的新信号

寻找：

- 频率或互动正在上升的概念
- 多个圈层独立出现的相同问题
- 原本小众的方法进入更大社区
- 旧问题出现新的语言或解释
- 讨论焦点从 A 转向 B
- 专家注意力从一个主题迁移到另一个主题
- 新的失败模式、工作流或行为习惯
- 高价值但尚未成为热门的弱信号

优先描述“变化”，而不是静态 topic。例如：

- 弱：本周很多人在讨论 AI coding。
- 强：AI coding 讨论从生成速度转向验证、测试与责任边界。

### 3.2 Learning Radar：值得学习的知识缺口

寻找：

- 高频出现但材料没有解释清楚的概念
- 讨论中反复被引用的论文、理论、工具或术语
- 圈内人默认知道、圈外人可能缺失的背景
- 同一术语被不同人以不同含义使用
- 争议背后的基础知识缺口
- 用户看不懂但大量高手在转发的内容
- 能连接多个现象的高杠杆概念

对每个知识缺口回答：

1. 需要补的具体概念是什么？
2. 为什么现在值得学？
3. 学到什么深度就足以支持判断或写作？
4. 建议从哪些一手材料开始？
5. 它与现有知识的连接是什么？若无创作者画像，标记未知。

把学习过程设计为：

`看到 → 压缩核心观点 → 对比旧认知 → 连接已有知识 → 应用到具体问题`

### 3.3 Content Opportunity Radar：值得写的内容机会

不要问“什么最火”，要问：

> 哪里同时存在注意力、困惑、供给缺口和可形成观点的张力？

每个选题至少检查：

1. **需求**：材料中是否有人明确关心、追问或争论？
2. **增量**：现有内容是否已经说透？
3. **证据**：本周材料是否足以支撑一篇文章，还是需要继续研究？
4. **供给验证**：是否完成目标语言、公开 Web 或目标平台的内容供给审计？只在材料中没看到，不等于市场没有供给。
5. **时机**：窗口正在打开、已经拥挤，还是更适合常青内容？
6. **个人适配**：有画像则评估；无画像则标记未知。

详细分类见第 4 节。

### 3.4 Open Questions：值得持续追踪的问题

不要强迫所有材料形成结论。把以下内容提炼为可持续积累证据的问题：

- 目前存在两个合理解释，但证据不足以区分
- 新现象可能只是短期事件，也可能是结构变化
- 需要跨周观察的注意力迁移
- 需要产品数据、论文或实际案例才能回答
- 某一争议中缺失的关键变量

好问题应当：

- 具有时间窗口
- 能被新证据推进
- 对学习或创作有明确价值
- 不只是宽泛的“未来会怎样”

### 3.5 Cognitive Conflict：值得形成观点的认知冲突

寻找两个都具有合理性的判断之间的冲突：

- 主流观点 vs 扎实反方
- 理论承诺 vs 实际行为
- 降低门槛 vs 提高高级能力价值
- 效率提升 vs 责任或验证成本上升
- 个体体验 vs 群体制度后果
- 创作者叙事 vs 使用者语言
- 同一概念在不同社区中的相反含义

不要统计“哪边人多”就结束。提炼真正的张力、双方最强论据、隐藏前提和需要什么证据才能判断。

### 3.6 Cognitive Surprise：认知意外与盲区

至少检查四类：

1. **反共识**：高质量论证与自己的默认判断相反。
2. **解释失败**：旧知识无法解释新现象。
3. **预测失败**：实际发生的结果与常见预测相反。
4. **群体认知差异**：材料暴露出一个此前未意识到的群体观点。

把惊讶转化为：

- 我们通常假设什么？
- 新材料显示什么？
- 哪个前提可能错了？
- 还需要什么证据？

### 3.7 Cross-domain Connections：跨领域迁移

寻找其他领域已经存在、可解释当前问题的结构：

- 软件工程的抽象、测试和质量控制
- 生物学的生态位、适应与选择
- 游戏设计的反馈循环、进阶和激励
- 行为经济学的切换成本、损失厌恶和信号
- 组织理论的委托代理、责任分配和协调成本
- 媒介理论的信息压缩、注意力与公共知识

每个连接都要回答：

- 来源领域和原始概念是什么？
- 映射到当前问题的对应关系是什么？
- 哪些部分只是类比，不能过度外推？
- 它能产生什么可检验的新问题或选题？

### 3.8 People / Mind Radar：人物与注意力迁移

跟踪的不是单条内容，而是高质量人物的思维轨迹：

- 最近开始关注什么？
- 反复引用哪些概念、论文、工具或人物？
- 与谁争论，争论焦点如何变化？
- 以前的立场是否改变？为什么？
- 注意力是否从 A 迁移到 B？

只有单周材料时，只能描述本周注意力分布或提出“可能的迁移假设”。确认观点变化至少需要过去材料、旧帖或明确自述。

### 3.9 Noise Filter：什么可以不看

识别：

- 同一新闻的大量重复转发
- 只有情绪、没有新事实或论证的帖子
- 已经高度饱和、缺少新角度的话题
- 高互动但与创作者目标无关的梗图、站队和人物八卦
- 无法核实的惊悚说法
- 由平台机制或账号体量放大的内容
- 只保留标题、无法支持解释的条目

Ignore 不是说内容绝对不重要，而是说它在当前注意力预算下没有足够增量。

### 3.10 Source Gems：高价值原始材料

不要让报告只保留二次提炼。额外挑出少量值得读原文的材料：

- 提供罕见一手案例、完整论证或关键反例
- 被多条讨论引用的原始论文、法规、仓库或长文
- 虽然互动不高，但逻辑、数据或方法扎实
- 能直接支持 Learn、Write 或认知更新的材料

对每条 Source Gem 编码：

1. 核心观点是什么？
2. 它挑战或更新了什么默认认知？
3. 能用在什么学习、判断或写作场景？
4. 为什么值得读原文而不是只看摘要？

只列真正值得打开的 3–10 条，不要把全部证据链接重新抄一遍。

### 3.11 Action Layer：行动分类

- **Write**：需求和内容缺口明确，证据足够，已经形成可辩论的主张或清晰解释结构。
- **Learn**：重要性高，但创作者需要先补基础知识或原始材料。
- **Explore**：直觉有价值，但证据独立性、核实或边界仍不足。
- **Watch**：可能是结构变化，需要跨周、跨来源或事件后续确认。
- **Ignore**：重复、饱和、低增量、低相关或证据质量过低。

一条洞察可有主行动和次行动，例如 `Learn → Write`，但必须明确顺序。

## 4. 内容机会分类

### 六种核心机会，必须逐一检查

#### A. 高讨论、低解释

大家反复提到现象，但没有讲清因果、机制或边界。适合深度解释。

#### B. 高争议、低框架

双方在争论，却缺少共同定义、变量拆解和决策框架。适合做争议地图或判断框架。

#### C. 高价值、低关注

对未来能力、制度或工作流影响很大，但互动和覆盖暂时不高。适合早期解释和长期跟踪。

#### D. 高复杂、缺少低门槛解释

原始材料是论文、法规、技术实现或专业争论，读者有需求但进入门槛高。适合通俗化，但不能牺牲准确性。

#### E. 碎片很多、缺少整合

单条内容各自有价值，却没有人把案例、概念、分歧和实践拼成整体。适合 synthesis。

#### F. 新现象、旧框架解释不了

旧叙事无法解释最新行为或结果。适合提出新框架，但先把它作为可被推翻的假设。

### 五种内容缺口

- **解释缺口**：知道发生了什么，不知道为什么。
- **视角缺口**：主流只从 A 看，B 视角被忽略。
- **实操缺口**：口号多，步骤、案例和失败模式少。
- **反方缺口**：一边倒共识中存在有力但被低估的反例。
- **整合缺口**：零散材料缺乏结构、术语和结论层级。

一条选题可以同时属于多个类型，但要指出主类型。

## 5. 评论区需求信号

评论区比原帖更容易暴露未满足需求。重点识别：

- “那 X 怎么办？”
- “为什么没人提 X？”
- “这只适用于 X 吧？”
- “有没有具体案例、数据、来源或步骤？”
- “我还是不理解……”
- “另一个问题其实是……”
- 对定义、边界条件和反例的反复追问
- 大量人纠正同一个误解

不要把一句孤立评论直接变成选题。看它是否：

- 被多人独立提出
- 获得高质量回应或高赞
- 在不同帖子重复出现
- 指向现有内容真正缺失的环节

### 按「这条评论能变成什么」分类，不按情绪分类

正面/负面/中性这种粒度对写作没有任何指导。四类各有各的去处：

| 类型 | 特征 | 去哪一节 |
|---|---|---|
| **求助型** | 提出一个没被解决的问题 | 内容机会 · Insight Card 的「读者问题」 |
| **反驳型** | 挑战原帖的主张 | 认知冲突与反共识 |
| **经验型** | 给出自己摸出来的解法 | 写作时的靶子——**这些是读者已经知道的，绝不能当新东西讲** |
| **共鸣型** | 「太真实了」「演我」 | 情绪证据，计数即可，不单独引用 |

### 赞和回复数，量的不是同一件事

**赞 = 有多少人有同感；回复数 = 有多少人有话要说。** 后者才标识争议点和真问题。

两条都验证过的教训：

- **按赞筛会筛掉最值钱的。** 实测一批 188 条评论里最直接指向选题的那条
  （楼主自己追问「我发现依赖 ai 之后代码能力变弱了……我不知道怎么办」）只有 ♥27，
  而点赞过千的几乎全是零信息量的共鸣。
- **回复数跨帖不可比**，和赞一样：三千条评论的帖子回复数天然在几百，
  二十条评论的帖子只有个位数。直接全局排序，排出来的是「哪篇评论多」，
  而那一篇会用它的梗霸占整个榜单。要比就在同一帖内部比，或每帖只取头部再合并。

## 6. Evidence Ledger、候选综合与 Candidate Registry

把逐块证据写入 `evidence-ledger.jsonl`，建议字段：

```text
id
source_file
platform_or_feed
section
date
author_or_community
title
url
visible_metrics
content_status
selection_context
claim_or_question
evidence_type
candidate_radar
event_cluster
dependency_group
verification_needed
limitations
```

把 Ledger 聚类为候选洞察时，先记录工作字段：

```text
candidate_id
working_title
observations
independent_evidence_ids
counterevidence_ids
pattern
interpretation
implication
knowledge_gap
personal_relevance
content_gap
open_question
cross_domain_connection
falsifier
```

### 跨候选综合

在评分前强制问：

- 哪些事件候选其实是同一个上层机制的不同表现？
- 哪两张卡彼此引用，说明应该合成一个 Meta Insight？
- 论文概念能否解释多个事件，而不是单独占一张卡？
- 合并是否会掩盖关键反例或不同的行动路径？

优先保留上层 synthesis，把具体事件放进 Evidence。不要“一事一卡”。

### Candidate Registry

把所有候选的最终状态写入 `candidate-registry.json`，它是报告的唯一状态源。至少包含：

```text
candidate_id
title
top_card
action_sequence
primary_action
queue_status
priority_score
score_basis
fact_status
pattern_maturity
interpretation_confidence
opportunity_validation
independent_evidence_groups
source_types
load_bearing_unverified
report_sections
```

一页结论、Top Cards、Learn Queue、Write Queue、Watchlist 和行动计数都从 Registry 渲染。不要在不同章节重新手动判断或计数。完整 schema 见 `references/run-artifacts.md`。

## 7. Insight Card 字段

每张 Top Insight Card 必须包含：

1. **结论式标题**：标题强度不得超过 Pattern maturity。
2. **Action**：必要时写顺序，如 `Learn → Write`。
3. **Fact status**：事实核实到哪一层。
4. **Pattern maturity**：Single event / Recurrent / Cross-source / Cross-week / Conceptual / Material observation。
5. **Interpretation confidence**：High / Medium-high / Medium / Low。
6. **Opportunity validation**：Not assessed / Material-only / Supply-audited / Validated / Not applicable。
7. **Priority score + Score basis**：分数为 5 的倍数，并显示 N/I/E/D/L/C/Penalty。
8. **Signal / Observation**：材料中直接观察到什么。
9. **Evidence**：关键原始链接、依赖组、反例和局限。
10. **Why it matters**：为什么值得注意。
11. **Underlying pattern / Interpretation**：机制与竞争解释。
12. **Cognitive conflict**：主要张力；无证据时明确写不足。
13. **Knowledge gap**：需要补什么具体知识。
14. **Personal relevance**：与创作者当前工作、知识和平台的关系；报告正文使用第二人称。
15. **Content opportunity**：机会类型、缺口、Supply Audit 结论与覆盖限制。
16. **Possible angles**：2–3 个不同承诺的写作角度。
17. **Cross-domain connection**：可迁移框架及类比边界。
18. **Open question**：后续积累什么证据、何时复查。
19. **Verification**：逐 claim 的简要核实结果。
20. **What would change my mind**：可观察的推翻条件。

字段没有材料支持时写“本周材料不足”，不要生成看似完整的空话。Fact status 为一手核实，不等于现实模式或解释也能标为 High。

## 8. 多周分析的额外能力

若同时提供连续多周材料，增加：

- Topic Shift：主题内部讨论重点如何迁移
- Signal Velocity：同一信号在各周的出现、扩散和衰减
- Attention Migration：人物、社区或行业关注点如何移动
- Prediction Review：上周 Watch/Explore 判断是否得到新证据
- Question Progress：开放问题有哪些新答案或反例
- Saturation Change：内容机会是否已从空白变为拥挤

比较时使用每周相同的上游筛选策略。筛选规则变化时先解释，不把采样变化误判为趋势变化。
