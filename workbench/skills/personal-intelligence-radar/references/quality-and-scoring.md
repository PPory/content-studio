## 1. 证据独立性

“多条内容”不等于“多份独立证据”。先识别依赖关系。

### 通常不独立

- 同一帖正文与该帖评论
- 同一新闻稿的多次转发或摘要
- 同一作者在同一 thread 的连续发言
- 不同账号复制同一段文字
- 多家媒体只引用同一匿名来源
- 同一产品发布后同步出现的宣传内容

### 相对独立

- 不同平台、不同社区独立提出同一问题
- 不同作者基于各自案例得出相似判断
- 社媒体验帖与原始论文、官方文档相互支持
- 不同事件暴露出同一结构性问题
- 支持和反对两方都承认同一基础事实

在 Evidence Ledger 中给相关证据标记相同的 `event_cluster` 或 `dependency_group`。Top Insight 按独立组计数，不按帖子数量计数。

## 2. 洞察评分

评分用于排序，不用于制造客观精确感。每项 0–5 分，在 Candidate Registry 中记录一句理由。

### Novelty｜新鲜度，权重 15

- 0：常识或标题复述
- 1：熟悉话题，没有新角度
- 3：出现新的案例、边界或组合
- 5：揭示此前未被注意的结构或认知更新

### Importance｜重要度，权重 20

- 0：对学习和创作几乎无影响
- 3：会改变短期关注或一篇内容
- 5：可能改变领域理解、长期学习路线或内容定位

### Evidence｜证据强度，权重 20

- 0：无可追溯证据
- 1：单条、仅标题、严重截断或二手说法
- 3：两组相对独立证据，边界明确
- 5：跨来源证据、一手来源核实、反例检查充分

### Explanatory Depth｜解释深度，权重 15

- 0：只说“很多人在讨论”
- 3：提出机制和关键变量
- 5：机制、边界、反方和可检验预测都清楚

### Learning Value｜学习价值，权重 15

- 0：不指向新知识
- 3：明确一个值得补齐的概念或方法
- 5：该知识节点能连接多个问题并提高长期判断力

### Content Potential｜内容潜力，权重 15

- 0：没有读者需求或已经高度饱和
- 3：有明确问题和可行角度，但供给或证据仍待核实
- 5：需求、供给缺口、证据和独特主张均经验证

### Penalty｜扣分，0–20

- 内容供给已高度饱和：0–8
- 主要由单一事件或营销放大：0–5
- 与创作者目标明显无关：0–4
- 时间窗口已过或无法形成常青价值：0–3

### 计算与显示

```text
Priority =
  Novelty/5 * 15
+ Importance/5 * 20
+ Evidence/5 * 20
+ ExplanatoryDepth/5 * 15
+ LearningValue/5 * 15
+ ContentPotential/5 * 15
- Penalty
```

把结果四舍五入到最接近的 5，不使用 83、97 这类伪精确数字。卡片显示：

```text
Priority score：85
Score basis：N5 · I5 · E3 · D5 · L4 · C5 · Penalty 5
```

解释区间：

- 75–100：Top Insight 候选
- 60–70：进入 Learn / Write / Watch Queue，不进入 Top Cards
- 45–55：Explore，需补证据
- 0–40：通常 Ignore，除非是高重要、低证据的弱信号

## 3. 四轴校准

不要用一个 Confidence 同时表达事实、模式、解释和内容机会。每个候选分别记录四个维度。

### 3.1 Fact status｜事实状态

- **Primary verified**：由法规原文、论文、官方文档、仓库、当事方完整记录等一手来源支持，且不存在明显冲突。
- **Official claim only**：事实是利益相关方的官方主张；确认“它这样说过”，不等于主张已被独立证明。
- **Independently corroborated**：有一手来源并得到至少一个相对独立来源支持。
- **Secondary only**：只有二手报道、摘要或转述。
- **Unverified**：找不到可靠来源或页面不可访问。
- **Contradicted**：可靠来源与材料中的说法冲突。
- **Not applicable**：只描述材料中的观点结构，不依赖外部事实。

### 3.2 Pattern maturity｜模式成熟度

- **Single event**：一个事件或一个案例；可以产生问题，不足以代表趋势。
- **Recurrent**：多个不同事件出现相似结构，但时间跨度或来源仍有限。
- **Cross-source**：不同来源类型或社区独立出现相同结构。
- **Cross-week**：使用可比的多周材料确认变化、扩散或持续性。
- **Conceptual**：主要是论文或理论提出的结构，现实证据仍早期。
- **Material observation**：对本周材料本身的描述，例如被追踪账号的内容形态。

### 3.3 Interpretation confidence｜解释置信度

- **High**：多组独立证据、一手核实、竞争解释和反例检查均充分；上游选择偏差难以推翻机制判断。
- **Medium-high**：解释能覆盖多组证据，主要边界已说明，但仍缺一部分独立验证或长期数据。
- **Medium**：机制合理，但存在竞争解释、单周样本或单一事件限制。
- **Low**：主要是有启发性的 hypothesis。

约束：

- `Single event` 默认最高 `Medium-high`；不得为 `High`。
- `Conceptual` 的论文存在可以是 Primary verified，但现实模式的解释仍可能只有 Medium。
- Fact status 为 Primary verified，不会自动提升 Interpretation confidence。

### 3.4 Opportunity validation｜内容机会验证

- **Not assessed**：尚未检查供给。
- **Material-only**：只知道本周三份材料里没看到或解释不足。
- **Supply-audited**：已用 Brave Search 对目标语言、公开 Web、时间窗口和最接近内容做定向审计。
- **Validated**：除公开 Web 审计外，还有目标平台内搜索、历史发布记录、读者反馈或其他需求证据。
- **Not applicable**：该候选不以内容供给缺口为行动依据。

`Material-only` 不能支持“低竞争、没人写、供给稀缺、内容空白”这类总体供给判断。

## 4. Top Card 晋级规则

同时满足以下条件才可进入 Top Cards：

1. `Priority score >= 75`。
2. 有至少一个可追溯原始链接；模式性判断通常需要两个独立证据组。
3. 事实、模式、解释和内容机会已经分开校准。
4. 有合理反方或竞争解释。
5. 有明确学习、创作或观察行动。
6. 标题强度不超过 Pattern maturity。
7. 有可观察的 `What would change my mind`。

强制降级：

- 分数 60–70：只进 Queue 或 Emerging Signals。
- 单一事件却使用“稳定、持续、正在成为、行业趋势”等模式词：降为 Explore / Watch，或改成事件级标题。
- 无历史基线却声明注意力迁移或长期模式：降级。
- 承重事实 Contradicted：删除或重写。
- 承重事实 Unverified / Secondary only：不能以 `Write` 为第一行动。
- 关键供给缺口只来自材料缺席：不能以 `Write` 为第一行动。

默认保留 3–5 张 Top Cards，目标 4 张。弱信号不靠进入 Top Cards 才算被保留；可以进入 Emerging Signals、Explore 或 Watch。

## 5. 行动映射

### Write

作为第一行动时必须同时满足：

- 读者问题有证据
- 增量主张清楚
- `Opportunity validation = Supply-audited / Validated`
- 证据包足以支持文章结构
- 承重事实没有 Unverified / Contradicted 阻断项
- `queue_status = ready`

### Learn → Write

- 选题价值明确，但需要先读论文、法规、方法或原始实现
- 事实大体成立，文章主张取决于知识补齐
- `queue_status = needs_research`

### Explore → Write

- 直觉新鲜，但需要找更多事件、反例或独立来源
- 承重事实仍有重要未核实项
- 内容供给尚未完成审计

### Learn

- 重要，但当前主要价值是补高杠杆知识节点
- 明确学习范围、起点和预期产出，不写泛泛“继续研究”

### Explore

- 可能形成新框架，但目前是 hypothesis
- 指明下一步要找哪类证据

### Watch

- 需要跨周观察速度、扩散、兑现或事件后续
- 写出可观察触发器和复查时间

### Ignore

- 重复、饱和、低增量、明显营销或与当前目标不相关
- 写出重新打开条件，避免永久封存误判

## 6. 选择偏差与反证检查

每条 Top Insight 回答：

1. 上游 Top-N 或详写规则是否制造了这个模式？
2. 这是同一事件的传播，还是不同来源的独立出现？
3. 是否存在与结论相反的帖子、评论或一手证据？
4. 只看高赞评论是否忽略少数但有力的反方？
5. 正文截断是否删掉关键限定条件？
6. 平台文化或被选账号名单能否解释现象？
7. 拿掉互动指标后，判断是否仍成立？
8. 是否把“重要”误写成“流行”？
9. 是否把“当前材料没看到”误写成“没有发生”？
10. 是否有更简单的替代解释？
11. 搜索结果是否都引用同一原始来源？
12. 是否主动做过一次反向搜索，而非只找支持材料？

若关键反例无法排除，降低 Interpretation confidence，并把竞争解释写进卡片。

## 7. 内容供给审计与 Write 门槛

一个 Write 候选至少明确：

- **读者问题**：读者具体想知道或解决什么？
- **现有供给**：最接近的 3–5 篇内容讲到了哪一层？
- **真实缺口**：没人写、只有新闻转述、缺机制、缺框架、缺实操，还是已被说透？
- **增量主张**：文章比现有内容多提供什么？
- **证据包**：案例、数据、原始材料和反方是否齐全？
- **文章承诺**：读完后能理解、判断或完成什么？
- **时效和载体**：窗口多长，适合公众号、小红书、Newsletter 还是短帖？
- **个人适配**：有画像则具体判断；无画像写 Unknown。

### Supply Audit 最小流程

1. 设定目标语言、公开 Web 或明确平台、30/90 天或常青窗口。
2. 运行至少 3 个不同意图的查询：概念本身、解释/为什么、实操/争议。
3. 找出 3–5 个最接近的已有内容。
4. 排除发布稿复制、低信息短帖和同源转载。
5. 记录每篇覆盖到哪一层，以及仍缺什么。
6. 明确覆盖限制：公开 Web 不能代表微信、小红书等站内全量。

三圈验证：

1. **有人关心吗？** 用讨论、追问、评论困惑和跨来源出现验证。
2. **你能写好吗？** 用 creator profile、已有知识和可取得材料验证。
3. **写出来有增量吗？** 用 Supply Audit 验证。

缺知识 → Learn；缺事实 → Explore；缺时序 → Watch；缺增量 → Ignore。

## 8. 跨候选综合

在最终排序前，检查：

- 两张事件卡是否共享一个更高阶机制？
- 两张卡是否在正文里互相引用，说明它们应合并？
- 一条论文概念是否能解释多个事件，而不是单独占一张概念卡？
- 合并后的 Meta Insight 是否能保留不同事件的反例与边界？

优先保留：

```text
Meta Insight
├── Event A：支持机制的一面
├── Event B：暴露机制的另一面
└── Competition：能否由更简单解释覆盖
```

不要把两个相关事件机械地拆成两张长卡，再在每张里重复另一张。

## 9. 最终删减清单

删除或降级：

- 标题换一种说法，没有机制
- 只有一个高赞帖，却写成稳定趋势
- 使用“大多数、普遍、全网”但分母不可得
- 把官方自述当独立证明
- 把相同新闻的转发数量当趋势
- 事实已核实，却把未核实的因果一起标为 High
- 只在材料中没看到，就断言内容市场没有供给
- 卡片 Action=Write，Queue 却写 Needs research
- Top Card 分数低于 75
- 反共识只是为了反对，没有扎实论证
- 跨领域连接只是漂亮比喻，没有映射和边界
- 人物变化没有历史证据
- 所有字段都写得很满，但没有真实链接或可推翻条件
- 同一主张在一页结论、卡片、Queue、跨领域和 Source Gems 中反复完整重写

宁可交付 4 张强卡片，也不要凑 8 张平庸卡片。
