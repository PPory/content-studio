# Xenho 网页助手

在普通网页、飞书等在线文档中划取文字，直接连接本机 `content-studio` 的 Xenho OS。

## 安装

1. Chrome 打开 `chrome://extensions`，开启右上角“开发者模式”。
2. 点“加载已解压的扩展程序”，选择本项目的 `extension` 文件夹。
3. 首次安装时允许扩展读取网页内容。这项权限用于识别你主动选中的文字；内容不会因为安装扩展而自动入库。
4. 批注、提问、对话、灵感和素材需要启动工作台；收件箱收藏可以在工作台关闭时先安全暂存。

## 使用

在网页上选中至少两个字，选区旁会出现 Xenho 小图标。点开后有五个入口：

- 批注：在右侧面板写想法，保存到本地知识库的 `网页批注/`。
- 提问：解释、展开、反驳，结果可再存为批注或素材。
- 对话：选择 Claude Code 或 Codex，围绕选区连续交流。
- 选题：直接把选区转成内容方向，结果显示在“提问”面板。
- 收件箱：主收藏按钮一键保存到收件箱；展开入库菜单后，也可以明确选择“收件箱、灵感库、素材库”。

选区悬浮入口不会再因为页面滚动或窗口变化自动消失；按 `Esc` 或明确点击其他位置可以收起。公众号、动态信息流、富文本编辑器和内嵌正文会同时监听鼠标、触控与浏览器选区变化。

不提供高亮和翻译。

## 数据与权限

- 扩展只连接 `http://127.0.0.1:5180`，不会接触 Cloudflare Worker 或模型密钥。
- 素材和灵感经本机工作台的受保护接口写入 `content-studio` 的 D1 流水线；扩展不再依赖或直连 Notion。
- 工作台关闭时，收件箱收藏会暂存在 Chrome 本地扩展存储，扩展每分钟尝试补传；成功进入工作台后即从待同步队列移除。最多暂存 100 条。
- AI 结果和对话只暂存在当前 Chrome 会话；批注和你主动入库的内容才会落库。
- 默认只发送选区。对话中的“附带选区附近正文”需要手动勾选。
- Chrome 内部页面、Chrome 应用商店及部分浏览器内置阅读器不允许扩展注入，这是浏览器限制。
- 飞书等在线文档需要在正文中真正划取文字；扩展会进入文档内嵌框架，但不会在输入框、搜索框里弹出。
- 收件箱收藏可离线暂存；批注、提问、对话、灵感库和素材库仍需要启动工作台，因为这些动作依赖本地知识库、模型或 D1 接口。

## 更新

代码更新后，在 `chrome://extensions` 找到“Xenho 网页助手”并点刷新按钮，然后刷新已经打开的网页。扩展更新后，旧网页里的悬浮条会失去后台连接；刷新该网页即可恢复。若工作台重启，扩展会自动重新配对。

## 关于“Service Worker（无效）”

这是 Manifest V3 扩展空闲约 30 秒后进入休眠的正常状态，不代表插件损坏。划词、点击扩展图标或打开侧边栏时，Chrome 会自动唤醒它。插件把配对信息保存在当前 Chrome 会话中，休眠和唤醒不会丢失连接；侧边栏右上角的“已连接 / 部分可用 / 未连接”才是工作台的真实状态。
