## 1. 这次重构要解决什么

当前工作台把五种不同维度放在了同一层：

1. 用户任务：收集、构思、写作、发布、复盘；
2. 内容对象：收件、灵感、素材、选题、稿件；
3. 对象状态：待整理、待写、撰写中、待修改、已发布；
4. 自动化状态：待初筛、生成中、核验失败；
5. 工具：热点、洞察、书架、排版、数据。

每个局部都能解释，但陌生用户必须先理解系统的数据结构，才知道下一步该点哪里。重构的目标不是减少几个 Tab，而是让用户只需要理解一条链：

> 从一个想法开始，把它推进成一篇发布过、复盘过、能反哺下一篇的内容。

完成后的工作台需要满足：

- 第一次打开就能回答“我现在该做什么”；
- 开始创作后始终知道“我在哪一步、还缺什么、下一步是什么”；
- 空白起稿、素材起稿、AI 访谈只是三个入口，后面共用同一条内容链；
- 素材、事实来源、正文彼此关联，但不互相污染；
- AI 帮助提问、组织和小幅推动，不替用户编造观点和经历；
- 发布不是把稿件扔出系统，数据也不是一块孤立仪表盘；
- D1、Worker 和 vault 继续作为真实数据来源，工作台不建立第二套业务数据。

## 2. 第一性原理

### 2.1 导航按“用户要完成的事”组织

一级导航不能再代表数据库、后台处理步骤或单个工具。它只承载高频任务和长期资产。

### 2.2 单篇创作只有一条主链

一篇内容的正常路径固定为：

`开始创作 → 策划 → 写作 → 诊断 → 发布 → 复盘`

阶段允许暂存和回退，但不能跳到另一个库后失去上下文。

### 2.3 每一步只要求一个主要决定

每个阶段都必须清楚显示：

- 现在要决定什么；
- 完成后得到什么；
- 下一步会去哪里；
- 不能继续时缺少什么。

### 2.4 内容母版优先，平台适配在后

先把观点、证据、结构和表达完成，再生成平台版本。平台不能在创作一开始就把同一个想法切成几条互不相通的链。

### 2.5 写作与诊断分开

起稿阶段优先保证表达完整，不用实时批评打断写作。初稿完成后再集中做结构、事实、口吻和发布准备检查。

### 2.6 状态必须由事实或明确动作产生

阶段推进、发布状态、核验结果、数据判断必须由可验证条件和用户动作决定，不能由模型猜测，也不能只靠前端改一个标签。

### 2.7 AI 永远不是业务真源

AI 可以：追问、整理、建议结构、提供小推动、生成待确认草案。AI 不可以：

- 编造用户经历或观点；
- 把检索候选冒充已采用素材；
- 绕过核验门槛；
- 自行宣布内容可发布；
- 自行改变项目阶段或发布记录。

## 3. 目标信息架构

### 3.1 一级导航

| 新入口 | 用户问题 | 默认看到什么 |
| --- | --- | --- |
| 今日 | 我现在最值得做什么？ | 可以继续的作品、等待决定的事项、需要复盘的发布 |
| 内容 | 我的内容正在走到哪一步？ | 按创作阶段组织的内容项目，而不是选题库/稿件库 Tab |
| 素材 | 我有哪些可复用的原料？ | 待处理来源、可用素材、核验提醒和引用关系 |
| 发现 | 外面有什么值得关注？ | 热点、洞察、书架中的发现及其转化动作 |
| 复盘 | 哪些假设有效，下一篇改什么？ | 已发布作品、表现判断、结论和下一步实验 |

侧栏底部保留四个全局入口：

- 收集；
- 搜索；
- 创作基线；
- 设置。

“创作基线”是低频长期资产，不挤占每日主导航。它包含定位、用户、内容支柱、表达口吻、内容边界和主平台策略。

跨页面目的地统一放进左侧二级导航，页面内部不再重复同一排入口：

| 一级 | 二级入口 |
| --- | --- |
| 内容 | 项目、选题、稿件、排版 |
| 发现 | 热点、洞察、书架 |

“素材”不再展开数据库对象。进入后直接看到来源到成稿的处理链，并用阶段、类型和核验状态筛选。

月度切换、榜单分类、状态筛选等只改变当前页面内容的控件继续留在页面内；它们不是新的目的地，不进入侧栏。

### 3.2 旧入口迁移

| 当前结构 | 新归属 | 处理原则 |
| --- | --- | --- |
| 总览 | 今日 | 从状态总览改成下一步行动页 |
| 收件箱 | 素材 | 作为“待处理来源”并入统一列表，旧地址自动跳转 |
| 灵感库 | 素材 | 作为“灵感来源”并入统一列表，旧地址自动跳转 |
| 素材库 | 素材 | 作为“可复用素材”并入统一列表 |
| 选题库 | 内容 | 作为兼容期二级入口，候选选题逐步并入项目 |
| 稿件库 | 内容 | 作为兼容期二级入口，正文与版本归属内容项目 |
| 热点 | 发现 | 保留内容，但动作统一为收藏、形成选题、加入项目 |
| 洞察 | 发现 | 作为深度发现来源，不再伪装成创作阶段 |
| 书架 | 发现 | 作为长期来源库；摘录进入素材后参与创作 |
| 排版 | 内容的发布阶段 | 在需要发布时出现，不再作为独立日常目的地 |
| 数据 | 复盘 | 数据导入降为设置；主页面只展示能产生判断的数据 |

### 3.3 不再使用的导航方式

- 不把收件、灵感、素材、选题、稿件作为同层 Tab；
- 不把“卡片/看板”当成内容结构，只作为同一列表的显示偏好；
- 不把对象状态和创作阶段混为一谈；
- 不把排版、封面、标题、AI 续写做成一级入口；
- 不用多个小 Tab 模拟流程。

## 4. 核心对象：内容项目

用户看到的主对象改为“内容项目”。一个项目代表一个想法从策划到复盘的完整上下文。

### 4.1 内容项目包含什么

- 创作简报：目标、受众、要解决的问题、核心观点、内容目的；
- 来源选题：候选选题或临时想法；
- 素材包：实际选中的事实、案例、经历、引用和来源；
- 内容母版：大纲、正文、修订历史和诊断结果；
- 平台版本：由母版派生的公众号、X、小红书、视频号、YouTube 版本；
- 发布记录：平台、时间、链接、采用版本；
- 数据与反馈：数据快照、评论结论、表现判断；
- 复盘结果：验证了什么、失败在哪里、下一次实验什么。

### 4.2 第一阶段不新建第二套内容库

内容项目首先是 Worker 返回的聚合视图，不立即增加 `content_projects` 表：

- `topics` 作为已有选题根；
- `drafts` 作为正文和平台版本；
- `topic_materials`、`topic_inbox` 提供来源关系；
- 发布与反馈继续使用 `drafts` 中的现有字段；
- 没有选题的独立稿件以 `draft:<id>` 作为临时项目展示；
- 聚合、状态推导和异常提示全部在 Worker 中完成，前端只渲染契约。

这样能先重建用户链路，再决定哪些字段确实需要迁移，避免为了新页面复制整套数据。

### 4.3 内容项目读模型

Worker 新增只读聚合契约：

```text
ContentProject
  id
  title
  stage
  stageReason
  nextAction
  blockers[]
  brief
  topic
  masterDraft
  variants[]
  sources[]
  materials[]
  publication
  review
  updatedAt
```

必须同时返回 `stageReason` 和 `blockers`。前端不能只拿一个阶段字符串再自行猜原因。

### 4.4 母版的确定规则

现有一个选题可能有多篇平台稿件，不能让模型或前端随便挑一篇当母版：

1. 只有一篇稿件时，直接作为母版；
2. 多篇稿件且只有一篇与选题主平台一致时，用这一篇；
3. 仍有歧义时返回“需要确认母版”，由用户选择；
4. 第二阶段增加 `topics.primary_draft_id`，以后由该字段做唯一真源；
5. 平台变体增加 `parent_draft_id`，明确从哪一版派生。

## 5. 一篇内容的完整链路

> 2026-08-24 产品决策更新：本节原来的“三个新建起点 + 每篇短简报”已被后续真实使用反馈取代。
> 现役流程是“新建即写”；固定读者、常用平台、默认风格只在「我的创作」设置一次；素材常驻项目右栏；
> AI 访谈变成编辑器内的「聊一聊」，只整理线索且必须显式插入。专家与风格由工作台内置，
> 不依赖外部预设目录；直接新建的空白临时项目在退出确认后删除。下文保留为迁移背景，不再作为现役验收口径。

### 5.1 开始创作

全局“新建”只提供三个起点：

1. 空白文章；
2. 从已有素材起稿；
3. 和 AI 对话梳理后起稿。

三个起点最终都创建同一种内容项目，进入同一个编辑器，不建立三套稿件类型。

#### 空白文章

- 建立空项目和空母版；
- 允许稍后补简报、素材和平台；
- 不因没有标题而阻止开始；
- 默认进入写作阶段。

#### 从素材起稿

- 先选择素材，正文仍为空；
- 素材常驻编辑器右侧；
- 只有用户明确操作时才插入正文；
- 插入位置严格是当前光标；
- 保留素材来源和引用关系；
- 不自动把素材拼成一篇文章。

#### AI 访谈起稿

- AI 先追问用户的目标、观点、经历、冲突和证据；
- 只整理用户实际表达过的内容；
- 先生成创作简报供确认；
- 用户确认后才建立正文；
- 正式起稿前必须能返回继续访谈；
- 模型没有得到的信息必须标为缺口，不得补写成事实。

### 5.2 策划

用户只需要完成一份短简报：

- 写给谁；
- 解决什么问题；
- 核心观点是什么；
- 这篇内容用于拉新、建立信任、转化还是留存；
- 属于哪个内容支柱；
- 还缺哪些证据。

输出是“可写的内容任务”，不是一堆写作技巧。

### 5.3 写作

页面以正文为中心：

- 中间：唯一编辑器；
- 右侧：本篇素材、来源、缺口；
- 顶部：当前阶段和下一步；
- 底部或选区旁：小推动、改写、补充结构等上下文动作。

AI 续写必须显式触发，结果先以可编辑审阅稿出现，确认后才进入正文。最终持久化的仍然是用户确认后的 Markdown。

写作时不常驻展示整套诊断分数，不在用户每写一句时弹问题。

### 5.4 诊断

用户主动点击“初稿完成”后进入集中诊断：

- 主旨是否明确；
- 结构是否支撑主旨；
- 开头是否兑现承诺；
- 场景、故事、对话是否有效；
- 视角、口吻和创作基线是否一致；
- 事实、数据、引用是否有来源并已核验；
- 结尾是否形成行动或余味；
- 是否存在无素材支撑的第一人称经历。

诊断输出按严重度排序：阻塞发布、建议修改、可选优化。每条建议都必须允许忽略、接受或返回正文修改，不能由 AI 直接覆盖全文。

### 5.5 发布

发布阶段才出现：

- 标题候选与选择；
- 摘要；
- 封面；
- 关键词；
- 互动目标；
- 主平台排版；
- 其他平台适配；
- 发布时间和链接记录。

内容母版与平台版本分开保存。排版是当前版本的发布工具，不再跳到一个失去项目上下文的独立页面。

发布动作必须经过专用命令，校验链接、时间和版本，并一次写入发布记录。不能通过通用状态下拉把稿件直接改成“已发布”。

### 5.6 复盘

复盘不是展示所有数字，而是回答：

- 本篇原先想验证什么；
- 问题出在曝光、点击、阅读、互动、关注还是留存；
- 哪个标题、角度、结构或素材起了作用；
- 哪些结论只是样本不足；
- 下一篇具体改变什么。

表现突出时，可以把标题样本、内容角度和平台反馈沉淀回素材库；必须先显示依据并由用户确认。

## 6. 页面设计

### 6.1 今日

首页只展示需要行动的内容，按优先级排：

1. 继续上次未完成的内容；
2. 阻塞中的项目；
3. 等待用户决定的事项；
4. 已发布但需要补数据或复盘的内容；
5. 候选选题。

每张卡只显示：项目、当前阶段、阻塞原因、一个主动作。后台流水线数量可以作为辅助状态，不再占据首页主叙事。

### 6.2 内容

默认是按阶段分组的项目列表：

- 策划中；
- 写作中；
- 待诊断；
- 待发布；
- 待复盘；
- 已完成；
- 已搁置。

筛选包括阶段、内容支柱、平台和更新时间。“列表/看板”只是显示方式切换，不改变信息架构。

项目卡固定显示：标题、当前阶段、内容目的、更新时间、下一步。没有下一步的卡片视为状态错误，测试必须拦住。

### 6.3 内容项目工作区

顶部用阶段条展示 `策划—写作—诊断—发布—复盘`，但不做五个彼此独立的小 Tab。

- 当前阶段占据主区域；
- 已完成阶段可展开查看；
- 下一阶段只有在满足门槛后才能推进；
- 右侧始终显示与当前阶段有关的上下文；
- 返回时回到原列表位置和筛选条件。

### 6.4 素材

素材页用处理状态和类型筛选替代五个库 Tab：

- 待处理来源；
- 可用素材；
- 待核验；
- 已引用；
- 已归档。

类型筛选：来源、想法、观点、证据、故事、方法。后台仍可保留 `inbox/materials` 的不同表与处理状态，用户无需理解它们。

素材详情必须展示：原文、来源、核验状态、关联项目、正文引用位置。删除与归档的可恢复性要照实说明。

### 6.5 发现

发现页整合热点、洞察和书架，但保留各自来源身份。每条发现只提供清晰的转化动作：

- 收藏为来源；
- 提炼为素材；
- 形成候选选题；
- 加入已有内容项目。

“未处理”不作为满屏灰色标签；只有已收藏、已转化或失败时显示状态。

### 6.6 复盘

默认展示需要复盘的已发布内容。进入一篇后，按“目标—数据—判断—行动”组织，不按平台字段堆仪表盘。

账号级趋势放在第二层，只有当数据能支持结论时才显示。数据导入、字段映射和连接状态放进设置。

### 6.7 创作基线

包含五类长期默认值：

- 定位与内容承诺；
- 核心、辐射和潜在用户；
- 内容支柱、栏目和边界；
- 表达口吻与禁止事项；
- 主平台与适配策略。

单篇项目默认继承，允许局部覆盖。覆盖必须显示“本篇与基线不同”，避免用户不知道当前使用哪套约束。

## 7. 状态与数据规则

### 7.1 当前必须先修正的状态冲突

当前数据库中稿件状态只有 `待修改`、`已发布`，前端却展示了 `待发布`、`已弃用`。重构第一阶段先让界面只使用数据库允许的值，禁止继续制造无效写入。

第二阶段再通过正式迁移把稿件状态调整为：

- 写作中；
- 待诊断；
- 待发布；
- 已发布；
- 已弃用。

迁移规则：

- 旧 `待修改` 映射为 `写作中`；
- 旧 `已发布` 保持不变；
- 未完成诊断的历史稿不自动判为待发布；
- 有发布链接和发布时间的稿件才能进入已发布；
- 已弃用是用户明确动作，不由长时间未编辑自动推断。

### 7.2 选题状态与稿件状态不重复判定

选题的 `撰写中/已成稿/已发布` 由关联稿件事实校正；用户只直接决定“待写、开始、搁置”。统一通过 Worker 的关系校正完成，前端不能分别改两边。

### 7.3 阶段推进门槛

| 推进动作 | 必须满足 |
| --- | --- |
| 策划 → 写作 | 有标题或临时标题、有目标受众、有核心观点；空白直写模式可暂缓简报，但显示缺口 |
| 写作 → 诊断 | 用户明确点击“初稿完成”，正文非空 |
| 诊断 → 发布 | 没有阻塞级真实性问题；用户完成或明确忽略其余诊断项 |
| 发布 → 复盘 | 有发布平台、链接、时间和采用版本 |
| 复盘 → 完成 | 有表现判断和至少一条下一步结论；样本不足也是有效判断 |

### 7.4 命令接口代替通用改状态

新增 Worker 命令：

- `POST /wb/projects`：创建统一内容项目；
- `GET /wb/projects`：按阶段列出聚合项目；
- `GET /wb/projects/:id`：读取完整项目；
- `POST /wb/projects/:id/advance`：校验并推进阶段；
- `POST /wb/projects/:id/materials`：调整本篇采用素材；
- `POST /wb/projects/:id/master-draft`：确认母版；
- `POST /wb/projects/:id/publish`：记录发布；
- `POST /wb/projects/:id/review`：提交复盘结论；
- `POST /wb/projects/:id/variants`：从确认后的母版创建平台版本。

所有写命令都要：

- 校验当前状态；
- 在 D1 事务内写入关联数据；
- 支持幂等键，防止重复点击造成重复稿件；
- 返回最新项目和下一步；
- 给出用户可执行的错误提示；
- 由 Worker 定义规则，本地服务只转发。

### 7.5 创作基线数据

创作基线属于业务数据，需要在 D1 中持久化，建议新增：

- `creator_profiles`：定位、承诺、口吻、边界、主平台；
