# 内容机会

面向持续表达的个人创作者，回答「最近有什么值得讲，以及怎样把它变成一篇内容」。

首页以紧凑页头和「发现方向 / 已保存 / 研究线索」视图导航组织任务。视图切换保留输入与候选选择，不调用模型。页面采用统一的细分隔线、列表选择、正文与辅助栏布局；移动端导航横向滚动，内容详情单独展开。

## 使用流程

1. **发现方向**：用户可指定关注点，也可留空，从已有知识和真实用户声音中寻找候选。进入页面不会自动调用模型。重新扫描期间保留上次结果，失败时可继续使用已有机会。
2. **判断是否值得写**：桌面左侧选择方向，右侧阅读完整判断、读者问题、知识依据与证据缺口。小屏先呈现列表，点选后进入详情，返回保留选择。读取、比较不会写业务数据。
3. **选择讲法**：候选只展示开篇、核心判断、风险、缺口与来源数量。选定后展开完整创作简报与材料来源，右侧集中自然语言修改、调整记录和保存。
4. **确认并继续**：用户明确保存后，机会出现在首页「已保存」视图。可以搜索后重开，建立内容项目时继承简报和材料；正文仍由用户决定如何生成与采用。

## 辅助路径

- 已经有明确起点时，手动探索分两步选择知识和读者问题。选择结果始终可查看和修改。
- 完整分析先展示核心判断，再解释问题、依据、认知差和写作入口；侧栏提供目录与知识来源。
- 真实用户声音、研究方向与长期议程保留独立入口，避免成为每篇创作的必填表。

## 真实性与状态

- AI 输出是候选。受众假设与可追溯原话分别标注，不能把关联来源数量称为已核验证据数量。
- 比较与详情切换不调用模型；修改、重新扫描和保存有独立忙态。
- 讲法和未保存修改使用当前浏览器会话内存，在发展页与完整分析之间往返保留。刷新未保存会话会丢失，页面应明确提示。
- 已保存业务数据仍以本地 SQLite 为唯一真源。本次重设计不更改 API、模型或真实性校验规则。

## 验收

`tests/content-bridge-ui.mjs` 使用临时独立工作区，覆盖分步选择、核心判断阅读、保存重开、来源核对、候选切换、小屏返回、搜索、讲法修改和进入创作。AI 响应在测试中使用固定候选，不产生真实模型费用。
