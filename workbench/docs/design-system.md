# creator-workbench 设计体系

工作台的**设计理念、视觉语言和交互规则**，以及那些**做出来看过、然后否掉的方案**——后者和前者一样重要，留着是为了不再试第二次。

- 总体架构和存储契约在 [`design.md`](design.md)，**改架构先改它**。
- 改代码时的硬约束在 `../CLAUDE.md`。**那边写「是什么」，这边写「为什么」。** 两边冲突时以代码为准，然后两边一起改。

落地全在 `src/styles.css` 一个文件里：没有 CSS 框架、没有 CSS-in-JS、没有 UI 库。结构参考 oyorf/person_dashboard 和 Media OS，但每一条落地方式都是自己的。

---

## 零、三条总原则

**1. 用户体验高于技术偏好。** 后端可以复杂，用户触碰的每一层必须丝滑。GUI、CLI、对话式交互、系统反馈都算界面。

**2. 判据只写一处。** 同一个判断散在两处，迟早漏一处，而漏掉的那处通常**不报错**——它只是安静地少做一件事。这条在这个项目里反复兑现：`isChapterFile`、`renderMarkdown`、`fieldIcon`、`vault-dirs.mjs`、外链委托监听，每一个都是把一个曾经散在多处的判据收成了一个。

**3. 宁可不画，也不要画一个点了没落点的东西。** 禁用的按钮比隐藏更糟——点不动又不说为什么，用户的结论是「这功能坏了」。同理：宁可不显示，也不显示一个看着像真的假数。

## 一、颜色

### token 分三层

原始色 → 语义（`--surface` / `--text-1` / `--border` …）→ 组件。**组件里只准用语义层。**

这套语义名是项目原有的，换皮时一处没改到组件文件——那次就是分层的收益兑现的时候。

眉标（`.eyebrow`）用 `--text-3` 而不是 `--accent`：跟大标题同色的话两行会互相抢，小灰字压在大黑字上面才有层次。

**暗色只改语义层的赋值**，不写第二套组件规则。唯一的例外是 `--on-accent`：暗色下 `--accent` 翻成近白，白字压在上面就没了，所以「黑块上的字色」必须单独有个 token。

### 黑白两色，以及三处有意的例外

**不引入第二个颜色。** 彩色点缀会和内容里真正需要颜色的东西（趋势图的平台色、状态的红黄绿）抢注意力；黑白只靠字重、留白和实心块分层次。当前项、当前 tab、主按钮一律是**实心黑块**——黑白配色下淡色底几乎看不出来。

例外一律是**功能性**的，不是装饰性的：

**例外 1 · 标记色**（`--mark-yellow/green/blue/pink`）。选区和高亮必须能压在任意正文上、一眼看见、又不能盖掉底下的字。

**例外 2 · 正文的暖色强调**（`--band` 小标题底衬 / `--emph` 加粗字色 / `--emph-line` 下划线）。这一处比标记色走得更远——标记色只压在字**底下**，这里是**字本身**换了颜色。

理由是**中文的加粗太弱**：字重 400→700 在中文字面上的差别远不如西文，一屏扫过去几乎抓不住重点，而这个工作台的正文有一半是拿来找重点的报告和成稿。

- **色相要和标记黄岔开。** 标记黄的含义是钉死的「这个我圈中了」，底衬说的是「这里开了一节」。所以底衬走粉红那一侧（浅色下合成出 `#fbbfbc`），柠檬黄整个留给高亮和选区。冒烟测试直接断言这两个值不相等。
- **底衬必须写成半透明，不能直接写那个 hex。** 阅读设置里的「纸色」是把米黄铺在 `.ws-main` 背景上，不透明的粉压在暖底上会断层。所以写的是「在白底上正好合成出目标色」的 rgba。
- **暗色要分别翻**：底衬取**浅粉**那一头（把浅色那个 `rgba(244,72,64)` 原样搬过去，会在近黑底上压成一块暗红），字色往亮里翻（`#de7802` 在深底上偏闷）。
- ⚠️ **`--emph`（`#de7802`）在白底上只有 3.1:1**（上一版 `#a2540b` 是 4.9:1），而 16px 粗体够不到 WCAG 的大字豁免线（18.7px）。这是**有意选的观感，不是疏忽**——以后觉得长文读着费劲，先动这个值。

**例外 3 · 数据图的平台色**：固定分配给平台，不按当前有几条线循环。配色跑过对比度校验，浅色下有三个色对比度低于 3:1，**因此表格视图和图例是强制项**，不是可选装饰。绝不做双轴（粉丝和阅读量量级差太多，分成两张图）。

### 黑块 = 「你在这儿」，标记黄 = 「我圈中的」

这条界线要守住，否则界面上分不出「当前」和「已选」：

| | 用在哪 | 回答的问题 |
| --- | --- | --- |
| **黑块**（`--accent` 实心） | 当前页、当前视图、当前 tab、主按钮、互斥的分流选择（入库的「存到哪」） | **位置** |
| **标记黄**（`--mark-yellow`） | 选区、划词高亮、多选打勾（平台闸门的 `.pick`）、打标（素材类型 `.chip`）、问过的追问模式 | **我对它做过什么** |

- **状态筛选条选中的芯片是黑块，不是标记黄**（`.filter-bar .chip[aria-pressed="true"]`，和那排 `.pill-tab` 是同一件事）**。** 它一次只能选一个，说的是「我现在在看哪一档」——那是位置。这里一直用着标记黄，是这条规则的一处漏网；正文换成暖色系之后更明显：一屏上粉底衬、橙加粗、黄芯片三种暖色互相打架，而其中只有前两个是内容。**入库抽屉里的素材类型芯片仍然是黄的**——那才是打标。
- **hover 用同一族色的更淡一层**（`color-mix(… 36%)`），不是另一个颜色：路过是预览，点下去才是确认。
- **不给普通按钮加黄色 hover。** hover 只是「鼠标在这」，不是「我选了它」；到处都黄，黄色就不再意味着「我圈中的」，选区和高亮跟着一起贬值。

### 暖色是给内容的，不是给界面骨架的

试过给元信息行的图标上 `--emph`，做出来看图撤了。三条理由，别再试第二次：

1. 13px 的线性图标撑不住饱和色——1.7px 的笔画上铺赭黄只读成「有点脏的褐色」；
2. 每一项都上色等于没有一项被强调，散在灰行里的色点是噪音不是节奏；
3. 最本质的一条：**加粗、小标题底衬、热榜的热度值是内容，元信息行是骨架。** 骨架也染上同一个暖色，内容里的暖色就不再意味着「这里被强调了」。

### `::selection` 走过的两个极端

先是跟着 `--accent-soft`（浅灰 `#c4c4c8`），白底上几乎无感——划完词弹出菜单，人却不知道选中了哪几句；改成纯反白之后又太重，一整段变成一块黑砖，反而看不清选中的是什么内容。

现在是低饱和暖色蒙版、**字保持原色**——和高亮标记同一套语言，所以选中之后直接点高亮，视觉上是连续的。

## 二、字体

### 等宽字体没有中文字形，这是「字体看着都不一样」的总根源

JetBrains Mono 里没有汉字。给中文套上等宽，浏览器会让它掉进**系统默认字体**（Windows 上是微软雅黑），于是同一行里数字是 JetBrains、汉字是雅黑，字重字宽全对不上。

修法走过两个阶段：

1. **逐处去掉等宽**——治标。漏一处，或者以后新加一处，它就又冒出来了。这个问题反复出现过五六次（标签、元信息字段名、计数卡标签、表头、面板小字、书详情），每次都是同一个根因。
2. ⚠️ **在 `--font-mono` 的栈里夹一层 `Noto Sans SC`**——总根源修复。兜底回落的不再是系统字体，而是**正文同款**。冒烟测试直接断言这个变量里有它。**别把它删掉。**

**但这不代表可以随便给中文套等宽。** 那一层只是兜底，**内容是中文的地方仍然该用正文字体**。等宽留给时间戳、路径、UUID 这类真·机读信息，以及英文小眉标（`ON THIS PAGE` / `CHAPTERS`）。

找漏网的办法：在页面上扫「有中文文字节点 + computed font-family 含 mono」的元素。

### 具体落点

- **标签、元信息字段名、计数卡标签、表头、面板小字**（`.micro`）一律正文字体。`text-transform: uppercase` 对中文还是个空操作，跟着一起去掉。
- **面板里的小字统一走 `.micro`**（`.panel-head__count` / `.panel-head__time` / `.board__head em` / `.day-group__head em` / `.board__hot` 都是它的别名）。这里原来是五种写法（11 / 10 / 10 / 9.5 / 9px）而且全套着等宽，可这几处**没有一个是真·机读信息**——时间是「刚刚」、热度是「130.4万」、计数带「条」，全是中文。**值比字段名深一档**（`.micro__v` 用 `--text-2`），否则「10」和「条」一样重，扫的时候得逐字读才知道数字是哪个。热度用 `--emph`（`.micro__v--hot`）：它是这一页唯一需要互相比大小的数字。
- **左右两个小标签分属两种文字，所以字体不同、字号相同**：左栏 `ON THIS PAGE` / `CHAPTERS` 是**英文**，等宽眉标在那儿才成立；右栏 `批注 3` / `高亮 2` 是**中文**，走正文字体。两边字号取齐（10~11px），一屏左右两个小标题才像同一层东西。
- **中文标题的字号上限要比英文低。** person_dashboard 的 `clamp(36px, 5vw, 58px)` 是给英文短标题的；中文标题动辄二十几个字，那个字号下要占满整屏五行，正文被推到折叠线以下。`.reader-title` 上限压到 33px 是实测出来的（两行封顶）。
- **字体自带（@fontsource），不走 Google Fonts CDN**——那条链路在国内网络下经常几秒才回来，首屏会先闪一遍系统字体再跳字。只引实际用到的字重。

### 文字得看得见

- **`--text-3` 的值是量出来的，不是挑出来的。** 原来 `#a1a1aa` 在纸白上只有 **2.46:1**——低于 WCAG AA 的 4.5，连给大字和图形用的 3:1 都不到。而它管着元信息、字段名、提示、时间戳、空态文案，也就是「除了正文之外你要读的所有字」。现在是 `#6b6b75`（5.05 / 5.27 / 4.79），灰的层次一点没丢。
- **暗色要单独量**：同一个灰在深底上的对比度和在浅底上完全是两回事。暗色的 `--ink-400` 从 `#78787f`（4.04~4.57）提到 `#8e8e99`（5.29~5.99）。
- **「操作说明」类文字的下限是 13px**（`.field-hint` / `.todo-card__hint` / `.rail-empty` / 空态那几行）：这类字是要真读进去的，12px 的中文在 1440 屏上已经开始费劲。**元信息、时间戳、路径留在 12 以下没问题**——它们是核对用的，看一眼对上就过。
- 冒烟测试量的是**屏幕上真实元素**的 computed color 和 font-size，不是 CSS 变量：变量可能被组件层覆盖。

## 三、正文排版

### 小标题是一块贴着字的底衬

不是横线也不是 `//` 前缀。落点得在**扫的时候**看得见，1px 的横线在余光里几乎不存在。

- **用 `width: fit-content` 而不是 `display: inline-block`。** 后者会把标题塞进匿名行盒、继承 `--read-leading`（默认 1.95）的行高，凭空撑出一段空隙，行距调大时尤其明显。
- **负 margin 让底衬向左出血，字仍和正文左对齐**（`max-width` 要把这 24px 加回来，长标题才用得满整栏）。去掉负 margin 是这条最容易**安静**坏掉的地方：底衬还在、颜色还对，只是每个标题比正文缩进 12px。所以冒烟测试量的是**字的左边缘**，不是盒子左边缘。
- **右栏 `.prose-sm` 不吃底衬**（规则写成 `.prose:not(.prose-sm)`）：那边的 h2 被压成 9.5px 的等宽眉标，给 h3 加底衬会让层级倒过来。

### 加粗 = 换字色 + 一条下划线，不是垫底衬

底衬那版做出来截图看过、否掉了。理由留着免得有人再试一次：

- **密度实测差一个量级**——书里 810~2900 字一处（点睛），洞察报告 **115 字一处**。同一条规则，后者一屏七八条带子，段落像被荧光笔胡乱涂过。
- **整段加粗的行会跟着中招**：报告里 `**信号 Signal / Observation**` 这种自成一段的加粗很常见，垫上底衬之后它和真小标题长得像却又不一样，层级反而更乱。
- **和划词高亮同形**：都是压在字底下的一条带子，读者得先分辨「这是我划的还是作者加粗的」。

换成字色之后三条全解：密度再高也只是字变色不是加块面；整段加粗只是整段变色，和小标题的**块**一眼分得开；色相也和标记黄岔开了。

落地上的两个点：

- **下划线用 `text-decoration` 不用 `border-bottom`**：加粗跨行时边框只画在首尾片段上，中间几行会漏。偏移 3px 是让线离开中文下沿，贴着字时「三」「四」这类字的末笔会和线糊在一起。
- **加粗这条不排除 `.prose-sm`**（底衬那条排除了）。排除的理由只对标题成立；右栏放的是 AI 解释和对话回复，同一个加粗在正文里是橙的、在右栏是黑的就成了两套语言。
- **表格里的加粗只换字色，不画线。** 表格本来就是一格一格的线画出来的，格子里再来一条下划线就是三条线夹一行字；而「这一列是主键」光靠字色已经说清楚了。

### 链接 = 黑字 + 灰线 + 一个 ↗

三样东西各有各的记号：加粗是橙字橙线、链接是黑字灰线加箭头、小标题是橙底衬。

- 加粗变成彩色之后，链接原来那条 `--accent-soft`（`#c4c4c8`）的浅灰线**就撑不住了**：同一段里加粗是彩色的、链接几乎看不见，**链接看着比加粗还不像能点**。所以线加重到 `--text-3`，并补一个箭头。
- **不用斜体。** 中文没有真正的斜体，浏览器是把字形做仿射变换合成出来的，笔画变形发虚（思源黑体上尤其明显）；而且斜体在中文排版里传统上表示书名和引文，等于借一个已经有主人的记号。
- **也不给链接第三个颜色。** ↗ 说的是真事——正文里的链接**全是外链**，点了会开新窗口离开工作台；而 `.doc-meta` 的「原文 ↗」已经是这个语汇，读者不用学第二套。
- 箭头用**和那个按钮同一个** tabler `arrow-up-right` 路径，走 `mask` 而不是 `background`——mask 才吃 `currentColor`，暗色下跟着翻。正文是 `dangerouslySetInnerHTML` 出来的，塞不进 React 图标组件，所以只能走 CSS。图片链接要排掉（`a:has(img)`），一张图后面挂个小箭头看着像图没加载全。

### 和文字混排的图按行高显示

epub 里生僻字和公式常被切成小图嵌进句子（《平凡的世界》的「圪塄」实测 175×200、5KB，而同一本书真正的插图是 1766×2539）。按原尺寸铺出来，一个字变成 200px 高的一块，**把句子劈成上下两半**——图是显示出来了，但那一段没法读。

判据是「这一段里除了图还有没有字」，**CSS 表达不了**：`:only-child` 只数元素子节点，一段「文字 + img + 文字」里那个 img 照样是 `:only-child`。所以在 HTML 串上做（`markGlyphImages`）。

## 四、组件语汇

### 按钮与标签

- **标签有两种重量，因为它们回答的不是同一个问题**：`.tag--state`（状态：浅底实心 + 小圆点 + 深字，卡片上最该一眼看到的）和 `.tag`（属性：平台/类型/标签，细边框灰字，退到背景里）。共用一个样式的后果很具体——一张卡上四个一模一样的灰方块，扫的时候得逐个读字才知道哪个是「这条卡在哪一步」。
- **只有图标的按钮压成正方形**（`.btn-icon`）：`.btn-sm` 左右各 11px 内边距，不压的话一个 13px 的图标坐在 35px 宽的横条里，跟旁边的文字按钮排在一起像是那一个没写完。
- **图标统一从 `src/components/icons.jsx` 出去**，别的文件不直接 `import "@tabler/icons-react"`。那是个 5000+ 图标的 barrel，Vite 预打包一次就够了。线宽 `stroke={1.7}` 是这套设计的基调（2 太重压过正文，1.5 在 13px 导航里发虚）。

### 元信息行

- **一项是「标签 + 值」两拍，不是「图标 / 字段名 / 值」三拍**（`.doc-meta__label` 把图标和字段名裹成一个单元，内部 4px、和值之间 9px）。三个间隔一样宽的话，一项看着像三项——那正是这一行显得挤的来源。
- **不是一排灰药丸**（`.doc-meta__item`）**。** 药丸那版有三个毛病：字段名和值挤在一个方框里分不出主次；每个都套灰底，五六项排开就是一条杂色带；而「目标读者」这种整句话的值在定宽药丸里只能被切成「25-35岁知识工作者、内容消费重度用…」——最该看的信息恰好被切没了。现在项与项之间只靠间距分开（加分隔线就又回到「一条杂带」）。
- **用 `align-items: center`，不能用 `baseline`。** 这一行里混着三种高度：状态那个 26px 的药丸、纯文字的字段、22px 的「原文」链接按钮。按基线对齐时，有边框的和没边框的会错开一两像素——那就是「看着没对齐」的来源。冒烟测试量的是各自的**垂直中心**（差 ≤1px）。
- **字段顺序就是屏幕上的顺序**（`Object.entries` 按插入序），所以在适配器的 `meta` 里**短的排前面**：优先级、平台都是一两个词，目标读者是整句话——把长的夹在中间，后面那项会被挤到第二行，一行看着像两行。
- **字段名不能省。** 图标是**关键词匹配**的（`FIELD_ICONS`），认不出来的一律回落到通用标签图标——那时候只剩图标的话，那一项就成了一串没有名字的值。而且值自明的字段（平台名）和不自明的（`优先级 高`）混在同一行，规则只能取其一。**宁可给个通用的，也不要一行里有的有图标有的没有。**
- **模糊匹配是有意的**：Notion 那边随时可能把「适配平台」改成「发布平台」，精确匹配的话图标会悄悄消失。（这和榜单图标那条**相反**——那边按 id 精确匹配，因为 id 是我们自己定的、稳定的。）
- **「成稿去向」和元信息共用同一套标签形态**（`.draft-links__label`）。它俩上下紧挨着，各画各的就是同一个界面里两种元信息语言。
- **书详情和阅读区共用同一套。** 它们回答的是同一个问题（「这份东西是什么」），各画各的话，同一个界面里就有两套元信息语言。所以 `fieldIcon` 放在 `ui.jsx` 而不是某个页面里——两个调用方，谁也不该 import 另一个页面的私有常量。

### 自绘下拉（`ui.jsx` 的 `Select`）

**不用原生 `<select>`。** 原生 select 是这套界面里唯一一个跟着操作系统走的控件：Windows 上是直角白底、蓝色高亮的系统菜单，字体也不跟 CSS 走。旁边全是圆角药丸 + 黑白两色，只有它一处露出「这是个网页表单」——而它偏偏是阅读区里最常点的控件（改状态）。

自绘的只做一件事：选一个值。**不引下拉库**——它们的体积和 API 面是为搜索、多选、异步准备的，这里一样都不需要。

- 形态是**一行一个图标 + 名字**的浮层菜单：大圆角、软阴影、38px 行高、hover 是一整块圆角矩形——比一条条的高亮条更像「可以点的东西」。
- **状态图标靠形状区分，不靠颜色**（`STATE_ICONS`）：虚线圈=等我动手 · 半圈=正在跑 · 勾圈=做完了等下一步 · 实心点=已经出去了 · 叉=不要了 · 叹号=出事了要人管 · 归档盒=收起来。加一档状态色等于新开一个颜色维度，而颜色在这里已经有主人了；形状还不依赖辨色。
- 按钮上用的是**同一个**状态图标——按钮和菜单里那一行必须长得一样，不然人得在两套记号之间做一次翻译。
- **没有计数芯片。** 参考里那个数字是「这一档有几条」，而这个下拉改的是**当前这一篇**的状态，在这儿放个数字既没有来源也答非所问。**宁可不放，也不放一个看着像真的假数。**
- **`renderIcon` 必传，而且要逐项不同。** 默认那枚是状态图标，给平台配它纯属答非所问；而整列用同一枚字段图标的话七行长得一模一样，图标就不提供任何信息、只在每行左边占 15px（做过一版，就是这样）。「全部平台」那一行例外，用**字段**图标——它代表整个维度而不是某个值。冒烟测试量的是 svg 里 `path` 的 `d` 有几种（数 class 没用，class 都一样）。

### 卡片

- **卡片内部要行行对齐。** 一排卡片里标题有一行的也有三行的、有的有副标题有的没有，摘要和标签就会落在不同高度——扫一排卡片时眼睛得上下找，卡片墙那点「一眼扫十几条」的效率就是这么丢的。做法是给每个槽位固定高度：标题**恒占两行**（`clamp: 2` + `min-height`，完整标题留在 `title` 属性里）、副标题那行**没有内容也要渲染**、标签用 `margin-top: auto` 压到底。冒烟测试量的是三张卡上同一行的**像素差**（≤1px），不是「有没有渲染」。
- **同一张卡上，同一件事只说一遍。** 稿件卡原来副标题和底部标签都写平台。留下的是标签（平台是属性，`.tag` 正是属性的位置），副标题置空——但**不是不渲染**，那一行有 `min-height` 撑着对齐。
- **卡片外壳不是按钮。** 书架卡片曾经是 `<div role="button" tabIndex={0}>` 里套着两个真按钮。鼠标上看不出问题，键盘和读屏上是坏的：button 里嵌 button 属于非法结构，读屏把整张卡念成一个按钮，而 Tab 到卡片按空格是「打开」还是「下架」全看浏览器心情。改法（`.book-card__body` / `DocCard` / `BookCard` 一致）：外壳退成普通容器（整卡点击留着，那是鼠标的便利，不需要 role 也成立），主动作是里面那个真按钮。
- **卡片必须有摘要。** 没有摘要的卡片和一行标题的列表没区别，卡片墙就白做了。这条对看板同样成立。

### 共用页头

`src/components/ui.jsx` 的 `PageHeader`（等宽小字 + 大标题 + 右侧动作）和 `SectionHead`（圆形图标 + 分区标题）。每页都长一样，用户不用重新找「刷新在哪」。

**面板头部的图标要比直觉的大一号。** 图标和标题**几何上**早就是居中对齐的（量过，差 0.3px），但看着仍然不齐：tabler 的墨迹只占 24 viewBox 的 66%，15px 的框里实际只有 10px 高，而汉字几乎占满 12.5px 的字面——再配上比标题更淡的颜色，图标就成了挂在字左边、又小又虚的一点。16px + 跟标题同色，两边的视觉重量才配得上。**这类问题量坐标是量不出来的，只能看图。**

## 五、布局与滚动

### 滚动条：能少一条是一条，剩下的让它安静

阅读区天生是三个滚动区域（左栏目录 / 正文 / 右栏批注台），这是布局决定的、去不掉。真正该消灭的是**滚了也没反应**的那条：

- **覆盖层开着时锁住 body 滚动。** 覆盖层是 `position: fixed; inset: 0`，底下的列表页并没有消失、照样能滚，于是窗口右边挂着一条纯噪音的滚动条。恢复时写回原来的 `overflow` 而不是清空——别的地方也可能锁过。
- **剩下的三条做细做淡**：8px、圆角、平时接近透明，鼠标进到那个区域才变深。系统默认的实心灰条竖三根在屏幕上，视觉重量比它们承载的信息还大。
- **不要为了少一条滚动条去套 `max-height`。** 那只会把一栏切成两半（鼠标在哪滚的是哪，手感直接碎掉）。引用块展开、看板列、左栏目录都踩过这条。
- **列不自己滚。** 页面已经有一条滚动条了，列内再来一条就是两层套在一起。列跟着内容长，和卡片墙同一套行为。

### 用 `:has()` 决定宽度，不给 App 加状态

看板要吃满屏（`.main:has(.kanban)` 解掉正文栏的 1320 上限），内嵌工具同理（`.embed`——排版工具自己的工具栏在窄容器里会把「公众号预览」挤成三行）。编辑区的整屏三段式也是（`.ws-main:has(.ws-edit)` 解掉外层滚动）。

**宽度是内容决定的，不是路由决定的。**

### 内嵌工具不套容器

它本身就是个完整应用，自带边框圆角分栏，外面再包一层带边框的卡片就是「框里画框」，两圈圆角永远对不齐，而且那层内边距还在吃宽度。做法是负 margin 抵掉 `.main` 的左右内边距铺到边，只留一条上边线跟页头分开。

## 六、键盘与可达性

### 弹层的规矩只有一份（`src/lib/use-dialog.js`）

工作台有六个弹层。它们原来各做各的：有的自己监听 Esc，有的自己 focus 一下输入框。**各做各的结果是每个都缺一两条**，而缺的那条是同一类问题——焦点还留在背后那一页上。

**这不是无障碍加分项，是一个用键盘就能误触的危险动作**：打开阅读覆盖层之后按 Tab，焦点会一路走进背后那一页的卡片，那儿每张卡右下角都有个垃圾桶。屏幕上什么都看不出来（背景被盖住了），而回车就是一次删除。

`useDialog(open, onClose, { autoFocus })` 一次给五条，缺一条这个 hook 就没意义：焦点进弹层（优先 `[data-autofocus]`）· Tab/Shift+Tab 只在内部循环 · 背景 `inert` · Esc 关闭 · 关闭后焦点回到**打开它的那个按钮**。

- **`inert` 要沿着「从弹层到 body」的整条路往上刨兄弟**，不能只看 `document.body.children`：这个项目的弹层没有一个是 body 的直接子节点。只看 body 那一层的话过滤完一个都不剩——**代码在跑，效果是零，而且看不出来**。
- 用 `inert` 而不是自己遍历改 `tabindex`：后者要记住每个元素原来的值，而弹层开着时背景那一页还在继续渲染（状态轮询、流式输出），改回来时十有八九对不上。
- **Esc 谁管要想清楚，别两处都管。** 阅读覆盖层的 Esc 留在页面那边，因为那儿有一条这里没有的规则：**正在输入框里打字时 Esc 不退出**（写批注写到一半按 Esc 把整个阅读区关掉，写的东西就没了）。传 `undefined` 表示「这一层不管 Esc」。
- **平台闸门跑起来之后 Esc 失效**：那一步已经在往 Notion 写了，半路撤不回来。
- **焦点归位前要判断那个元素还在不在**：弹层里的动作可能把它删掉了。硬 focus 一个游离节点，焦点会掉回 body，下一次 Tab 从整页开头重来。
- ⚠️ **测焦点陷阱必须真按 Tab。** 在 `evaluate` 里循环读 `activeElement` 只是在看焦点有没有自己动，那什么都测不出来。

### 自绘下拉的键盘规矩

关着时 ↓/↑ 展开并落在当前值上；开着时 ↓/↑/Home/End 移动、回车选中、Esc 收起、Tab 收起但**不吞掉那一下**（焦点该照常走到下一个控件）。

- **「键盘走到哪一项」和「当前值」是两回事**，上下键只是在看，回车才算选中——边走边写的话，用方向键路过「已弃用」就把这篇稿子废了。
- 键盘游标和鼠标 hover **共用一个高亮**：分两套的话，鼠标随便动一下就看不出回车会落在哪一项。
- 它的键盘事件**全在捕获阶段拦**：这个下拉常开在阅读覆盖层里，而那一层的 Esc 是「退一层」、j/k 是翻条目。不拦的话，收菜单的那一下会顺手把整个阅读区关掉。

### 两条快捷键的规则不一样，不能写在同一个判断里

- 带修饰键的 `Ctrl+K` **在输入框里也要生效**（写批注时想起「刚才那本书叫什么」是常事）。
- 裸键 `n` 在输入框里**绝不能**触发，否则打字打到 n 就弹抽屉。
- **快捷键不能是唯一入口**：Ctrl+K 学一次就记住，但没人会去猜一个看不见的功能存不存在。所以侧栏里有一个长得像输入框的按钮（`.rail-find`），按键提示压在右边。
- **快捷键提示不刻在按钮上。** 侧栏「入库」上那枚 `n` 角标只有第一天有用，之后一直跟着这个最显眼的按钮出现在每一屏。留在 `title` 里。

## 七、阅读体验

### 浏览层和精读层是两件事

- **卡片墙 / 看板** — 浏览层。卡片墙回答「有什么」（带摘要和标签，一眼扫十几条），看板回答「卡在哪一步」。搜索、筛选、翻页都在这一层。
- **阅读覆盖层** — 精读层。点开一张卡才进来，整屏：正文 + 批注台 + 动作。

**为什么不是常驻的「左列表 + 正文 + 右栏」三栏**：那种布局逼你每看一条点一次，列表列又只能显示标题；而正文和批注台各自都嫌窄。拆成两层之后，扫的时候信息密度高一个量级，读的时候能吃满整屏，关掉还能回到原来的滚动位置。**浏览和精读不该挤在同一屏。**

阅读覆盖层是**三栏**：左栏「我在哪」、中间正文、右栏「我要做什么」。顶栏底下那条进度线是长文的必需品——中文长稿滚起来没有页码，不知道还剩多少会让人不想往下读。

**两侧栏都能收起**（`ReaderOverlay` 顶栏两个按钮，状态存 localStorage）**。** 读长文时正文该能吃满屏——左栏是导航、右栏是工具，真正沉进去读的时候两样都不需要。

### 左栏

**只放标题、来路、字数、目录。** 曾经堆过「选题 / 待写 / 公众号 / X」四个芯片加一行机读时间戳——那几个标签顶栏面包屑和正文的元信息行里都已经有了，**第三遍出现只是噪音**。`<1180px` 整栏隐藏。

**目录只在有两个以上小标题时才出**：一条只有一项的目录不是目录。但没有目录的文档（成稿几乎都是流式的，一个 `h2` 都没有）会让左栏空出两百多像素——所以那块空白由**字数 / 预计读完**顶上。这不是为了填空：写稿的人一直在问「这篇够不够长」，公众号深度长文和 X 短帖差一个数量级，字数是当场就要的判断依据。

**顶栏面包屑答的是「我在哪」，必须短。** 不给 `crumb` 的话会一路退到 `sub`，洞察那边就成了「覆盖 2026-08-05 — 2026-08-12」一整条日期区间铺在顶栏上。内容是中文（库名 / 状态），所以也不套等宽和大写字距。

**链接不单独占一行。** URL 又长又没法读，铺在元信息行里会比标题还显眼，而人对它唯一的动作就是点一下跳过去——所以它长成一个「原文 ↗」的小按钮（`metaLink` + `.doc-meta__link`），跟在来源后面。

### 右栏：固定的上下文 → 滚动的内容 → 固定的动作条

上一版是「所有东西排成一列一起滚」，三个具体后果：「理解」里那段引用会跟着滚出屏幕，读到一半忘了 AI 在解释哪句话；「存为笔记」沉在内容底下，输出长一点就得先滚到底才能点；对话输入框跟着消息跑。**动作条固定之后，按钮永远在同一个位置，肌肉记忆才立得住。**

- **每个页签都不能是死按钮。** 「理解」以前在没划词时是 `disabled` 的灰按钮——点不动又不说为什么，用户的结论是「AI 功能坏了」。现在它永远能点，空态直接讲怎么用。
- **高亮和批注在同一个页签**（「标记」）。分成两个的话，你得先想「我当时是划的还是写的」才知道该点哪个。
- **「衍生」的四个模式各存各的，点回去是回读不是重跑。** 这里改过三版，前两版都错在把「问过了」和「正在看」混成一件事：v1 后一次覆盖前一次（想对比就得重跑，重跑再花一次 token）；v2 四段全叠着排（结果一长，右栏成了一条几千字的长卷）。现在四个模式**就是四个页签**（「在看哪一段」是纯视图状态，留在 `AiBody` 里，不往页面上传）——没问过的点了才跑，问过的点了只切视图、一个请求都不发；**重跑必须明确点「重新生成」**。花钱的动作不能藏在「再点一次」这种手滑就会触发的手势里。
- **「存为笔记」因此挪进了每一条自己的头上**：要存哪一段是分开的决定。
- **旁边并排一个复制按钮**（`CopyButton`）**。** 原来只有「存为笔记」，想把回复贴到别处只能手动划选——而回复动辄几百字带标题和列表，**划全一段本身就很难**。复制的是 Markdown 原文：去处基本都是 Obsidian、排版工具或另一个对话框，标题和列表要留着。
  - **就地回执（图标变成勾），不弹 toast。** 划词工具条那个「复制」必须弹 toast——它点完自己就消失了，没地方显示回执；而这个按钮点完还在原地。
  - **失败要变成一个带字的按钮。** 图标按钮上只改 `title` 等于没提示，现象是「点了没反应」——而人的下一步是去粘贴，粘出来的是上一次的东西，比直接报错难查得多。
- **右栏里也能划词**（`useRailSelection` + `RAIL_ACTIONS`，三个去处：存素材 / 存为笔记 / 复制）。AI 答出来的东西里最常有的就是能直接用的句子，只能整条存走的话，想要其中一段就得手动复制再去别处粘。解释/展开/反驳在 AI 自己的输出上再来一遍是套娃；高亮更没有落点（那段话不在书里）。
- **对话区：你说的话靠右、实心气泡；它答的话不做气泡**，只用一行署名 + 左侧细线。回复常常是几百字带标题和列表的 Markdown，套进圆角框里只会更难读。
- **流式回复没到字之前不要画空气泡。** 流式是先插一条 `text: ""` 的占位再往里灌字，照着渲染的话屏幕上会挂一个灰色空条，旁边另有一个「正在想」——两个东西说同一件事，其中一个还是空的。
- **输入区是一个盒子，不是三层。** 曾经是「带边框的 textarea + 一排按钮 + 一行快捷键」堆在底部，加上 textarea 自己的 resize 手柄，最该干净的地方线条最多。现在文本域无边框贴在容器里、跟着内容长（1 行起 6 行封顶），焦点落上去时**整个盒子**亮起来。引擎开关和「新对话」挪到页签下面那一行——它们是**关于这场对话本身**的，不是关于正在打的这句话。
- **对话要能重开一轮**（`onNewChat`：清消息 + 清 session id）：一直聊下去上下文越滚越长也越跑越偏；而只靠刷新页面的话，整个阅读区会跟着关掉。
- **等待态要说清在等什么、等了多久。** headless CLI 冷启动本来就十几秒，一条光秃秃的骨架屏挂在那儿，用户只会以为它死了。
- 「这段解释默认不保存」是**一行小字，不是整块警告框**——它讲的是默认行为，不是出了问题。

**引用块的 clamp 有两个坑，都会表现成「内容显示不全」：**

- 「展开」按钮**必须在 blockquote 外面**。clamp 按行裁，写在里面的按钮会被裁成半截——现象是底下挂着个残缺方块。
- clamp **必须挂在没有内边距的里层 span 上**。挂在有 `padding` 的块上时，line-clamp 按 content box 裁行、`overflow: hidden` 按 padding box 裁像素，两者不重合，底部那 8px 会把第四行的上半截露出来（连省略号都不出）。
- 展开之后**不给它自己的滚动条**：右栏本来就窄，套一个内滚区等于把一栏切成两半。

### 划词工具条

**工具条是图标不是文字。** 它浮在正文上：五个中文词一排要 300 多像素，盖住的正好是你刚读的那一行；图标一排只要一半宽。

**但八个图标 = 八个谜语，除非每个都带说明**——所以是自绘 tooltip（标题 + 一句人话）而不是原生 `title`：后者要悬停一秒才出、样式跟不了主题，等于每次都要等。

**分三组，中间竖线断开**（自绘 tooltip 是 `.sel-bar__tip`），因为动作的性质不一样：标记（高亮/批注）留在这本书里，问（解释/展开/反驳/翻译/拿去对话）不落盘，带走（存素材）离开这本书进流水线。混成一排的话，「存素材」这种会写到别处的动作和「解释」这种一次性的看起来一样重。

**右栏那条和正文那条是同一个组件类**（`.sel-bar` + `.sel-bar--fixed`）。划词这个动作在哪儿做都是一回事，长两个样子只会让人以为它们功能不同。差别只有定位方式。

### 阅读设置：取哪些、不取哪些

readest 那套设置里「分栏数、最大列高、页眉页脚、剩余页数、最小字号」全是**分页阅读器**才有的概念；我们是滚动阅读 + 右侧常驻批注台，抄过来只会多出一堆调了没反应的开关。

取的每一项（`components/ReadingPrefs.jsx`）都满足一个标准：**调完屏幕上立刻看得出差别**——字号 / 行宽 / 行距 / 段距 / 字重 / 字体 / 纸色 / 首行缩进 / 两端对齐。

- **数值是一格一格调的，不是三档。** 三档够快但不够准：同一个人在 27 寸屏和笔记本上想要的行宽差一百多像素，而三档之间的跨度是 140px，中间那个刚好不合适。`min/max` 卡在「还能读」的范围内——让人能把字号调到 8px 不叫自由，叫没做限制。
- **「黑体」必须是思源黑体（Noto Sans SC），不能是 `system-ui`。** 那是这个项目原来的默认正文字体。写成 `system-ui` 打头的话，Windows 上等于换成了微软雅黑：字重更细、字面更小、标点空隙更大，长文读起来就是不如原来的。
- **字体分中文和拉丁两组，因为它们管的不是同一件事。** 中文那组管中文书里 99% 的字，换一个整页观感就变；拉丁那组的 @fontsource 包**只有拉丁字形**，选它们只会改数字、英文和标点。**默认是黑体**——加拉丁字体不能把它挤掉。**Bookerly 没有**：亚马逊的专有字体，没有可分发版本；Georgia 是系统自带，不用引包。
- **系统字体要先量一下这台机器上有没有**（`hasFont`：和 monospace 各量一次同一串字，宽度一样就说明回落了）。苹方只有 macOS、微软雅黑只有 Windows，摆一个点了没反应的按钮比不摆更糟。没装的**留在原位但禁用**并在 title 里说清原因——直接藏掉的话用户会以为是自己看错了。`document.fonts.check()` 在这里没用：它查的是「字体加载完了没」，对压根不存在的系统字体一样返回 true。
- 字体按钮**用它自己的字**显示：选之前就看得出长什么样，比看名字准。
- 纸色只在浅色模式下给：暗色底色本来就不是白的，再叠一层米黄只会变成脏灰。

## 八、各页面的取舍

### 侧栏

品牌名是 **Xenho OS**（副标 `CREATOR WORKBENCH`）。「OS」在这儿是隐喻不是字面意思——它不等于「工作台」，指的是「我所有事都在这上面跑的那一层」；副标才说明这是干什么的，两行合起来意思才完整。

- **导航标签一律两个字。** 长短不一的一列（「总览」「近期热点」「内容工作台」）会让侧栏被最长的那个撑宽，多出来的宽度全程占着屏幕；齐平之后眼睛也不用在参差的右边缘上找落点。
- **宽度的下限是品牌行定的，不是导航项定的**：logo + 「Xenho OS」+ 收起按钮一行排开要 194px。试过 184，「Xenho」和「OS」当场分了家——所以是 200px，品牌名 `nowrap`。
- **收起态只改变量和「藏什么」，不写第二套侧栏。** 导航项、入库按钮、连接状态在两种形态下是同一批 DOM，收起只是把文字那一段 `display:none`。写两套的话，加一个导航项就要改两处，迟早漏一处。
  - 60px = 左右各 10px 内边距 + 一个 40px 的图标按钮。藏文字的同时要把 `gap` 和左右 `padding` 归零，否则图标会偏左几像素。
  - **角标退成一颗点**（`.nav-item__dot`）：60px 里放不下数字，而这一刻要回答的是「这儿有没有事」。
  - **收起态下 logo 自己就是展开按钮**，收放按钮那时是藏起来的：60px 宽的一条里摆两个方块显得挤，而 logo 已经在最顺手的位置上。展开态它退回纯标识（`pointer-events: none` + `aria-hidden`），免得「点 logo 是回首页还是收侧栏」变成一个要想一下的问题。
  - **logo 收起态要放大到和导航项的方块同宽**（40px）。26px 的 logo 挂在一列 40px 的图标块上面，比谁都小一圈，看着像还没加载完。
  - **收起态的搜索只剩一个图标，边框和底色一起去掉**（圆角也要跟 `.nav-item` 一样是 `--r-surface`）**。** 展开态那个方框是有用的——它让「搜索」看起来像个输入框；但收起后框里只剩一个放大镜，而放大镜本身就是全世界都认得的记号，框不再解释任何东西，只是在一列**没有框**的图标上面多出一个有框的。
  - **收起按钮常驻**，不做成 hover 才现身：收放侧栏是随手就用的动作，藏起来的话每次都得先拿鼠标扫一遍才找得到。
- **品牌标记（`BrandMark`）的底色和 X 吃语义 token，不写死黑白**（`.brandmark__bg` / `__x`）**。** 素材原始形态是黑底白字，直接搬进来的话，暗色模式下这块纯黑会糊进深色背景——而侧栏当前项的黑块在暗色下是翻成白的，logo 不跟着翻就成了整屏唯一一个不认主题的东西。

### 设置：左栏分类，右栏一次只画一段

**入口贴着连接状态。** 侧栏底部那行「流水线已连接」报的就是「Worker 配没配、通不通」——齿轮是去改它的地方，两者是同一件事的两面。**`.conn` 整行不做成按钮**：收起态下它只剩一颗 7px 的点，一个点是看不出可点的；齿轮才是那个可点的东西。收起态状态点绝对定位成齿轮右上角的角标，复用「60px 里放不下就退成一颗点」那条规则，DOM 仍然只有一套。**收起态齿轮不能藏**：工作台没配好时它是唯一那条能走的路，而收起是个会一直保持的状态。

**为什么不是侧栏一页。** 侧栏每一项都是一天动线上的一站（看外面 → 做内容 → 发出去 → 看反馈），设置不是那条线上的一站；而它是「随手改一下就回去干活」的动作，占一次页面切换等于把当前上下文丢掉。

**形态走过三版，第三版才对：**

1. **抽屉（660px，六段全铺）** —— 一屏望过去全是灰字说明，字段藏在里面。每个字段底下挂两三行踩坑说明，那些说明本身没错，错在**默认全铺开**。
2. **整屏覆盖层** —— 左栏 208 + 内容上限 760，在 1440 屏上右边留出大半屏空白，底部动作条的两个按钮隔着一千多像素分居两头。需要整屏的是阅读区（正文要吃满宽度），这一屏不需要。
3. **一张居中的面板**（`min(1120px, 100%) × min(840px, 100%)`，顶栏 / 左栏+右栏 / 动作条三段）——比例对了，还顺带留住了「背后是哪一页」这条上下文。

**左栏的价值不是「省地方」，是「哪一段出了事一眼看得见」。** 每项挂一枚记号 = 那一段自检里最坏的一条。没有自检的段**不画**——一个恒为绿的假勾比不画更糟。

- **说明文字分两位**：`hint` 一行（配了能多做什么 / 空着会怎样），`why` 是长的那些，收进「为什么」折叠、**默认收起**。信息一条不删，但默认一屏只剩字段。这就是第 1 版那个毛病的正解——问题从来不是「话太多」，是「话不该默认铺开」。
- ⚠️ **切段不能丢改动**，底部计数是**跨段总数**。丢了的话「改 A → 去 B 改一下 → A 白改了」，不报错也看不出来。
- **左栏当前项是实心黑块**，和侧栏导航、页内 tab 同一个记号（黑块 = 「你在这儿」）。
- **自检结果紧贴着它检的那个配置项**，不另开一个「诊断」段。单开一段的话，「流水线连不上」和「Worker 地址」隔着半屏，看到结论还得自己找回去改哪儿。
- **自检状态靠形状分，不靠颜色**（虚线圈=没配 · 勾圈=通了 · 叹号=有话说 · 叉=配了却不通），和自绘下拉的 `STATE_ICONS` 同一条规矩。只有 `bad` 额外吃 `--danger`——那和 `Note` 的 danger 是同一件事：真出问题了才配得上一个颜色。
- **可选能力没配画成 `off`，不是 `bad`。** 把「你没开这个功能」画成红的，等于每次打开面板都在骂人。
- **每条自检都要带「下一步」**，不是状态点加一个词。那一行存在的全部理由就是 `hint`。
- **密钥框不做「显示明文」的眼睛。** 这台机器上会录屏、会共享桌面，而**核对 key 对不对靠的是底下那条自检，不是肉眼比字符串**——一个手滑就把密钥摊在屏幕上的开关，换来的是一件本来就不该用眼睛做的事。
- **「清除密钥」是个独立按钮，不是「把框留空」。** 框本来就永远是空的（服务端不回值），靠留空表示清空的话，改一下别的字段就会顺手把 key 洗掉，而且不报错。
- **有默认值的字段不给 placeholder**（`SNAPSHOT_KEEP_DAYS`）：底下那行「留空时用：30」已经说了，框里再放一个灰色的 30 就是同一件事说两遍。
- **保存点两下**，第二下的按钮上直接写东西去哪（「写入 creator-workbench/.env」），配一个「取消」——和删除那两条同一套。没有改动时主按钮上写的是「没有改动」而不是灰着不说话。
- ⚠️ **同一屏上不能有两个长得一样的「没有改动」。** 流水线提示词那一段自己头上有一个（管当前那个 .md），底下动作条上又有一个（管 .env）——两个灰按钮长得一模一样、管的却是两回事。修法是那一段没改动时**底下整个不画**。看图才发现的。
- **不放「模型供应商」那一组框。** 三条 AI 链路各不相同（理解走 Worker 的 `/wb/explain`、对话走本机 CLI、翻译走 DeepL），一个「base_url + key」对哪条都不生效。**摆一个填了没用的框比不摆更糟**（总原则三）。
- **不做 `.env` 全文编辑器**：那是把记事本嵌进网页，还绕过了所有校验和自检。

**提示词分成两项，因为它们生效的方式不同。**「工作台」改完立刻生效，「流水线」写的是 content-pipeline 的文件、要部署一次才算数。混成一段的必然结果是：用户改完 Worker 的提示词、看到「已保存」、以为生效了。**所以连保存按钮都长得不一样**——工作台那段跟着底部动作条走，流水线那段就地一个自己的按钮，按钮上写「保存到 content-pipeline」。

- **「还没部署」的横幅改过就一直挂着**，点「我已经部署了」才消。拿不到 Worker 真实的部署时间，**宁可多问一次，也不能默认「大概生效了」**——忘了部署的表现是「改了没反应」。横幅里给命令 + 复制按钮，别让人去别处找。
- **改不掉的那段安全约束只读展示，不藏起来。** 藏了的话用户以为自己改的那段就是全部，而实际发出去的比他看到的多一段——那是另一种「让用户猜」。虚线边框在说「这块和上面那个输入框不是一类东西」。
- **提示词编辑器复用 `MarkdownEditor`**，不重造。提示词本来就是 Markdown。
- ⚠️ **这一段只留一条滚动条（编辑器自己那条）。** 第一版给编辑器写死 `min(56vh, 560px)`，比右栏可见高度还高一点——于是右栏滚一层、编辑器内部再滚一层，鼠标在哪滚的是哪，正是「不要为了少一条滚动条去套 max-height」踩过的同一个坑。改成 `:has()` + flex 撑满，冒烟测试量的是右栏的 `scrollHeight - clientHeight`。
- **左栏两项都叫「流水线」是对的**（一个在「连接」下、一个在「提示词」下），组名已经把意思分开了。但**测试选择器要按 `data-key` 点**——和收起态「创作」那条是同一种坑。

**空态引导必须能点。** 「在 `.env` 里填 `VAULT_ROOT`」这句话原来是个死胡同——读完之后下一步是去开编辑器，而那一步机器完全可以替他走。总览的三处和数据页的一处都接上了「去设置」。**拿不到 `onSettings` 时不画那个按钮**，而不是画一个点了没反应的。

### 总览：先分「谁来动手」，再答「上次干到哪」

**计数分两组，因为 0 的含义正好相反。** 「待初筛 / 待整理 / 撰写中」是 Worker 自己会消化的队列，**0 是它们的正常态**；「选题待写 / 待修改」不点它就永远不会动。上一版把五个平铺成一排同样大的卡片，后果很具体：首屏最贵的一整行里有 60% 的面积在展示「没有事」，而真正等你动手的两个数字混在三个 0 中间。

- **三张卡的外壳一样，层次靠内容拉开。** 中间试过给流水线那格去掉边框和底色来压层次，实际效果是同一排里两张有壳一张没壳，**看着像那一格没加载出来**。
- **右上角那个「N 件事等你」只数待办组。** 把 Worker 正在跑的活也算进「待处理」，会让人以为自己欠着事——「撰写中 3」并不需要你做任何动作。
- **上排和「接着上次」共用同一套三列**，两行才严丝合缝。只放两张卡的话，宽屏上每张会被拉到 750px，一个 46px 的数字浮在那么大一片空白里，看着像还没加载完。
- **「可以点」要在静态下就看得出来**：卡片底部常驻一行「去看看 →」。只靠 hover 抬升的话，第一眼和截图里它就是块展示牌。
- **「接着上次」三块的出口固定在底部**，落在同一条水平线上（冒烟测试量的是 `.resume-panel__go` 的 `top`，差 ≤1px）。各摆各的话，一行三个按钮会因为内容长短各在各的高度上。
- **「最近改过的」要按标题合并。** 一个选题会成好几篇稿（一个平台一篇），标题是 LLM 起的同一个 headline——不合的话列表里就是连着两行一模一样的标题，扫过去只会以为是重复渲染的 bug。
- **「接着读」列两本（`recentReadings` / `resumeEntry` / `bookProgress`，都在 `src/lib/reading.js`），但只有真读过的才算数**，不拿书架上没动过的书填空——那样就把「你正在读这些」变成了「书架上有这些」，而后者书架页自己就是。两本的槽位要**固定行数**（书名恒占两行），否则进度条会错开，而这一格的用处就是「扫一眼还剩多少」。百分比不和章节名挤一行，挪到进度条右边：挤在一起时长章节名会把最该看的那个数字先截掉。
- **vault 路径和归档不占首屏**：路径正常时没人需要看它，归档是几周想起来一次的动作。降级成一条系统行；**出错时照旧是显眼的 Note**——那才是它重要的时候。
- 眉标是 `PIPELINE` 不是 `PIPELINE · TODAY`——这一页没有任何东西是今天维度的，写了就是句假话。

### 筛选条

**只占一行：状态是芯片，分面是下拉。** 两排芯片摞在一起时第一眼分不出「上面是状态、下面是平台」（长得一模一样），而且第二排会随选项数量变长，把卡片墙一路往下顶。收成下拉之后「现在按哪个平台在看」直接写在按钮上，比在一排芯片里找哪个是选中的更快。

- **有权威名单的分面要列全，没有的才从数据现算。** 稿件库属前者：只列已加载条目里出现过的平台，你就分不清「小红书 0 篇」和「小红书不存在」，而作为筛选器前者才是这一刻想知道的事。素材库属后者：「类型」的选项在 Notion 那边随时会加，写死会让新类型凭空消失。
- 选项标签带计数（`公众号 2`），所以**标签和值要在同一个数组里一起算出来**——各拼一次的话，平台名里只要有个空格，回读就对不上。

### 看板

**默认一律卡片墙，看板是个开关。** 看板回答「卡在哪一步」，那是偶尔问一次的问题；日常进这几个库是来找内容的，默认给看板等于每次打开都先看一屏光标题。

- 列宽 `flex: 1 0 272px; max-width: 400px`：等分的话中文标题一行放不下三个词，写死的话列数一多就被切。宽度真不够时横向滚，右边压一道渐隐，让「还有一列在外面」看着像能滚而不是被墙切掉。
- **异常落点空着就藏起来**（`quietStates`）。「搁置」是所有平台都失败时的落点，正常永远是空的，白占一列；但**不能从 `states` 里删掉**——删了的话成稿失败的选题会从看板和筛选条上一起消失。
- **拖拽只是快捷方式**，每条仍然能在阅读区用下拉框改状态。触控板拖长列表很难受。
- 其余状态改完给一条带**撤销**的 toast：改错一格的成本应该是点一下，不是回 Notion 翻。

### 书架是三层，不是两层

**书架不走通用的阅读页，它有自己的 `pages/Shelf.jsx`。** 因为一条素材就是一份文档、点开就该看正文，而一本书是几十份文档，中间必须有个地方让你挑章节——少了那一层，打开一本书只能从第一章读起，读到第 30 章想回头查第 5 章就没路了。

三层动线：**书架封面墙 → 书详情（封面 + 元信息 + 章节目录）→ 阅读区**。

- **单篇书直接进正文，跳过书详情**：那一层只有一个按钮时，它就是白点的一次鼠标。
- **元信息和动作贴着封面底边**（`.book-hero__foot` 的 `margin-top: auto`，配 `.book-hero` 的 `align-items: stretch`），不跟着书名长短上下浮动。中文书名有一行的也有三行的，跟在标题后面排的话，「继续读」这个每次都要点的按钮在每本书里都落在不同高度——而这一层的用处只有一个：接着读。封面必须 `align-self: flex-start`，被 stretch 拉高的话 `aspect-ratio` 会被盖掉、图直接变形。
- **书详情的封面是张图，不是换封面的按钮。** 整块封面点下去弹的是文件选择器，而这一页最常做的事是读书——一次误触换来的是一个文件对话框。换封面只留书架卡片角上那个小按钮，那本来也是主要入口。
- **封面本身指向「打开这本书」，换封面是压在角上的小按钮。** 有封面时按钮只在 hover / 聚焦时出现，没封面时常驻（那正是最需要被看见的时候）。
- **书详情不再重复一遍 vault 路径。** 路径就是上面那个大标题（书名 = 目录名），等于把标题又说一遍，而中文书名动辄二十几个字、那一行自己就要占两行。**批注去哪并没有因此丢**：它由阅读区在真要写批注的时候说——说明该出现在动作旁边，不是提前打招呼。
- **作者只显示，不给改**（曾经做过，撤掉了）。做过的那一版是卡片上点一下就地改（`BookAuthor` + `POST /api/vault/books/meta`），当时的理由是「缺作者的多半是单篇书，而单篇书从书架直接进正文、根本不经过书详情，入口只放在书详情等于大半的书没入口」。撤掉的理由更硬：**这一格挨着「打开这本书」，而它改的是 vault 里的真文件**——`book.md` 的 frontmatter 在 Obsidian 里本来就能编辑，工作台再开一个入口，多出来的不是便利是误触面。**同一件事有两个入口时，留那个不会误触的**（对比：「类型」留着，因为它决定正文能不能改，是工作台自己的开关，Obsidian 那边没有对应概念）。
- **一个动作都没有时，整条动作栏不画。** 藏书是只读的，那一条会退化成一条光秃秃的分隔线加一片空白——看着像有什么东西没加载出来。
- **下架一本书 = 整个目录移进 `.trash/`**，不是删掉。里面有你自己写的批注；而且 Obsidian 自己的「删除到废纸篓」也是移进 `.trash/`，所以这跟你在 Obsidian 里删它是同一个动作、同一个地方能找回来。确认文案要**写清去哪**，不写「确定删除吗」。

### 删除

**删除 = 归档进 Notion 废纸篓**，30 天内能捞回来。Notion 的 API 根本没有硬删除，而这恰好是我们想要的。界面上就照实说「移到 Notion 废纸篓」，**不要写「永久删除」**——既不准确又让人不敢按。

两个入口：卡片右下角的垃圾桶（平时是灰的）和阅读区动作条最右（离「编辑」最远）。都要点两下，**第二下的按钮上直接写清楚东西去哪了**，不写「确定吗」这种没有信息量的话。确认态必须配一个「取消」——少了它，点错第一下就只剩「删」和「离开这一页」两条路。

### 编辑器：所见即源码，但源码长得像文档

**为什么不做真 WYSIWYG。** 它每次保存都要把整份文档按自己的方言重写一遍：`*斜体*` 变 `_斜体_`、列表重排、空行归一化都是小事，**真正会坏的是 `[[双链]]`、脚注、`> [!note]` 这类 Obsidian 专有语法**——它们不在通用 Markdown 规范里，通用编辑器会转义或直接丢掉。而这些 md 的另一个编辑器就是 Obsidian，vault 里现在有 40 个文件在用双链。

只装用到的六个包，没装 `codemirror` 全家桶——搜索、自动补全、lint 一样都不需要。用它**不等于**破了「无 UI 库」：它是纯文本编辑器内核，不带组件、不带皮肤、不接管布局。

- **着色只用语义 token**，不写死颜色，否则暗色下这块是整屏唯一不认主题的东西。加粗用 `--emph`——和阅读区看到的是同一个颜色，不然人得在两套记号之间做一次翻译。
- **记号本身（`#`、`**`、`>`，CodeMirror 里是 `t.processingInstruction`）压到 `--text-3`。** 记号和内容同色，一屏 Markdown 就是一堵字符墙——那正是原来那个 textarea 难看的根源。
- **工具栏按钮一律「插入 Markdown 记号」，不是富文本命令**：按钮做的事和你自己敲出来的完全一样，没有第二套模型要对账。加粗/引用/列表都是**再点一次就取消**。
- **不画活动行底色。** 这里的一「行」是整个逻辑段落（开了 `lineWrapping`），一整段涂上暖色底看着像「这段被高亮了」而不是「光标在这儿」——而暖色底在这套界面里已经有主人了。
- **编辑区是整屏三段式**：工具栏贴顶、编辑区自己滚、动作条固定在底。原来那版是「固定 54vh 的 textarea + 外面一层带边框的卡片 + 右下角 resize 手柄」，三个毛病：正文被压在小窗口里看不全、框里画框、而「保存」在内容下面，长文要先滚到底才点得到。
- **预览复用 `renderMarkdown` + `.prose`**，所以「预览」和真的读起来必然一致。

### 入库抽屉

**先问内容，再问分流和打标。** 点「入库」的意图只有一个：把手上这段东西存进去。分流（存到哪）和打标（素材类型）是存之前顺手做的事，而且多数时候默认就是对的，不该挡在正文前面。

底部一行「取消 + 主动作」：人填完表之后目光在底部，退出的路不该要求他先把视线拉回右上角那个 ×。

### 热点

**两个视角并排，各刷各的。** 平台热榜回答「现在大众在关心什么」，AI 情报回答「这一天 AI 圈发生了什么」。分成两个端点而不是一个大对象：两侧的刷新节奏差一个数量级（热搜按分钟变，AI 精选按天变），合在一起就只能迁就快的那个。

模型榜（解析 AI HOT 的 `/leaderboard` 页面，类名 `lb-row` / `lb-score`）和另外两栏**不是一类东西**：热榜和情报是「今天发生了什么」看完就过，模型榜是「现在的牌面是什么」几周才动一次。所以这一栏**没有收藏、没有入库**——它不是素材，是背景知识。

- **过滤是个看得见的两段式开关**（只看命中 / 全部），不是一句状态说明。原来只显示当前状态，看着像句说明，没人知道它能点、更看不出还有「全部」。
- **挂掉的源不铺版面，但要在底部如实点名**（`.panel-note`）**。** 长期挂着的那两个一直杵在状态条里很脏，但悄悄消失又会让人以为它们没接。
- **上游的失败原因不能直接铺到界面上。** 60s 返回的是「服务器出错了... Unexpected token '<'...」这种东西，铺出来会把整行状态芯片撑爆而且没人看得懂。`shortReason()` 把它翻成「上游返回了网页，多半被风控」，原文留在 `title` tooltip 里。
- **每个榜名前有一枚平台图标**（`BOARD_ICONS`）**。** 认不出的回落到 `IconNews`——宁可给个通用的，也不要一排榜里有的有图标有的没有。 榜是按平台分的，而平台是有形象的——一列纯文字标题里，图标比读四个汉字快。**按 id 精确匹配，不按 label 关键词**：id 来自我们自己的代码，是稳定的；label 是给人看的，随时会改字。
  - ⚠️ **知乎故意不用 `IconBrandZhihu`**：那个图标画的是「知」字本身。一排线性图标里只有它是个字形，笔画密度完全不是一路；而且它就贴在「知乎话题榜」左边，等于把第一个字说了两遍。
- **热点条目能在工作台里读完，不用先跳出去。** 这一页的动线是「扫一眼 → 觉得有用 → 入库」，中间那步「点开看看」原来要跳浏览器新标签，回来时滚到哪儿全丢了。
- **热点原文不复用阅读覆盖层**（另有 `components/ArticleOverlay.jsx`，靠 `SideRail` 的 `tabs` / `saveLabel` / `railActions` 三个可选 prop 裁出来）**。** 那是「精读 + 批注台」，整套搬过来等于逼人先决定「我要不要在这篇上留东西」，而多数时候答案是不要。按「这一栏在这儿有没有落点」逐个挑：
  - **左栏（目录）要**——抓回来的文章动辄上万字，没有目录只能一路滚。纯导航，零副作用。
  - **右栏「衍生」要**——热点里英文原文占一半，翻译和解释几乎是刚需，而它只是把选中的文字发给 API。
  - **「标记」不要**——这篇不在 vault 里：没有 notes.md 可写、没有 .highlights.md 可锚。**画一个点了没落点的页签，比不画更糟。**
  - **「对话」不要**——那条通道的价值是「能读你整个 vault」，而这篇不在里面。真要深聊，正确的顺序是先存素材、进了流水线再聊。
- **按钮上的字必须说实话**：这儿的「存」落进素材库，还写「存为笔记」就是骗人。
- **转化链的芯片只在「已经动过」时才画。** 一屏几十条里绝大多数是「未处理」，给每条都挂一个灰标签等于铺一层没有信息量的噪音，真正走出去的那几条反而淹在里面。用**文字**不用颜色——这套界面里颜色已经有主人了。

### 数据页

- **发布量画堆叠柱不画折线。** 发布量是整数、量级只有 0~4，折线会在 1 和 2 之间画一条斜线，等于宣称「周三发了 1.5 篇」——那个数不存在。堆叠柱一眼给两个答案：这周几篇、都发在哪。
- **指标名按平台换字**（小红书「观看」/ 公众号「阅读数」），**某个指标一条都没有值时整格不出现，不显示 0**。摆一个 0 会被读成「收藏了 0 次」，而真相是「这个平台压根没有这个指标」。同理覆盖不全时如实标 `(4/5)`。
- **首行第四格写缺口不写状态词**（「缺 3 · 小红书 3 篇」而不是「可分析」）：它既是状态也是下一步。
- **页签一直在，哪怕一条数据都没有。** 粉丝周录住在「数据来源」里，空态时把整条页签藏掉等于把它一起锁在门外。空态本身要自己会讲话：拖拽区 + 四个平台各一句「去哪导」，不是四个 0 和一张空图。
- **导入必须分两步**（预览 → 确认），而且界面上必须摊开「我把哪一列当成了什么」——**这是这个流程存在的全部理由**。解析器只能靠列名认字段，认错了不报错、不白屏，只会让一列数字安静地进错格子。
- **自动发现优先于手动拖拽。** 手动那条路里最烦的不是点确认，是「开文件对话框 → 翻到下载目录 → 在一堆文件里认出刚下的那个」——而这三步机器全知道答案。
  - **卡片上点之前就说清会发生什么**（「新增 3 / 更新 0」）。多数时候答案是「已经导过了」，那时按钮要改口。
  - **解析失败的不铺出来。** 下载目录里本来就有一堆无关的表格，把它们列成「无法识别」只会把真正要点的那一个埋掉。
  - **认不出平台的不猜**，给个下拉让人选。猜错了整批数据会挂到别的平台名下，而那是安静的错。

### 全局检索：空态就是「继续上次工作」

**不单独做一个大页面。** 那会是那种「装修完就再没人去过」的房间；而这个面板每天都要开，把「上次干到哪」放在它一打开就看见的地方才真的会被用到。空态三组：接着读 / 最近打开 / 最近搜过。

- **每条结果都带「怎么继续」（`go`），不是只给一个标题。** 搜到之后还要自己想「这条在哪个页面」的话，检索就只做了一半。
- **结果要打开「那一条」，不是「那一条所在的那一页」。** 找不到那一条时**退化成「停在这张过滤好的列表上」**，不弹一个空的阅读区。
- **搜到书里的某一章时带的是章节路径**：只跳到书详情的话，人还要在五十九章里再找一遍——那正是他刚用检索想省掉的一步。
- **在工作台里没有页面的东西（归档 / 网页批注）给 `obsidian://`**，并在那一行上写明「在 Obsidian 打开」。比画一行点了没反应的结果强，也比硬造一个只读页诚实。
- **词与词之间是「都要有」，不要求连着。** 中文里「杠杆 复利」分别出现在标题和正文里非常常见，要求连续等于搜不到。标题命中排前面，同分按时间新的在前——**不算相关度**，几十条结果上再来一层玄学排序只会让人找不到刚看过的那条。

## 九、从 readest 吸收了什么、没吸收什么

[readest](https://github.com/readest/readest)（Next.js + Tauri，foliate-js 渲染 EPUB、PDF.js 渲染 PDF）是个成熟的跨端阅读器。

**不采用它的阅读引擎。** foliate-js 是把 EPUB 当 EPUB 渲染——保留原书分页、原书 CSS、原书字体。那和这个工作台的定位是冲突的：这里的书**先转成 Markdown 落进 vault**，才能被 Obsidian 双链、被全文搜、被划词摘成素材卡。上了 foliate 就等于书正文不再是 vault 里的文件，整条「读 → 批注 → 摘素材」的链子断在第一环。**这是取舍，不是它不好。**

**吸收了三条**，都是「和渲染引擎无关、但每天都在用」的：

1. **阅读设置**（见上）。
2. **书内全文搜**：一本书拆成几十个文件之后，「那句关于杠杆的话在哪一章」是刚需。服务端读文件搜，不建索引（几十个文件几百 KB，读一遍是毫秒级；建索引就要管失效和重建）。结果直接列命中句并高亮，不是只给章节名——只给章名的话还得一章章点进去找。
3. **整本进度**：**按章数算，不按字数加权。** 加权更准但准得没用：各章长短差十倍时，读完三个短章显示 4%，而人的直觉是「我读了三章了」。这个数字是给人看的。

**明确不做的**：TTS、翻译整页、词典、OPDS/Calibre、跨设备同步、分页翻页模式、MOBI/AZW3。前五个是阅读器的活儿，不是创作工作台的；分页模式和右侧常驻的批注台打架。

**关于「用 foliate 就做不了批注了吗」——不，做得了。** foliate-js 支持选区和 CFI 锚点，readest 的高亮/笔记就是这么实现的。真正的代价只有一条：**书的正文不再是 vault 里的文件**。于是 Obsidian 搜不到书里的句子、章节不能被双链、批注里的 CFI 只有工作台认得。所以这是「原书排版保真」和「正文进 vault」二选一，不是能力问题。

要两头都要的话有第三条路：**Markdown 照旧，另外把原文件也留在书目录里，加一个「原版」模式用 foliate 渲染**，批注仍写 notes.md——代价是多一个前端依赖和第二套阅读界面。这一步没做，等需要时再决定。

## 十、否决过的方案（留着免得再试一次）

| 试过什么 | 为什么撤 |
| --- | --- |
| 加粗垫一条底衬 | 洞察报告 115 字一处，一屏七八条带子；和划词高亮同形分不清 |
| 元信息行的图标上暖色 | 13px 线性图标撑不住饱和色；**暖色是给内容的，不是给骨架的** |
| 流水线那格去掉边框压层次 | 同一排里两张有壳一张没壳，看着像那一格没加载出来 |
| `::selection` 用浅灰 / 用纯反白 | 前者划完看不出选中了什么，后者一整段变成黑砖 |
| 常驻「左列表 + 正文 + 右栏」三栏 | 列表只能显示标题，正文和批注台各自都嫌窄 |
| 「衍生」四段全叠着排 | 结果一长，右栏成了一条几千字的长卷 |
| 「衍生」后一次覆盖前一次 | 想对比就得重跑，再花一次 token |
| 侧栏宽 184px | 「Xenho」和「OS」当场分了家 |
| 整块封面当「换封面」按钮 | 这一页最常做的事是读书，一次误触换来一个文件对话框 |
| 快捷键角标刻在按钮上 | 只有第一天有用，之后一直跟着最显眼的按钮出现在每一屏 |
