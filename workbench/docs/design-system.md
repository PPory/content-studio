# Xenho OS 设计系统

这份文档记录现役界面的视觉与交互判断。它不是组件 API；实现前仍要检查已有组件，并按项目规则查 Emil UI、coss 或 ReUI 的真实用法。

## 设计目标

界面围绕记录问题、连接知识、阅读讨论和写成文章展开。任何视觉选择都先保证任务清晰、状态可预测和操作即时，再考虑精致度。

优先级：

1. 用户意图和任务完成；
2. 清晰与可预测；
3. 即时反馈与感知速度；
4. Accessibility 与输入方式；
5. 连续性和空间关系；
6. 性能与一致性；
7. 视觉精致与 delight。

## 视觉语言

- 主体使用中性黑白灰，内容和状态才获得强调色。
- 层次靠字重、间距、边界和实心面积，不靠大面积渐变、光晕、模糊或投影。
- 中文正文优先可读性；等宽字体只用于路径、代码和结构化标识。
- 同类表面使用同一圆角、边框和间距级别，不就地创造新数值。
- 一屏只保留一个最强主操作。选中态、状态和主按钮不能都用同样的实心黑块。

## 应用外壳

侧栏只放稳定的用户任务和设置；面板页头说明当前位置和本页动作。AI 协作栏属于主面板的第二列，不在页面上再套一层独立应用壳。

本地工作区正常时不常驻绿色连接灯。真实故障由当前模块就地说明；不要展示已经退出的远程服务状态。

## 不要框里画框

外壳已经提供了一层白色框架，工作区是它里面的浅灰。**不要在里面再给每块内容套一个白盒子。**

- 写字和读正文的页面（项目工作区、AI 助手页、阅读区）整页是白的，
  编辑区不画卡：一页正文不是一张卡片。分区靠留白和一道 1px 线。
- 白底容器里的条目不画「白底 + 边框」的卡——那圈边框会成为屏幕上唯一在说话的东西，
  两张并排就是两个空盒子。窄栏里靠间距和 hover 底色分开就够。
- 判据是「这层边界回答了什么问题」。答不上来就删掉它。

## 内容密度

- 卡片适合有封面、需要比较少量候选或承载一个明确对象。
- 纯文字的大列表优先行或表格，避免每条多一圈边框和摘要截断。
- 同一事实只出现一次。页头、区块标题、眉标和空态不要用不同句子重复解释。
- 系统后台状态退到次要位置；用户当下需要决定的对象排在前面。
- 空白不是默认价值。大片留白如果不能建立层次或焦点，就应收紧。

### 「同一事实只出现一次」在页面上长什么样

这条最常被违反的地方不是文案，是**版面**。三种具体形态，判据写死在这里：

- **不要在列表上面另开一组「需要你处理的」卡片。** 那组卡片取的是同一份数据的前几条，
  于是屏幕上第 2/3/4 行和顶上三张卡说的是同一件事，还各带一套视觉语汇。
  「先做哪一件」由**排序**回答——把优先级放进列表的默认排序，第一行就是它。
  创作页为此撤掉了整块 `.project-attention`。
- **一整列的值全都相同就不画那一列**（连表头一起）。判据是「填了的那些里有几种」——
  空值不算一种，因为一列「—」和一列同一个词一样是零信息。
  「有一条还没填」那件事有它自己该待的地方（行内的阻塞行），不值一整列。
- **能从旁边直接读出来的可视化不要画。** 进度条画的是阶段序号除以总数，
  而阶段就写在同一行的状态 pill 上——两者是同一个事实的两种画法，
  而且进度条**会骗人**：它说的是流程走到第几格，不是内容写了多少。

### 列表行中间那一列，放能做决定的东西

一行列表通常是「名字 | 中间 | 右端」。**中间那一列最宽，所以它必须装做决定要用的东西**，
而不是一段会被截断的说明。判据：把这一列遮住，还能不能做决定？能，就说明它没在工作。

Wiki 待审阅那五行是典型：中间原来是 AI 写的编译说明，每行开头都一样
（「已阅读全文（N 段） · 」），不同的那半句刚好被截掉。而你在那一行要决定的是
「让不让它改我的 Wiki」——靠的是**它要改哪几页**，那几个页面名一直在数据里，
却被折叠藏着。换成页面名之后，一行放得下，还顺带看得出哪几页被多份来源同时盯上。

### 分节、流程图、筛选器，先数真实数据里有几档

画之前先数一遍，这条对三种东西都成立：

- **分节**：Wiki 索引的分节机器支持十一档，真实数据只落到三档，其中一档只有一条成员。
  **一个只有一条成员的小节不是分节**，它只是多了一行标题和两段留白，还把一条能连续扫的列表切断。
- **流程图**：素材页曾用五张大卡画「待处理 → 已收纳 → 可用素材 → 已进入项目 + 证据闸门」，
  而真实数据里**五格有四格常年是 0**。用一张五段流程图去画一条两段的链，画的不是现状是愿景，
  代价是首屏 150 px。改成按顺序排的芯片之后顺序没丢，空格子没了；哪档真有东西哪档才出现。
- **筛选器**：只有一个取值的筛选器不是筛选器。素材库的核验状态全是「不适用」，
  那颗下拉筛不掉任何东西，却和旁边真正有用的「类型」长得一模一样。
  取值要按**这个库里真的出现过哪几种**算（`facets`），不是按适配器里那份静态清单。

这三件事都该退成同一套语汇：`.chips-sm`。同一个问题在这个工作台里只有一种长相。

### 选中态的底色必须和它身后的底色不同

`--sel-bg` 是 `--sunken`，而列表页的筛选芯片待的就是 `--sunken` 底（`.main` 的背景）——
**选中的底色和身后的底色量出来是同一个值**，于是「全部 30」在屏幕上就是一句普通灰字。
同一个 token 在侧栏是对的，因为侧栏是白底；换个底就失效。

芯片现在按「谁在说话」排：**选中**白底 + 实边 + 正文色，是一排里唯一像控件的那颗；
**未选**透明底、无边、`--text-3`，退进底色，指上去才浮起来。
挑任何选中态的值，都要放到它真正会待的那层底色上量一次。

### 卡片就该是卡片的尺寸，别为了填满而撑开

卡片网格的列宽用 `repeat(auto-fill, minmax(300px, 1fr))`：容器塞得下几列就开几列，
条数少就少几张，**右边空着是正常的**。

⚠️ **不要为了不留空位而让某一张跨格。** 内容机会试过「按总数除以列数的余数，
让第一张占 2 格或 3 格」——四条五条时确实铺得满，但真实数据只有一条候选，
那一张就横跨整个屏幕，一句判断被拉成 1093 px 宽的一条。
**填满不是目标，卡片尺寸一致才是。**

⚠️ 是 `auto-fill` 不是 `auto-fit`：`auto-fit` 会折叠空轨道，一条候选又被拉回满宽。
也不需要断点减列，`auto-fill` 按容器宽自己决定开几列。

**卡内每一段都要定行数，卡才等高。** 只截不撑的话，标题短的那张下面每一行都比邻居高一截，
几张并排时没有可比的基准线。标题给 `line-clamp` **加** `min-height`，
页脚给 `margin-top: auto` 贴住卡底。

**展开的那张占两格，不铺满。** 不跨的话它只是变高，而一栏 358 px 里读长段中文全是短行；
跨满整行又回到「一张卡撑满屏幕」。一次只展开一张，最多错开一格。

### 卡片的主操作是「点这张卡」，页脚那几颗次要动作默认收起来

一张卡上并排三颗按钮（读 / 收藏 / 不感兴趣），一屏九张就是二十七颗——
而**它们里只有一颗是你每次都会点的**，其余两颗是你看完之后偶尔用一次的。
判据：这颗按钮是「打开它」的同义词吗？是就删掉，让整张卡承担这个动作；
不是就退到 `hover` / `:focus-within` 才出现。

⚠️ **状态不跟着收。** 「已收藏」「说过了」这类**已经发生过**的标记要一直看得见
（`:has([aria-pressed="true"])`），否则鼠标一移开就看不出自己刚才做了什么，
第二天扫同一批时会再做一遍。

⚠️ **选择用的 checkbox 和「已读 / 未读」不是一枚东西。**
情报的卡曾把它们塞进同一个 `<label>`：一个空方框后面跟着「未读」两个字，
读出来像是「勾上就算已读」。已读/未读靠标题前那枚点和字重说，
checkbox 平时收起来——一屏九个空方框会是屏幕上最先被看见的东西。

### 要逐条判断一批东西的页面，用右侧面板，不要整页跳转

情报的今日精选、灵感库的待处理、Wiki 的待审阅都是同一种场景：
**一批进来，逐条决定留 / 弃 / 展开。** 整页跳转的代价不是多一次点击，
是**每读一条就把列表位置和已勾选的那几条丢一次**；挑十条要来回二十次，
每次回来都得重新找刚才读到哪儿。

面板照 `SideRail.jsx` 那套三段：**固定的上下文 → 滚动的正文 → 固定的动作条**。
动作条跟着内容滚的话，正文长一点就得先滚到底才能点最后那颗按钮。

⚠️ **键盘流是这个模式的一部分，不是附加项**：↑/↓ 换条、Esc 关掉、Enter 进全屏，
外加这一页自己的一两个判断键。键盘监听放在**列表**那一层而不是面板里——
拆成两处的话，面板有焦点和没焦点时是两套行为，而用户不知道焦点在哪儿。
输入框里要让开（`INPUT` / `TEXTAREA` / `contentEditable`）：
少这一层判断，用户在搜索框里每敲一个 s 就收藏掉一条。

窄屏（<1000px）面板盖住整块工作区，不和列表并排——并排时正文只剩不到 300px，
读中文全是短行。整页详情仍然保留，作为面板里「全屏打开」的落点：
长文加讨论栏需要一整屏的宽度。

### 两栏并列时，栏宽跟内容宽走，不跟条数走

手动探索是「左边挑一条知识、右边挑一个用户问题」。上一版按条数分成 3fr / 2fr，
理由写的是「知识 95 条、问题几条，等宽是假对称」——**分反了**：
左边是词条名（两到四个字），右边是整句用户问题。结果就是短标题那栏空着大片，
长问句那栏被挤成两行。两边做的又是同一件事，等宽也让它们读起来是一对。

**挑东西的列表要能扫。** 那两栏原来一行约 140 px 高（大字标题 + 完整摘要 + 元信息），
而列表限高 480 px——同时只看得到三条半，左边却有 95 条。
摘要截一行、字号收一档之后同屏六条，完整摘要点进去就有。

### 眉标要挣它占的那一行

一段内容前面挂一个灰色小标题，只有在**读了内容还猜不出这是什么**的时候才值得。
内容机会那张候选卡曾有六个（你认为可能有人在困惑 / 你的知识 / 为什么值得连接 /
可能留下的判断……），380 px 的卡里光标签就占四行——而一个问句不用标注「这是个问题」，
一句加粗的结论不用标注「这是结论」。砍到两个之后卡从 476 px 降到 268 px，
一个字的内容都没少。

**同一个免责声明只说一遍。** 那张卡上「**你认为**可能有人在困惑」和
「**你认为**这可能是一个受众问题，尚待真实反馈验证」连着出现，中间只隔一个问句。
真实性文案尤其要盯死这条：措辞只有一处真源（服务端的 `evidenceLabel`），
界面别在它前面再加一句自己的话。

### 眉标逐个过一遍：这一张表就是判据

「读了内容还猜不出这是什么」太抽象，落到具体内容上其实只有几种形状。
发现方向那几页一次砍掉 21 个眉标（方向详情 6→2、内容简报 11→3、讲法卡 4→2、
总览卡 1→0），过的就是这张表：

| 内容长什么样 | 判 | 为什么 |
|---|---|---|
| 一个**问句** | 删 | 问号自己会说话，不用标注「这是个问题」。改成引号 + 大一档字号 |
| 一句**加粗的结论** | 删 | 加粗即结论。它要么就是这一屏的标题，要么是标题下面加重的那一行 |
| 一段**解释** | 删 | 读了就知道是解释。它是正文，不是一份带标签的字段 |
| 一句**真实性说明**（服务端的 `evidenceLabel`） | 删标签留话 | 那句话本身已经说清了它是什么；上面再加一句「为什么值得关注」就是同一个免责声明说两遍 |
| 一**列名字**（词条、来源、页面） | 留 | 不说清是什么列表就读不懂 |
| 几条**待办 / 缺口** | 留 | 看不出这几行是「还没做的」 |
| 一段**风险 / 警告** | 留 | 看不出语气；这一档还该给它 `--emph` |
| **两份并列的清单** | 留 | 必须说清哪份是哪份 |
| **引文 / 依据** | 留，但折叠 | 它回答「凭什么」，是读完之后才查的东西，不该敞开占正文 |

⚠️ **同一批引文只摆一处。** 方向详情曾经有「看原话」和「这个方向如何形成」两个折叠，
渲染的是同一批 `problem.evidence`——一屏上同一段话出现两遍，而两处都不会报错。

⚠️ **右栏目录只在内容长过一屏时才成立。** 内容简报那份目录有五个锚点，
而那五段全在同一屏里；里面还混着「保存之后」——那是一段说明，不是一个可以跳的地方。
说明该贴着它解释的那个动作（底部那条回执），不是挂在目录里。

### 一个没有量表的评级，要么给它引子，要么别给

「很自然」单独摆在页脚上说不清什么——没有量表、没有对照，也不驱动任何动作。
它下面正好有一段专门解释为什么自然，合成一句之后评级成了那段话的引子。
而「进行中」那一段连引子都没有，那颗药丸就整个撤掉：
那一段要回答的是「哪一条我该接着做」，那由「建没建项目」决定，不由保存时的评级决定。

### 页面不介绍自己

页名只在外壳页头（`.view-head`）出现一次，页面内不再重复标题。
**说明句只在空态出现**：给第一次来的人的那句话，不该每天占着第一屏最上面一行
把真正的内容往下推。`PageHeader` 的 `desc` 因此默认不传。

同理，页内不放「会把整页换掉」的切换器：那是导航，归侧栏。
页内那一条只筛当前页。创作页的「全部文章 / 合集」为此搬进了侧栏——
它原来就贴在真正的筛选芯片上面，两条长得一模一样，点之前分不出哪条会换页。

## 控件

- 先复用现有 Button、Input、Dialog、Menu、Tabs、Toast 和编辑器控件。
- 危险动作写清对象、影响和可恢复性；确认框不能只写“确定删除吗”。
- disabled 必须有真实原因；需要用户理解原因时直接说明，不让按钮无声失效。
- 搜索支持清空与 Escape，结果打开精确对象；找不到时给可执行下一步。
- 表单错误贴近字段，保存结果贴近保存动作，不另造遥远的诊断区。
- **同一颗控件的各个状态必须写在同一条选择器路径上。** 容器为「常规成员」定的规则
  （如输入器那行的 `padding` / `height` / `background`）会默默套到特例成员身上，
  而特异度更长的那条赢——把几何和颜色分散在两种特异度上，丢掉的那一档不会报错，
  只会在屏幕上消失。排查这类问题看 `getComputedStyle`，不看 CSS 源码，
  也不看 matched rules：那两处都会照着你写的复述一遍。
- 纯图标钮放进有内边距的按钮行时，显式归零 `padding` 并给图标 `flex: none`。
- 只有一两项的菜单不设 `min-width`：框贴着内容，否则右侧空出的死区读起来就是「没对齐」。
- **文字输入类控件的焦点不画黑框。** 浏览器把文本输入框一律判为 `:focus-visible`，
  鼠标点一下就套上全局那圈 2px 近黑描边——一屏最安静的控件反而最重。
  统一改成边框往下走一档（`--border-strong`）：输入框有光标和即时出字，
  焦点感知不靠描边。按钮和链接不在此列，键盘用户只能靠那圈描边定位。
- **浮层的宽度锚在它该对齐的那个盒子上，不要用 `100vw` 兜底。**
  模型菜单曾按 `min(320px, 100vw - …)` 算宽度，而它其实待在一条 336px 的右栏里，
  于是顶出栏外被 `overflow: hidden` 切掉半截。把定位父级换成输入器之后，
  同一条规则在完整页、右栏、浮层里都自动是对的。

## 删除

**这个工作区的删除全是软删除**（`entities.deleted_at`，或者像精选/方向那样的一个标记位），
所以界面上有三条硬规则：

- **文案照实说「移入回收站」，不说「已删除」。** 说重了，用户下次就不敢按；
  而说的又不是真的——东西还在库里，`restoreEntity` 一步就能拿回来。
- **每一次删除都给一条带「撤销」的回执**（`lib/use-undo-toast.js`，带撤销 8 秒、纯回执 5 秒）。
  ⚠️ 这一条不是锦上添花：**界面上没有回收站页面**，所以那颗「撤销」是「点错了怎么办」的
  唯一答案。**点错一下的成本应该是再点一下，不是打开备份翻废纸篓。**
  在详情页删掉之后要用 `handOffUndo` 把回执交接给你被送回的那一页——
  回执该出现在你正在看的地方，不是在正在卸载的那一页上。
- **两步确认 + 挡一次物理双击**，一份实现：`ui.jsx` 的 `RowDelete`。
  「取消」排在最右（行里最靠手的落点落在安全那颗上），确认态整行/整卡钉住
  （`data-confirm`），否则鼠标一挪走按钮就没了。320ms 那道闸的来历见
  `lib/use-confirm-guard.js`——**两步确认本身挡不住一次物理双击**，别重新推导。

⚠️ **删除入口平时不常驻。** 一屏九十行各挂一个垃圾桶，那一列会比内容还抢眼；
`hover` / `:focus-within` 才出现，窄屏（没有 hover）常驻。
**但状态要一直看得见**：「已收藏」「已保存方向」「恢复推荐」不是等着被点的动作，
它们是这一条现在什么样。

⚠️ **整行 / 整卡不能是一颗 `<button>`。** 删除入口要待在行里，而按钮里套按钮是非法 HTML——
浏览器会把内层那颗拎出去，点击落点整个乱掉。外层用 `<article>`、打开是内层铺满的那颗、
动作在右端；`studio/DocRow.jsx`、Wiki 列表行、选题卡、方向卡是同一个形状。

### 归档要有归档箱

按下「不感兴趣」之后那一条从列表上消失，而**没有任何地方能看到或恢复它**——
那不是归档，那是不可逆的删除穿着归档的衣服。今日精选的 `dismissed` 一直在库里，
缺的只是那个「已忽略」档位；`intel_directions` 缺的只是一列标记位。
判据：**任何让内容从当前视图消失的动作，都要有一个能看到它去哪儿了的地方。**

## 状态

根据组件类型覆盖：default、hover、focus、pressed、selected、disabled、loading、empty、success、warning、error。

- loading 不闪假空态；
- empty 说明如何开始；
- error 说明什么没完成、已有内容是否安全以及如何重试；
- success 安静确认，不把每次自动保存变成跳动文案；
- warning 只用于确实需要注意的未完成条件。

提示框使用一个安静表面和必要的图标，不用通用彩色左竖线。只有真实错误使用红色语气。

**状态 pill 不画底色。** 颜色收进那枚形状图标里（`--tone`，那套值本来就是给图标描边挑的），
文字退成 `--text-2`。一列同色的底块竖着排下来会成为整屏最亮的东西，
而那一页的主角是旁边那些标题。状态仍然两条路都能读：形状不辨色也认得出，词就写在旁边。

**筛选器不借用状态的语义色。** 「这一页现在只看哪一部分」是「你在这儿」，
走 `--sel-bg` / `--sel-fg`，和侧栏当前项、`.view-tabs` 同一套语汇。
黄色（`--mark-yellow`）留给「我给它贴的标」那类芯片——入库选类型、来源种类。
两者混用的后果在创作页量得到过：一排黄芯片压在一列黄色「写作中」上面，
同一个颜色在同一屏说两件无关的事，而且筛选器比它筛出来的内容还显眼。

## 编辑与阅读

- 正文编辑器保留 Markdown 源文本，自动保存绑定 SQLite 版本；并发冲突不覆盖。
- 候选、引用和报告是编辑器的协作层，不伪装成已保存正文。
- 书籍正文、章节、高亮和批注都由当前工作区管理。标题、类型或只读状态由书籍记录决定。
- 书架以封面识别为主；阅读详情优先“继续读”和“最近标记”，不是重复展示内部路径。
- 媒体写入资产库，正文保存稳定 asset URI；渲染层负责生成本机读取地址。

## AI 表面

- 项目协作栏与正文并排；Quick Assistant 浮在当前页面上但不阻断背景。
- AI 默认只读取明确对象，不抓 DOM。
- 结果区分 Answer、Candidate、Report 和 Proposed Action。
- 检查报告用“高风险 / 建议修改 / 可选优化”；真实阻断由代码硬闸承担。
- 候选采用按钮必须在候选旁，采用前可以编辑和比较。

## Motion

不要默认加动画。只为反馈、状态变化、空间关系或连续性使用动画；常用键盘操作优先即时。一般界面过渡保持短促的 ease-out，reduced-motion 下取消位移、缩放和非必要渐变。

## Responsive 与 Accessibility

- keyboard-only 能完成主要任务；focus 可见且不被遮挡。
- Dialog/Popover 使用成熟 primitive 的焦点、Escape 和 ARIA 行为。
- 小屏幕优先保住正文和当前动作，次要栏可折叠，不制造嵌套滚动。
- 文本和状态不只依赖颜色；长标题、空数据和快速连续操作都要验收。

## 完成标准

- 真实数据下默认、空、错、忙和禁用状态均可理解；
- 主流程可用键盘完成，focus 与 Escape 正确；
- 小屏幕和 reduced motion 可用；
- 复用了现有组件，复杂模式在适用时查过成熟方案；
- TypeScript/构建、相关测试和真实浏览器流程通过；
- 视觉任务已查看最新截图，而不是只相信构建或 HTTP 状态。

## 选题与阅读布局

- 首页提供各部分概览、最近打开和最近阅读；快速记录保持轻量。
- 选题使用左侧文档、右侧持续讨论。思考、文章、资料在左侧切换，聊天和输入区保持原位。
- AI 整理的理解可以折叠，与用户自己的笔记明确分开；正文和笔记不套大型卡片。
- 阅读页只显示一次标题，原文优先，AI 按需展开；小屏在原文和讨论间切换。
- 小屏输入区留在可视区域，长内容在各自区域滚动。保留正文内空格唤起 AI。
