# workbench 架构与存储

## 定位

workbench 是单用户、本地运行的创作者工作台。它把采集、素材、种子、内容项目、正文、书架、发布数据、复盘和 AI 协作放进一个可以完整备份和恢复的工作区。

## 运行架构

```text
浏览器（React）
  │ localhost HTTP
  ▼
Vite 本地进程
  ├─ server/routes        本地 API
  ├─ server/domain        业务不变量与动作
  ├─ server/storage       SQLite、资产和工作区生命周期
  ├─ server/backup        备份、预检、恢复与恢复前快照
  └─ server/agent-runtime Pi Agent SDK、权限与候选动作
```

应用只监听 `127.0.0.1`。API 与前端同源，不单独部署服务端。`npm run build` 只做编译验证，日常运行仍使用 Vite 本地进程或开始菜单入口。

## 单工作区

默认总根是系统“文档”目录下的 `Xenho`；`XENHO_HOME` 只能显式覆盖整个根。

```text
Xenho/
  workspace.json
  Workspace/
    workbench.db
    Assets/
    Books/
    Attachments/
  Backups/
  Exports/
```

`workspace.json` 标识工作区；`workbench.db` 是唯一业务真源。资产文件不自行表达业务关系，引用、版本、校验值和归属都记录在 SQLite。

路径输入必须经过根目录限制。备份恢复、测试和 Agent 挂载都不得使用未核验的绝对路径、上跳路径、链接逃逸或目录联接越界。

## 业务数据

SQLite 保存：

- 采集、素材、种子、项目、简报、稿件和正文版本；
- 素材关系、引用、发布记录、指标、复盘与反馈；
- 书籍、章节、高亮、批注和阅读记录；
- 设置、提示词、后台任务、审计、回收站和幂等请求。

本地域层负责状态转换、真实性约束、幂等、版本冲突和可恢复删除。前端只消费 API 返回的稳定字段，不复制状态机。

## Markdown 互操作

Markdown 是可携带格式，不是第二真源：

- 导入时解析并写入 SQLite 与资产库；
- 导出时从当前 SQLite 快照生成；
- 不监视外部目录，不做双向同步；
- 不根据 Markdown 路径反推业务状态。

## AI 与外部能力

Pi Agent 读取当前工作区或用户明确授权的本地挂载。AI 可以搜索、分析和生成候选，但修改正文、状态、发布、删除、写文件和执行命令必须由用户确认后交给应用或领域接口。

模型、翻译、网页正文、热榜、搜索和本机排版工具都是可选能力。单个能力失败只影响对应模块，不得伪装成成功或拖垮工作区。

## 备份与恢复

完整备份包含 SQLite、资产、图书原件和附件；便携备份可省略大体积图书资产。恢复必须先预检，再要求匹配的确认摘要；应用恢复前自动建立完整快照。`.env`、密钥和工作区外部数据不进入备份。

## 测试安全

任何会写持久化数据的测试必须：

1. 在系统临时目录创建独立 `XENHO_HOME`；
2. 串行运行；
3. 不读取或写入真实个人工作区、历史知识库或 `.xenho`；
4. 结束后关闭数据库和子进程，再清理临时目录。
