# workbench 总体方案

> 2026-08-10 定稿 v1，2026-08-18 随「库从 Notion 迁到 D1、两个包合进 content-studio」订正一遍。
> **订正只动「现在是什么样」的部分**；第八节的分批计划是当时的施工记录，保持原样，别拿它当现状读。
> 原文基于与辛禾的多轮讨论，基于与辛禾的多轮讨论，参考 [oyorf/person_dashboard](https://github.com/oyorf/person_dashboard) 的架构思路（本地优先、数据即文件、Agent 友好），但代码自研、体量收敛。

## 一、定位

一个**本地运行的创作者工作台**，服务一个人（辛禾）的完整创作循环：

```
输入（热点/洞察/书摘）→ 加工（灵感→素材→选题→成稿）→ 发布 → 反馈（平台数据）→ 反哺选题
```

它不是新系统，而是把已有系统接起来的**驾驶舱 + 阅读工作区**：

- 同仓的 `worker/`（Cloudflare Worker + D1 四库 + Telegram / 飞书 Bot）继续原样运行，工作台是它的观察与操作面
- Obsidian vault 继续是写作与笔记的家，工作台读它、往里落笔记，不替代它
- wechat-typeset、xenho-cover 保持独立，工作台只提供入口跳转

**明确不做**：知识星图、wiki 层（演示效果好、日常用不上，且代码最重）；深度写作编辑器（Obsidian 的事）；排版（wechat-typeset 的事）；多用户、公网部署。

## 二、核心原则（违反任何一条前先回到本文档改设计）

1. **工作台无状态**。所有交互产物——批注、笔记、对话记录——落成 vault 里的 Markdown 或库里的字段/批注。工作台重写、废弃、换框架，用户数据零损失；Obsidian 里永远能看到属于 vault 的那一半。
2. **行归数据库，文归 vault**。状态机里流转的「行」（灵感、素材卡、选题、稿件状态）在 D1；亲手写的「文」（读书笔记、长思考、批注）留在 Obsidian，不搬家。写作习惯一点不改。
3. **单向归档，永不双向同步**。只允许 D1 → vault 的单向导出（已发布成稿归档为 Markdown）。库 ↔ Obsidian 双向同步是著名深坑，红线禁止。
4. **每一块独立失败**。热点 API 挂了显示「今日无数据」，Worker 不通显示「上次更新于 X 前」，任何上游故障不能拖垮整个页面。
5. **打通靠数据汇合，不靠界面跳转**。统一入库动作 + 统一标签词表 + 来源回链（见第五节）。

## 三、总体架构

```
┌─────────────────────────── 浏览器（仅本机） ───────────────────────────┐
│  总览 │ 稿件库 │ 素材库 │ 灵感库 │ 书架 │ 热点 │ 洞察 │ 平台数据      │
└──────────────────────────────┬───────────────────────────────────────┘
                               │ HTTP (localhost)
┌──────────────────────────────▼───────────────────────────────────────┐
│                    本地服务（Node.js + Hono）                          │
│  /api/vault/*   读写 vault 文件（书架、热点、洞察、伴生笔记、归档）        │
│  /api/pipe/*    转发同仓 worker/ 的 /wb/*（列表、状态、intake、批注）    │
│  /api/ai/*      划词即时 AI（转发 LLM 代理，流式）                       │
│  /api/agent/*   Pi Agent SDK 对话（服务端权限模式 + NDJSON）      │
│  /api/data/*    平台数据（抖音 Excel 解析、手动 metrics）                │
└──────┬──────────────┬──────────────┬──────────────┬─────────────────┘
       │              │              │              │
   VAULT_ROOT     CF Worker      LLM 代理      Pi Agent SDK
  （Obsidian）    （D1 四库）
```

关键选型与理由：

- **必须有本地服务**（不能是纯静态页）：要读本地文件系统（vault）、要持有密钥转发 Worker/LLM、要 spawn CLI。这也是隔离密钥的方式——密钥只在服务端 `.env`，前端一行密钥都没有。
- **本地服务挂在 Vite dev server 的中间件里**，不另起进程也不配代理（`server/vite-plugin-workbench.mjs`）。一条 `npm run dev` 起全部，省掉端口对不上和 concurrently 这类依赖。**没有引服务端框架**：总共十来条路由，一个 40 行的匹配器比一个依赖更好维护。代价是 API 只在 dev 模式存在——工作台永远跑 dev，`npm run build` 只用于验证前端能编译。
- **前端 Vite + React**：页面多、阅读区交互重（批注、划词、流式对话），原生 JS 会越写越痛苦。与 wechat-typeset 的零构建哲学不同，因为本项目反正要跑服务，「双击即用」已不成立。
- **库一律经 Worker，不直连**：**Worker 是所有数据规则的唯一真源**，表结构、状态机、字段映射都在那边，工作台拿到的是 `/wb/*` 压平后的扁平字段，不抄第二份。这条兑现过一次——从 Notion 迁到 D1 时 `/wb/*` 的对外契约一个字没动，工作台一行没改。

## 四、存储契约

### 4.1 流水线侧（D1，经 Worker 的 `/wb/*`）

| 数据 | 位置 | 工作台权限 |
| --- | --- | --- |
| 灵感库 | D1 `inbox` | 读 + intake 新增 + 改状态 + 删 |
| 素材库 | D1 `materials` | 读 + intake 新增 + 批注 + 核验 + 删 |
| 选题库 | D1 `topics` | 读 + 改状态（改成「撰写中」先弹平台选择）+ 删 |
| 稿件库 | D1 `drafts` | 读 + 改正文 + 批注 + 记录发布 + 删 |

**状态取值的真源是 `worker/schema.sql` 的 CHECK 约束**，工作台的 `states` 和它逐字一致，差一个字就是 400。

### 4.2 vault 侧

**目录名的唯一真源是 `server/lib/vault-dirs.mjs` 的 `DIRS`**，不要照着下面这张图硬编码——
漏改一处的表现极具误导性：目录不存在时列表返回 `null`，界面显示的是「还没建，去导一本」的
**空态引导**，看起来像「你还没用过这个功能」，不像出错。

```
<VAULT_ROOT>/99 - 个人工作台/
  01 - 书架/
    <书名>/
      book.md          # 元信息（frontmatter：书名/作者/类型/状态/标签）+ 正文笔记
      notes.md         # 工作台批注伴生文件（追加式）
      <章名>.md         # 章节平铺，按文件名 numeric 排序
      <章名>.highlights.md  # 高亮伴生文件（锚点是原文文本，不是字符偏移量）
  02 - 洞察/
    2026-W32-社媒洞察.md  # skill 生成的研究报告，只读渲染
    _material/          # 原始周材料
  03 - 归档/发布作品/
    <平台>/<日期>-<标题>.md  # 稿件库「已发布」单向导出（只增不改）
  04 - 网页批注/<host>/…
  05 - 计划/<YYYY-MM-DD>.md  # 手写的每日任务清单
  09 - 热点/<日期>.json      # 每日热点快照
```

序号的分配有含义：**01–04 是你的字**（读的书、写的报告、发出去的稿、随手的批注），
05 是你的承诺，**09 是机器抓的数据**（json，不是给人读的）。中间留着空号，以后加一类不用重排。

### 4.3 伴生批注格式（`notes.md`，追加式）

```markdown
## 2026-08-10 14:32
> 被批注的原文片段（前 120 字）
批注正文…… #标签
来源: [[book.md]] | https://…
```

- **为什么伴生而不是改原文**：洞察报告等文件由 skill 重跑覆盖，笔记混进去就丢了；伴生文件在 Obsidian 里就是普通笔记，可搜可链。
- 流水线侧（素材卡、成稿）的批注不落 vault，写进库里的 `comments` 表（经 Worker）。**只有这个工作台能看到它们**——界面上的 `annotateLabel` 必须如实这么说。

### 4.4 平台数据（`data/`，项目内不进 vault）

- `data/posts.csv`：**已发布内容的事实层，一条内容一行**（`date,platform,title,url,views,likes,comments,collects,shares,extra,doc,synced`）。数据页上的发布量、渠道分布、以后的内容明细和复盘四象限全从这一份聚合。**整份重写不追加**——导入是「合并」不是「续写」，同一篇再导一次要更新它的数字。
- `data/metrics.csv`：账号级周录（日期,平台,粉丝,阅读/播放,备注）。它和上面那份**不是一回事**：posts 是内容级、平台导出给的；metrics 管**粉丝数**，那是账号级的，导出文件里没有也不会有。
- `data/douyin/`：抖音创作者后台官方 Excel（浏览器 skill 下载，见 7.4）
- `data/.snapshots/<key>/`：**自动快照**。上面这几份数据（外加 `config/attention.json`）每次改动前先留一版，保留 `SNAPSHOT_KEEP_DAYS` 天（默认 30）且最近 5 份永远保留。总览底部「备份与恢复」里可以按时间点回退，也可以把这些数据连同浏览器本地状态一起导出成一个 zip 带走。**vault 正文不进这个 zip**——它有自己的备份方式，包里只记路径。

## 五、打通机制（本方案的灵魂）

### 5.1 统一入库：万物皆可一键变素材

content-pipeline 的 Telegram 命令（/金句 /概念 /案例 /数据 /框架 /素材）已经定义了完整的入库逻辑：分类、`TAG_PROMPT` 自动打标、`#token` 挂选题、出处字段。给 Worker 新增一个 HTTP intake 端点复用同一套代码，工作台各处的「入库」按钮全部指向它：

- 热点条目 → 一键进灵感库（标题 + 链接），走正常初筛
- 洞察报告选中一段 → 存为素材（LLM 分类路径已有）
- 书摘金句 → 金句素材，出处自动带书名
- agent 对话中的结论 → agent 自己调 intake 存卡（见 7.3）

### 5.2 统一标签词表

`prompt/tags.md`（TAG_VOCAB）升级为全工作台标签基准：热点、洞察、书架批注打标都从词表选。回报在成稿环节——`fetchSupplementary` 按标签检索垫料时，上月存的热点和书摘会自动出现在同标签选题的 prompt 里。**数据在使用时汇合，这才是打通。**

### 5.3 来源回链

每条入库内容必须带出处（URL / 书名 / 报告文件名 / 对话存档路径）。从稿件库一篇成稿沿「关联素材 → 出处」能追回观点源头。成本≈0，收益是整个系统从六个工具变成一条有记忆的链路。

## 六、Worker 端点扩展（`worker/` 侧改动）

> ⚠️ 这张表是当初新增的那一批，**不是现在的全集**——后来还长出了 `/wb/publish`、`/wb/update`、`/wb/content`、`/wb/delete`、`/wb/explain`、`/wb/pick/materials`、`/wb/draft/material`、`/wb/cite`、`/wb/models` 等等。要看全的以 `worker/src/workbench.js` 的路由表为准。

新增，鉴权用独立低权限密钥 `WORKBENCH_KEY`（不复用 TELEGRAM_WEBHOOK_SECRET，泄露可单独轮换）：

| 端点 | 作用 |
| --- | --- |
| `GET /wb/status` | 各库待处理计数（复用 /状态 命令逻辑） |
| `GET /wb/list/{inbox\|materials\|topics\|drafts}?state=&cursor=` | 分页列表，返回精简字段 |
| `GET /wb/page/{id}` | 单条详情（素材正文、成稿内容） |
| `POST /wb/intake` | 统一入库：`{type, content, source, tags?, topicHint?}`，复用 telegram.js 存储逻辑 |
| `POST /wb/comment` | 给素材/成稿写批注（落库里的 `comments` 表）：`{pageId, text}` |

注意：受免费版 subrequest ≤50 限制，列表端点一次只拉一页，不做「全量拉取」。

## 七、模块清单与交互设计

### 7.1 总览（首页）

回答两个问题，顺序不能反：**有没有新活**（等你动手的两个数字 + 流水线在跑的三个）、**我上次干到哪了**（接着读的书 / 最近改过的稿 / 今天值得看的情报）。底部一条系统行放 vault 路径和归档入口。**四个库的外链已经撤掉**——库迁到 D1 之后它们指向的是一份不再更新的旧数据，而一个通往过期数据的链接比没有链接更糟。全部区块独立失败。

计数**分两组**：「待初筛 / 待整理 / 撰写中」是 Worker 自己会消化的队列，0 是正常态，收进第三张卡里的一列小字；「选题待写 / 待修改」不点它就不会动，给大数字。摊成一排同样大的卡片时，首屏最贵的那一行会有大半在展示「没有事」。三张卡外壳一致，层次靠内容（46px 数字 vs 三行小字）拉开。

### 7.2 阅读工作区（素材库 / 书架 / 洞察 共用一套阅读组件）

- **读**：左侧列表，右侧正文渲染（vault 文件直接渲染 Markdown；流水线素材经 Worker 的 `/wb/page/{id}` 取正文）
- **批注**：选中文字 → 写批注 → 落伴生 `notes.md`（vault 内容）或库里的 `comments` 表（流水线内容）
- **划词即时 AI**：选中 → 解释/展开/反驳。LLM 上游仍走 SSE，但 Worker 先收齐并完成真实性校验，再把纯文本返回界面。**默认阅后即焚**，点「存为笔记」才落盘——否则 vault 会被一次性解释糊满
- **一键入库**：选中 → 存素材（5.1）

### 7.3 agent 深度对话

保留现有 React chat 壳和 /api/assistant/* NDJSON 契约，本地服务直接运行 Pi Agent SDK。Pi 可读取 vault、批注、附件、Skills 和 Worker/D1 业务上下文，但能力由 daily / creative / developer 三种服务端模式裁剪。所有写入、命令和业务动作先生成候选卡，只有用户明确确认后才由应用层执行；Worker/D1 始终是业务状态、关系、幂等和长任务的唯一真源。对话历史继续落本地 conversation.json，并额外保存 Pi session 标识。
### 7.4 每日热点

定时任务（本地调度器或 cron）拉公开聚合 API → 按日存 JSON。**定性为 best-effort**：API 挂了显示「今日无数据」，不修不救；30 天自动清理；看中的条目一键入灵感库。

### 7.5 社媒洞察

不是实时数据，是**按需生成的研究报告**。做成独立 skill：搜集近期讨论 → 产出 Markdown 报告落 `洞察/`，工作台只读渲染 + 可批注 + 可摘素材。每周跑一次足够。

### 7.6 书架

`书架/` 目录一书一夹。工作台渲染书墙 + 笔记阅读页 + 批注 + 对话。**不做**进度管理、评分——那是豆瓣的事。笔记长到想调结构 → 该进流水线变选题，不在书架里继续长。

### 7.7 平台数据

**地基是「一条内容一行」，不是账号级周录。** 这一页所有块——本月发布量、每周发布量、渠道分布、内容明细、复盘的四象限——全部是从 `data/posts.csv` 聚合出来的。没有这一层，上面每一块都是空的。

**采集：接受现实，个人拿不到官方 API。** 公众号数据接口只给已认证服务号，小红书开放平台是给品牌和 MCN 的，抖音要企业主体；X Basic $200/月。第三方（新榜、飞瓜）是估算数据、要钱，也不是你后台里的真实数字。爬 App 接口违反条款且风控极严。

**唯一合法的自动路径是：用机主自己已登录的浏览器，去后台点那个「导出」按钮。** 数据是平台给的，只是换个地方看。所以「自动化」要做的不是绕过导出，是把导出之后的活儿全吃掉——按自动化程度排：

1. **自动发现**（已做）。后台点完导出，回工作台它已经在那儿等着了：扫下载目录 + `data/inbox/`，认出平台、算好新增几条，一键导入。你的操作只剩「在后台点导出」+「回来点一下」。
2. **浏览器自动化 skill**（待做）。用 Claude in Chrome 在已授权的浏览器里开三个后台、点导出、下载、调 `/api/posts/inbox/import`。你的操作只剩说一句「更新数据」，外加万一有验证码自己过一下。**遇验证码即停，不尝试绕过；只碰自己账号；只读 + 下载，不改后台任何设置。**
3. **定时**：第 2 步跑通之后挂个每周一的 cron 就是顺手的事。
4. **手录一条**：X 和视频号导出能力差，兜底得有。

**页面是两个 tab，不是两个侧栏项**（月度总览 / 数据来源）。数据只有一件事——「发出去之后怎么样」，拆成两个侧栏项等于让人每次先想「这个数字在哪一页」。内容明细和月度复盘是二三期，**不摆禁用的页签**。

**未来的复盘结论落 vault 的 `洞察/`，是一份 Markdown 月报**，不是只活在那个页面里的一块 HTML。这样它会出现在洞察源的卡片墙上，能读、能批注、能划词摘成下个月的选题——这才叫闭环。

### 7.8 归档导出

定时任务把稿件库「已发布」成稿导为 Markdown 落 `归档/发布作品/`。单向、只增不改。收益：本地作品全集、Obsidian 可全文搜、未来文风范例/RAG 语料现成。

## 八、分批计划

**第一批：地基**（先立双向数据通道，其余一切靠它）— ✅ 已完成 2026-08-10，端到端待用户部署 Worker 后验证
- 本地服务骨架（vault 读写 + Worker 转发 + .env 配置）
- Worker 六个 `/wb/*` 端点（比原计划多一个 `ping`：连通性探针不碰 Notion，界面判断「通不通」不烧配额）
- 总览页 + 四库列表呈现 + intake 抽屉
- 存储逻辑抽成 Worker 的 `src/lib/store.js`，Telegram 命令与工作台 intake 共用一份
- 验收：工作台能看四库列表与计数；提交一条素材后 Notion 出现且 Telegram 流程无感知；断网/断 Worker 时页面降级不白屏（`npm test` 已覆盖后者）

**第二批：阅读工作区** — ✅ 已完成 2026-08-10
- 书架 + 素材阅读页 + 伴生批注 + Notion 评论写回 + 划词 AI

2. **排版语义写在 class 里，不在标签上**。出版社 epub 大量用 `<p class="subhead">`、`<span class="quotation-s2">`，只认标签就只能看到一片 `<p>`。现在块的语义 = 标签 + 自身 class + 内部 span 的 class，映射表是数一遍这本书的真实用法定出来的。
3. `tidy()` 收尾：两段引用之间不画线、连着的引用并成一块、但隔过装饰符的留着分开。
4. pdf 没有结构层，只能从形状认标题，**判据从严**——误判成标题比没有标题更坏。

结果（《纳瓦尔宝典》）：9 个 `##`、40 个 `###`、92 个 `####`、255 行引用、37 处强调、15 张插图，HTML 残留 0。断言直接数标题和引用的条数钉在 `tests/unit.mjs` 里——只查「有没有 HTML 残留」是抓不住这个 bug 的。

2. **导入分两步**（`?dry=1` 先看、再确认写盘）。解析器只能靠**列名**认字段，认错了不报错、不白屏，只会让一列数字安静地进错格子——所以必须把「我把哪一列当成了什么」摊开给人看。这是这个流程存在的全部理由。
3. **发布量画堆叠柱不画折线**（参考用的是三条折线）。发布量是整数、量级只有 0~4，折线会在 1 和 2 之间画斜线，等于宣称「周三发了 1.5 篇」——那个数不存在。
4. **指标名按平台换字**（小红书「观看」/ 公众号「阅读数」），**某个指标一条都没有值时整格不出现，不显示 0**。摆一个 0 会被读成「收藏了 0 次」，而真相是「这个平台没有这个指标」。
5. **首行第四格直接写缺口**（「缺 3 · 小红书 3 篇」），不写「可分析」这种模糊词——它既是状态也是下一步。
6. **空态自己会讲话**：参考那个界面里全是数据所以看不出这块，而我们的第一屏就是空的。摆四个 0 和一张空图等于让人自己猜；现在是拖拽区 + 四个平台各一句「去哪导」。
7. **月度复盘的 AI 结论留到三期**，且要守三条：样本不够就说不够、绝不编数、结论必须能指回具体哪几篇。参考作者自己也说「目前比较粗糙，只能当信号」。

8. **自动发现下载好的导出文件**（`server/lib/inbox.mjs` + `/api/posts/inbox`）。用户的原话是「我必须手动导入吗，好麻烦」——**而手动那条路里最烦的不是点确认，是在下载目录里翻文件**。那三步机器全知道答案，所以现在后台点完导出、回工作台它就已经列在那儿了，卡片上直接写着「新增 3 条」。接口认 id 不认路径（路径当参数等于开了个任意文件读取的口子）。

**跨平台四象限要按「本平台中位数」归一化，不是全局中位数**（三期做）。参考作者基本只发小红书，全局中位数够用；我们是多平台，公众号 229 阅读和小红书 3085 阅读不是一个量纲，按全局切的话公众号永远趴在左下角。

## 九、风险与对策

| 风险 | 对策 |
| --- | --- |
| 列表页卡 | 一律经 Worker 精简字段 + 分页；D1 那边计数走 SQL 的 COUNT，不再整批拉回来数长度 |
| 热点聚合 API 不稳定 | 定性 best-effort，挂了不修，独立失败 |
| 平台反爬/风控（抖音 skill） | 只下官方 Excel、只碰自己账号、遇验证码即停、频率≤日一次 |
| 交互功能诱发范围蔓延（做成半个 Obsidian） | 守第二节红线：长文编辑不做，笔记长了进流水线 |
