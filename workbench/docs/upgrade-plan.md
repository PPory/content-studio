# creator-workbench 升级迭代计划

> 版本：v1.0  
> 日期：2026-08-13  
> 状态：待执行  
> 依据：2026-08-13 工作台多角度评审及后续决策反馈  
> 关联文档：[总体方案](./design.md)

## 一、升级目标

本轮升级不改变 creator-workbench 的产品定位，继续把它建设成一个**本地运行、统一入口、数据可掌控的个人创作者工作台**。

目标不是继续增加模块，而是让现有链路更安全、更可靠、更容易连续使用，并真正跑通完整循环：

```text
热点 / 洞察 / 阅读
        ↓
素材与选题
        ↓
写作与排版
        ↓
发布作品
        ↓
导入真实数据
        ↓
复盘并形成下一轮选题
```

本轮升级完成后，应达到以下结果：

1. 导入的外部内容不能借展示过程执行有风险的网页代码。
2. 代码、正文和工作台数据均有明确的备份、恢复和回退路径。
3. 可以从任何模块快速找到内容，并继续最近一次工作。
4. 可以追踪一条热点如何变成选题、稿件、发布作品和最终数据。
5. 数据复盘只基于真实样本，结论能指回具体作品并生成下一步行动。
6. 键盘操作、弹层焦点和辅助文字达到稳定可用状态。
7. 保留统一入口，同时降低大型页面的维护风险。

## 二、已确认的产品决策

以下内容作为本轮迭代边界，后续实现不得自行改变。

### 2.1 保留统一入口

阅读器、文章提取、AI 助手、电子书转换、数据分析和排版工具集中在同一入口，是工作台的核心价值，不做模块削减，也不要求用户在多个独立工具之间来回切换。

升级方向是：

> 外部保持一套工作台，内部拆成可独立维护、可独立失败的模块。

### 2.2 暂不处理窄窗口和移动端

工作台只在电脑上使用，本轮不投入移动端、手机端或窄窗口适配。常用桌面分辨率下不得出现新增的布局退化即可。

### 2.3 真实数据先于复杂分析

用户将在近期发布作品并导入第一批真实数据。在真实数据进入之前：

- 可以完善导入、关联和事实展示；
- 可以建设热点到选题的来源链；
- 不提前设计复杂图表；
- 不生成样本不足的趋势判断；
- 不让 AI 根据空数据或少量数据猜测原因。

### 2.4 热点原始榜单保持原样

“平台热榜”和“AI 情报”继续保持现有分层：

- 平台热榜负责展示大众正在关注什么，保留原始排名，不强制过滤；
- AI 情报负责摘要、多信源合并和关注方向筛选；
- 本轮强化的是热点的后续利用和来源追踪，不是继续增加信源或再次筛选榜单。

## 三、迭代优先级总览

| 阶段 | 优先级 | 主题 | 核心产出 | 启动条件 |
| --- | --- | --- | --- | --- |
| 准备阶段 | 前置 | 真实数据准备 | 第一批发布作品与平台数据 | 用户发布并导出数据 |
| 迭代 1 | P0 | 外部内容安全 | 安全渲染、危险链接拦截、回归用例 | 可立即开始 |
| 迭代 2 | P0 | 数据恢复 | 安全写入、自动快照、导出恢复、代码回退 | 可立即开始 |
| 迭代 3 | P1 | 连续工作与来源追踪 | 全局检索、继续上次工作、热点转化链一期 | 迭代 1 完成后 |
| 迭代 4 | P1 | 数据闭环与复盘 | 作品匹配、归因、周/月复盘、行动回流 | 有真实数据后 |
| 迭代 5 | P1 | 可用性与可读性 | 弹层焦点、键盘操作、文字对比度 | 可与迭代 4 并行 |
| 迭代 6 | P2 | 内部模块拆分 | 大页面拆分、职责清晰、行为不变 | 核心流程稳定后 |

准备阶段与迭代 1、迭代 2 可以同时推进。迭代 4 必须等待真实数据，避免根据假设搭建复盘系统。

## 四、准备阶段：真实数据进入工作台

### 4.1 目标

形成第一批可以贯穿“选题—内容—发布—表现”的真实样本，为后续复盘提供事实基础。

### 4.2 操作范围

1. 发布真实作品。
2. 在内容记录中补齐平台、链接、发布日期和对应稿件。
3. 从平台后台导出内容级数据并导入工作台。
4. 对无法自动匹配的作品进行人工确认，不允许静默错配。
5. 记录导入过程遇到的字段缺失、标题差异和重复作品问题。

### 4.3 完成标准

- 至少有一条作品记录能关联到对应稿件和选题；
- 重复导入同一份数据不会重复创建作品；
- 更新后的播放、阅读、互动数据会覆盖或合并到同一作品；
- 无法确认归属的数据被标记为“待匹配”，不会被错误计入复盘。

## 五、迭代 1：外部内容安全

### 5.1 问题

工作台会展示外部文章、书籍、洞察和 AI 返回的 Markdown。如果内容中夹带网页事件、嵌入页面或特殊链接，浏览器可能把它们当作工作台自身的一部分执行。

这不是禁止 Markdown，也不影响标题、列表、引用、表格、图片、链接和代码块。需要禁止的是内容中能够主动执行或嵌入其他页面的部分。

### 5.2 实施内容

1. 所有 Markdown 展示入口统一经过同一套安全处理，不允许各页面自行决定。
2. 保留正常排版标签和必要属性。
3. 删除所有事件属性，例如点击、加载、错误等自动触发行为。
4. 禁止嵌入页面、对象、表单及其他高风险标签。
5. 禁止 `javascript:` 等可执行链接。
6. 代码块始终作为文字展示，不能被当作页面执行。
7. 外部链接采用安全打开方式，避免获得原页面控制权。
8. 对本地写入、修改和删除请求增加来源检查，不能只因为地址是本机就默认可信。

### 5.3 验收标准

- 正常 Markdown 的标题、列表、引用、表格、图片、链接和代码块显示不退化；
- 含危险事件、嵌入页面和特殊链接的测试内容无法执行；
- 外部链接仍可正常打开；
- 阅读器、选题阅读、AI 输出等所有内容展示入口行为一致；
- 浏览器中连续打开正常内容和测试内容，页面无报错，工作台数据无变化。

## 六、迭代 2：可靠的数据恢复机制

### 6.1 恢复对象

| 对象 | 主要内容 | 恢复方式 |
| --- | --- | --- |
| 代码 | 工作台源代码、配置模板、脚本 | Git 版本历史与稳定版本标记 |
| 正文资产 | Obsidian 中的稿件、书摘、洞察和批注 | 文件级增量备份 |
| 工作台数据 | 作品数据、指标数据、热点快照及必要设置 | 安全写入、自动快照、导出与恢复 |
| 浏览器本地数据 | 阅读进度、书签、排版草稿等 | 纳入导出清单或迁移到可备份文件 |

### 6.2 实施内容

1. **代码回退**
   - 建立 Git 仓库；
   - 每个完整迭代使用独立提交；
   - 稳定版本建立清晰标记；
   - 密钥、真实数据和本地路径不得进入提交。

2. **安全写入**
   - 先写入临时文件；
   - 校验写入成功和格式完整；
   - 再替换正式文件；
   - 写入失败时保留原文件。

3. **自动快照**
   - 数据修改前自动生成快照；
   - 按时间保留最近版本；
   - 默认建议保留每日快照 30 天，实际保留数量可配置；
   - 清理快照时不得影响当前数据。

4. **一键导出**
   - 导出文件包含版本、生成时间、数据清单和校验信息；
   - 默认包含工作台数据和必要设置；
   - 对 Obsidian 正文只记录路径和备份状态，避免无提示复制整个 vault；
   - 明确提示哪些浏览器本地数据已包含、哪些未包含。

5. **恢复流程**
   - 恢复前再次备份当前状态；
   - 支持预览备份时间和内容范围；
   - 恢复完成后进行数据完整性检查；
   - 失败时自动回到恢复前状态。

### 6.3 验收标准

- 模拟写入中断后，原数据文件仍能正常读取；
- 同一数据连续保存不会产生半份文件或重复记录；
- 能从自动快照恢复到上一版本；
- 一键导出后，在临时测试目录中可以完整恢复；
- 恢复失败不会破坏当前数据；
- 恢复说明能够让不了解代码的人独立完成操作。

## 七、迭代 3：统一检索、继续工作与热点转化链一期

### 7.1 全局检索

第一版采用本地轻量检索，不建设复杂搜索平台。

检索范围包括：

- 热点与 AI 情报；
- 灵感、素材和洞察；
- 选题与稿件；
- 书籍和章节；
- 已发布作品及其数据。

每条结果至少显示：内容类型、标题、来源、当前状态和最近更新时间。

结果支持直接执行：

- 继续阅读；
- 继续修改；
- 打开关联素材；
- 打开对应选题；
- 查看已发布作品及数据。

### 7.2 继续上次工作

不单独新增一个大型页面，直接作为全局检索面板的默认状态：

- 最近打开；
- 最近修改；
- 尚未完成；
- 最近阅读位置；
- 最近一次搜索。

建议使用 `Ctrl + K` 呼出，并保留清晰的可点击入口。

### 7.3 热点转化链一期

热点不再只有“看过”和“收藏”，而是能够追踪后续去向：

```text
未处理 → 已收藏 → 已形成选题 → 已成稿 → 已发布
```

状态尽量由真实关联关系计算，不维护一套容易失真的手工状态：

- 没有关联：未处理；
- 已进入灵感或素材：已收藏；
- 已关联选题：已形成选题；
- 关联选题已有稿件：已成稿；
- 对应内容标记已发布：已发布。

热点卡片增加两个主要动作：

1. 创建新选题；
2. 关联已有选题。

创建或关联时自动保留：

- 原始标题和链接；
- 来源平台；
- 当时排名；
- 首次发现和最近出现时间；
- AI 分类、摘要和独立信源；
- 工作台中的稳定来源标识。

同一事件的多条热点允许共同关联一个选题，不强制生成重复选题。

### 7.4 选题侧来源呈现

选题详情增加精简的“来源”区域，展示：

- 源自哪些热点；
- 覆盖了哪些平台；
- 首次出现和持续时间；
- 是否存在重复或补充信源；
- 可返回原始内容的链接。

### 7.5 验收标准

- 使用一个入口可以找到各核心模块中的内容；
- 搜索结果可以直接继续对应任务，而不是只跳到模块首页；
- 关闭并重新打开工作台后，仍能恢复最近工作入口；
- 从热点创建选题不需要重复填写来源信息；
- 多个热点可以关联同一个选题；
- 热点状态会随真实选题、稿件和发布状态自动变化；
- 删除或解除关联后状态能够正确回退，不产生孤立记录。

## 八、迭代 4：发布数据闭环与复盘

### 8.1 作品匹配

数据导入后，系统按稳定标识、平台链接、平台作品 ID 和人工确认结果匹配作品。标题只能作为辅助信息，不能作为唯一依据。

匹配结果分为：

- 已确认；
- 建议匹配，待确认；
- 无法匹配；
- 疑似重复。

所有不确定匹配必须由用户确认后才能进入归因和复盘。

### 8.2 来源归因链

一条发布作品应可以反向追踪：

```text
发布作品 → 稿件 → 选题 → 热点 / 素材 / 洞察 / 书摘
```

基于这条链，可以回答：

- 哪些平台或热点类型最容易形成选题；
- 哪些热点只被收藏但长期没有行动；
- 哪些选题最终发布；
- 从发现热点到发布平均用了多久；
- 哪类来源最终产生了表现更好的作品。

这些结论只表达关联和观察，不把相关性包装成因果关系。

### 8.3 平台内比较

不同平台量级不同，作品表现优先在同一平台内部比较：

- 使用本平台的中位数或稳定基线；
- 不直接拿公众号阅读量与短视频播放量比较；
- 跨平台只比较标准化后的相对表现；
- 样本不足的平台只展示事实，不做排名。

### 8.4 样本门槛

第一版采用保守规则：

- 0 条作品：只展示导入指引；
- 1～4 条作品：只展示单篇事实和变化，不下趋势结论；
- 5 条及以上：可以提供描述性对比；
- 平台之间比较：每个平台都达到最低样本量后才启用；
- AI 复盘不能编造缺失数字，所有结论必须能指回具体作品。

门槛在积累真实使用数据后可以调整，但不得取消“样本不足”保护。

### 8.5 周复盘和月复盘

复盘输出分三层：

1. **事实**：发布量、平台分布、作品表现、转化耗时；
2. **观察**：表现突出或持续偏弱的内容及共同特征；
3. **行动**：继续追踪、改写、补充或停止的具体建议。

复盘必须：

- 指向具体作品和来源；
- 明确样本范围和统计时间；
- 将最终结论保存为 Markdown，进入 vault 的洞察目录；
- 支持把行动建议创建为新选题或关联已有选题；
- 不允许结论只停留在数据页面。

### 8.6 轻量转化漏斗

总览只增加一条轻量漏斗，不引入大型图表：

```text
本周关注 12 条 → 形成选题 4 个 → 成稿 2 篇 → 发布 1 篇
```

数字可以点击查看对应内容，避免只有统计没有行动入口。

### 8.7 验收标准

- 任意一条已发布作品可以追溯到稿件、选题和来源；
- 无法确认的作品不会参与归因；
- 重复导入只更新同一作品；
- 样本不足时明确提示，不生成趋势或优劣结论；
- 平台表现按本平台基线计算；
- 复盘中的每个结论都能打开对应作品；
- 复盘行动可以重新进入选题池；
- 保存后的复盘在 Obsidian 中可见、可搜索、可继续加工。

## 九、迭代 5：键盘、弹层与辅助文字

### 9.1 键盘与弹层

优先处理当前已经确认的问题：

1. 弹层打开后，键盘焦点进入弹层；
2. `Tab` 和 `Shift + Tab` 只能在弹层内部移动；
3. 背景内容在弹层打开时不可点击、不可被键盘访问；
4. `Esc` 可以安全关闭弹层；
5. 关闭后焦点回到打开弹层的原位置；
6. 书籍卡片等区域不再出现一个按钮内部套另一个按钮；
7. 自定义下拉框支持方向键、回车和退出；
8. 只有图标的按钮具备明确名称和悬停说明；
9. 危险动作仍需确认，不能因键盘操作被误触。

### 9.2 文字可读性

继续保持现有黑白视觉体系，不重新设计整套界面：

- 辅助正文和操作说明原则上不低于 13px；
- 极少数元数据可保留 12px，但必须满足对比度；
- 浅灰文字提高明暗差，避免在白底上接近不可读；
- 状态不能只依赖颜色，还应有文字或图标；
- 深色模式同步检查，不单独修一套颜色。

### 9.3 验收标准

- 仅使用键盘可以打开、操作并关闭选题阅读弹层；
- 弹层打开时，焦点不会进入背景中的删除等操作；
- 读屏顺序与视觉顺序一致；
- 所有图标按钮都有可理解名称；
- 主要文字和操作说明达到 WCAG AA 对比度；
- 桌面端关键页面实际截图确认视觉层级没有被放大字体破坏。

## 十、迭代 6：内部模块拆分

### 10.1 原则

这一步只降低维护成本，不改变用户入口、页面结构和业务行为。

优先拆分目前职责较多的模块：

- 书架与书籍操作；
- 数据导入、统计和复盘；
- 创作阶段与选题阅读；
- 阅读器与右侧批注台；
- 全局侧栏和快捷操作。

### 10.2 拆分方式

按真实业务职责拆分，而不是为了减少文件行数：

- 页面负责组合和状态边界；
- 展示组件只负责界面；
- 数据读取、转换和保存集中在独立服务；
- 搜索、来源关系、书籍处理等逻辑形成可单独测试的模块；
- 公共交互规则只保留一份，避免不同页面各自实现。

一次只拆一个模块，每次拆分前后都验证行为一致，不做全项目同时重构。

### 10.3 验收标准

- 导入、阅读、选题、排版和数据页面的用户流程不变；
- 原有数据格式无需迁移，或提供明确且可回退的迁移；
- 单个模块故障不拖垮其他页面；
- 公共逻辑不再散落在多个大型页面中；
- 拆分前后的桌面截图和关键流程一致；
- 自动检查及真实浏览器回归全部通过。

## 十一、每轮迭代的统一交付标准

每个迭代必须同时满足以下条件，才算完成：

1. 只修改本轮范围内的功能，不夹带无关重构；
2. 先保留现有数据，再执行任何格式变更；
3. 有效输入、无效输入和异常中断都有验证；
4. 自动检查通过；
5. 在真实浏览器中完成对应主流程；
6. 涉及连续操作时，至少验证两次连续执行；
7. 页面无新增浏览器错误；
8. 实际截图确认桌面端界面没有退化；
9. 更新总体方案或操作说明中受影响的部分；
10. 在 Git 中形成范围独立、可回退的提交，未经要求不推送。

## 十二、暂不纳入本轮的事项

- 删除或合并阅读器、文章提取、AI 助手、电子书转换、数据分析、排版等入口；
- 手机端、移动端和窄窗口专项适配；
- 多用户、账号系统或公网部署；
- 在真实数据不足时建设复杂图表；
- 用 AI 猜测缺失数据、因果关系或用户偏好；
- 新增热点数据源；
- 重做现有黑白视觉体系；
- 与本轮目标无关的全项目重构。

## 十三、推荐执行顺序

```text
用户发布并准备真实数据
        ├──────────────┐
        ↓              ↓
外部内容安全      数据恢复机制
        └──────┬───────┘
               ↓
统一检索 + 继续工作 + 热点来源链一期
               ↓
导入真实数据并确认作品匹配
               ↓
数据归因 + 周/月复盘 + 行动回流
               ↓
键盘、弹层和文字可读性收尾
               ↓
按模块逐步拆分大型页面
```

执行过程中，如真实数据暴露出新的字段或匹配问题，优先调整作品匹配和数据契约，不直接扩展分析功能。只有“数据能够正确关联到作品、作品能够追溯到选题和来源”之后，才进入复盘分析。

## 十四、最终完成定义

本轮计划全部完成时，工作台应能稳定回答五个问题：

1. 我最近在做什么，下一步从哪里继续？
2. 这条选题来自哪些热点、素材或阅读内容？
3. 它最终是否成稿并发布？
4. 发布后的真实表现如何，结论依据是哪几篇作品？
5. 这些结论将怎样进入下一轮选题和创作？

同时，即使出现错误升级、异常写入或设备故障，也能够明确恢复代码和数据，不以牺牲统一入口和现有使用习惯为代价。
