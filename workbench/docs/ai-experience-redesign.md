# AI 协作体验

> 当前实现说明。Stage 1–9 已完成；历史审计与迁移细节保留在 Git 历史中。
>
> 最后核对：2026-08-27。

## 一、产品边界

AI 是协作层，不是业务真源。

- Worker / D1 继续决定业务状态、发布、真实性校验和服务端硬闸。
- Assistant 可以回答、提出候选、生成报告、提出有副作用的动作，但不能静默修改正文或业务状态。
- 正文修改必须先形成 Candidate，再由用户采纳或弃用。
- 有副作用的 Action 必须明确确认；拒绝是正式状态。
- `@` 代表 Expert，`/` 代表 Skill。菜单只在用户输入对应字符后出现。
- 访谈是普通 Runtime Skill，不存在访谈页面、Tab、专属按钮、专属会话或专属结果类型。
- Project / Reading 不显示模型、权限、风格或 Pi Agent SDK 运行时信息；完整全局 AI 页面保留模型和权限设置。

## 二、能力模型

### 2.1 scope：语义上下文

`scope` 只说明 AI 当前站在哪个语义空间：

| scope | 上下文 | 会话 |
| --- | --- | --- |
| `global` | 不绑定某篇正文的全局工作 | 全局会话 |
| `project` | 当前内容项目、稿件、项目素材与报告 | 项目会话 |
| `reading` | 当前阅读对象 | 阅读会话 |

可编辑 vault 文档仍是 `reading`，不会因此获得项目阶段、项目素材或项目报告。

### 2.2 target：结果落点

`target` 描述对象类型、是否可编辑、当前选区和合法动作。

当前可产生 Candidate 的对象类型是：

- `draft`
- `vault-document`

只有 `target.editable === true` 时才允许写作 Candidate；有有效选区时才允许选区修订。只读 Reading 即使存在选区，也不会出现无法落地的修改动作。

### 2.3 surface：呈现方式

Assistant Core 的 `surface` 只有三种：

| surface | 用途 | 不影响的事项 |
| --- | --- | --- |
| `page` | 完整 AI 工作区 | 不增加能力 |
| `overlay` | Quick Assistant | 不减少能力 |
| `rail` | Project / Reading 侧栏 | 不根据宽度改变能力 |

编辑器内联菜单、Candidate 专注审阅和 Report 对照审阅是正文交互层，不是新的 Assistant Core surface。

核心不变式：

> Assistant 能做什么，由统一的 `scope + target policy` 决定；`surface` 不得增加或削弱能力。

实现真源是 `src/lib/assistant-policy.js`。调用方必须传语义 target，不得用 callback 是否存在或零散布尔值推测能力。

## 三、入口与召唤路由

页头右端的 AI 键和 `Ctrl/⌘+I` 共用 `assistant-summoner.js`：

- 项目页：打开或聚焦现有 Project Assistant。
- 阅读页或阅读覆盖层：打开或聚焦 Reading Assistant。
- 其他页面：打开 Quick Assistant。

快捷键在输入框内同样生效。

Quick Assistant 使用 `scope="global"`、`surface="overlay"`。它与 `#/assistant` 共用同一个 global conversation；关闭后保留 conversation 和未发送草稿。进入完整 AI 工作区时继续同一个 `conversationId`。

Quick Assistant 默认只携带页面或明确对象的引用：

- 可以携带页面类型、对象 ID、对象标题。
- 没有明确对象时显示当前位置，并说明“未附带页面内容”。
- 不自动发送正文、DOM、页面数字或其他页面数据。
- 正文只有在用户显式附带，或发送后由 AI 通过受控工具读取时进入上下文。
- 当前引用可以由用户移除。

Quick Assistant 是 non-modal：Esc 或点击外部可关闭，不给背景加 inert，也不做强制 focus trap。打开后立即聚焦 Composer；reduced-motion 下取消位移和缩放。
## 四、共享 Assistant Core

共享行为只实现一次：

- `AssistantPane`：conversation lifecycle、submit、stream、stop、retry、history、attachments、command menu 和公共错误状态。
- `AssistantComposer`：输入、附件、发送，以及仅在 global page 出现的模型与权限设置。
- `AssistantThread` / `AssistantMessage`：消息、loading、retry、message actions 和 AiResult 摘要。
- `AssistantHistory`：完整全局工作区历史（挂在页头标题下的浮层里，见九之四）。
- `ProjectAssistantHistory`：项目右栏的轻量最近会话。
- `CandidateCard`：正文候选审阅。
- `ActionCard`：有副作用动作的确认与拒绝。

页面容器只负责摆放位置、外部尺寸、当前 scope/target 和页面专属编排：

- `pages/Assistant.jsx`：完整全局页面。
- `QuickAssistant.jsx`：全局浮层。
- `ProjectAssistantRail.jsx`：项目上下文、报告和侧栏收起。
- `SideRail.jsx`：阅读区页签与 Reading Assistant。

Project Rail 直接接收统一 target，不再用 `selection / onInsert / onRevision` 兼容 props 重新拼能力。
## 五、各协作界面

### 5.1 完整全局 AI 页面

`scope="global"`、`surface="page"`。这是模型和权限的正式设置入口：

- Composer 仍以输入为第一视觉重点。
- 模型和权限在紧凑 footer 中持续显示当前值，点击后展开。
- 支持完整历史、重命名、置顶、归档、恢复和永久删除。
- 不绑定正文，因此不出现正文 Candidate 动作。

### 5.2 全局 AI 侧栏（原 Quick Assistant）

`scope="global"`、`surface="overlay"`。**它是 `.app__body` 里的第三列，不是浮在页面上的层**——
打开时正文让出宽度，两边都完整可见（飞书文档的做法）。

> ⚠️ **2026-08-28 推翻了「不挤压当前页面」和「Global Assistant Dock 属于否决结构」两条。**
> 浮层版实际用下来有三个问题：520px 的卡片压住的正好是用户想一边看一边问的那块内容；
> 它自带边框 + 圆角 + 大投影，压在本来就浮着的面板上像另一个应用贴上来；
> 而且浮层要自己管高度、定位和外部点击关闭，这些在一列布局里根本不存在。

- 宽度 `min(420px, 38vw)`；1100px 以下退回覆盖正文，但仍是贴边的一整条，不是圆角卡片。
- **点正文不关闭**——点正文正是它存在的意义。关闭只走 ×、Esc、页头那颗召唤键。
- 不做 focus trap、不给正文加 inert（`useDialog` 的 `modal: false`）：两边都要能操作。
- **不做宽度动画**：宽度变化会让 `main` 每帧重排，而正文里有长表格和图表，掉帧比没有滑入难受。
- **每次打开都是一段新对话，不继承 `#/assistant` 那一页的会话。**
  两处用法不同：侧栏是「手头这件事顺便问一句」，整页是「坐下来想一件事」。
  在别的页面顺手问的那句，不该在你打开 AI 助手页时已经躺在里面。
  要把侧栏这段带进整页，走「⤢ 在完整工作区继续」（它会把 conversationId 交过去）。
  实现真源是 `AssistantPane` 里的 `shouldResume`：**只有 `rail` 才自动续**
  （项目/阅读栏绑着这篇稿件或文档，切个页签回来就丢对话是另一种坏）。
- **不给入口卡。** 那三张是通用入口，而侧栏本来就是顺手问一句的地方，
  三张卡把一栏塞满，反而挡住「直接开口」这条主路径。
- **不放「历史对话」入口。** 这一栏是「现在这段对话」的地方；翻旧会话是另一件事，
  完整 AI 工作区那边有带搜索和时间分组的历史栏，比在 420px 里塞一个抽屉好用。
  代价是这排图标从五颗降到三颗，而省掉的那两颗一年点不了几次。
- 窗口动作（展开 / 关闭）和会话动作（存知识卡 / 新对话）之间一道细线分组——
  同样大小的图标连成一排时，读不出哪几颗是关这一栏的、哪几颗是管这段对话的。

### 5.3 Project Assistant

`scope="project"`、`surface="rail"`。**和全局侧栏、阅读侧栏同一种形态：贴边的一整列**——
只有一道 `border-left`，顶到上边、落到下边，不是浮在正文旁边的圆角卡片。

> ⚠️ **2026-08-28：撤掉了它自带的完整边框 + 圆角 + 18px 沟。**
> 那样同一个应用里会出现两种「AI 助手」：全局那个是贴边的外壳列，项目这个是贴上去的卡片，
> 用户切页时要重新认一次它在哪、长什么样。

**收起 = 整列消失**，没有那条竖排「协作」的 44px 窄条（竖排中文每字一行，
而且用一整列的位置只换来一颗按钮）。重开走**和其他页面完全一样的路**：
页头 AI 键 / `Ctrl+I`——召唤器在项目页本来就会展开并聚焦输入框。

右栏只保留：

1. “协作”、最近会话、新对话、收起。
2. 当前稿件与已使用素材的上下文入口。
3. 对话和 AiResult 摘要。
4. 输入、附件、发送。

空态建议靠近 Composer，点击只填入输入框，不自动发送。Project Composer 不显示模型、权限、风格、`@` 或 `/Skill` 常驻控件。

上下文面板按需显示当前稿件、素材和报告入口：

- 已核验是默认状态，不逐行重复。
- 只突出待核验。
- 最多直接呈现 10 条，内容滚动但不遮挡 Composer。
- 鼠标打开时不抢焦点；键盘打开时进入可用的焦点顺序。

项目会话历史是轻量 popover：保留当前会话、最近会话与新对话；新建不会删除旧会话。

### 5.4 Reading Assistant

`scope="reading"`、`surface="rail"`。空态使用阅读文档语境，不显示项目素材、报告、模型、权限、风格或运行时信息。

**空态下不画 pane 的那条 header。** 阅读页右栏本来就有一条页签（标记 / 衍生 / AI 助手 / 收起），
下面再压一条「当前全文 ………… ＋」是 88px 做全局侧栏 44px 就做完的事；
而且空态下那条里没有一个字是新信息——「当前全文」是恒定值，
「新对话」在一段还没开始的对话里点了等于没点。
有选区（「选中 N 字」是真变化）、有消息、有后台任务或可存知识卡时它才出现。

Reading rail 当前使用固定只读 target；可编辑 vault 文档的写作能力位于与 Project 共用的编辑器内联层。

### 5.5 编辑器内联 AI（2026-08-28 重做为三层，同日按 Notion 返工手感）

Project Draft 与可编辑 Reading 文档复用同一套内联层。三层各自回答一个问题：

| 层 | 什么时候 | 回答 |
| --- | --- | --- |
| **入口层** | 光标停在某一行 | 这儿能做什么 |
| **选区层** | 选中了一段字 | 对这段字能做什么 |
| **结果层** | AI 给了候选 | 改了什么，要不要 |

> ⚠️ **推翻了「内联 AI 只有 `Alt+Enter`」和「候选用 textarea 审阅」两条。**
> 前者的问题是**入口活在用户的记忆里**——界面上没有一个字提到它，功能在但没人会用。
> 后者的问题是**给了版本没给变化**：一段 800 字的改写里换了三处措辞，并排两坨字读不出来。

#### 入口层

- 光标所在行的左边有一颗 `+`（鼠标进编辑器才显形），点开块菜单。
- 这一行**是空行**时，行内多一句灰字：`按 space（空格）以启用 AI，或按 “/” 启用命令`。
  这句灰字是整个 AI 功能的说明书，**只在它有用的那一刻出现**；有字的行不挂，
  因为那时候空格和 `/` 都是普通字符。只读文档只显示后半句。
  灰字与正文同字号、在行框里垂直居中，只靠颜色退到背景里（理由见九之五）。
- **空格 = 问 AI**，就地展开输入条，**不插入空格**，Esc 之后什么痕迹都不留。
  判据在 `shouldOpenInlineAiOnSpace`：完全空的行 + 无选区 + 非 composition。
  空行上第一个键是空格时不可能处于 composition 中（要起组合得先有字母，有字母这行就不空了），
  但仍然显式判一次——这条判据将来会被复制到别处。
- **`/` = 块菜单**，斜杠照常插进正文（关掉菜单后留在纸上的就是一个普通斜杠，
  不会出现「按了个键什么都没有」）。判据是**反着写的**：默认开，只挡 ASCII 字母、
  数字、`/`、`:` 这四类前一个字符——正好覆盖 `https://`、`2026/08/28`、`and/or`，
  而行首、空白、中文字和中文标点后面一律开。
- 块菜单有两种过滤源：`/` 触发时用户**继续在正文里打字**（屏幕上只有一个插入点，
  方向键和 Enter 由菜单在捕获阶段接管，焦点不离开正文）；`+` 触发时菜单自带输入框。
  选中后 `/` 和过滤词一起被吃掉，否则「输入 `/标题` 选标题 1」会得到 `# /标题`。
- 菜单顶部是「建议」组（让 AI 写 / 续写这一段 / 想一想），下面是基本区块，
  底部一条筛选行显示正在筛什么和 `esc`。右边那一列**只放记号**，说明进 tooltip。
  只读文档不出现「建议」组：那一组每条都会改正文，列出来只是等着被拒绝。
- **空格唤起的那条 bar 只有一条输入框**，预设动作只住在 `/` 菜单里（理由见九之五）。
- `Alt+Enter` 保留为等价快捷键，不删老习惯。

#### 选区层

**同一段选中的字，一个面板。** 顶栏不再放排版按钮——上一版选中一段话想加粗要把视线
甩到屏幕顶端，想润色又要甩回选区旁边，同一个操作对象被拆到了两个面板。

面板四段竖排（Notion 的形状），顺序是**从快到慢**：

1. 块类型（正文 / 标题 1–3）——自己占一行。
2. 格式图标（B I S / 行内代码 / 链接 / 引用 / 列表）——纯本地，零等待。
3. 「技能」竖排列表（润色 / 纠错 / 缩写 / 扩写）——一次点击出结果。
4. 自由指令（`使用 AI 编辑`，右边写快捷键）——要打字。

「改写」不再是并排的第五颗技能，**它就是最底下那条输入框**：前四个是不用解释就能按的
快捷方式，而改写没有指令就没有意义，做成预设只会让人多点一次才看到输入框。

方向键在这四段之间**连续走**（`[data-inline-ai-action]` 覆盖块类型、格式和技能）。
面板打开时不抢焦点——选区还在，用户可能只是想接着调选区。

#### 实时预览

真源 `src/lib/editor-live-preview.js`。规则只有一条：**光标（或选区）碰到的那一行原样显示，
其余行隐掉记号**——不然你没法改那些记号。

- ⚠️ **文档一个字节都没变。** 隐藏是 `Decoration.replace`（把 `#`、`**` 换成零宽），
  图片是 widget。存回去仍是原字节 Markdown——`[[双链]]`、脚注、`> [!note]` 不会被重写。
  这是这个编辑器选 CodeMirror 而不是富文本内核的**全部理由**，实时预览不能把它换掉。
- 行内记号用正则而不是语法树：只隐**成对且同一行内**的，判不准的一律不隐——
  **宁可露出记号，也不能让文字缺一块**。
- ⚠️ `RangeSetBuilder` 要求按 from 递增喂，而装饰是按「先块级后行内」生成的，**必须自己先排序**。
- 图片取不到时退回显示原始那行 Markdown，不显示碎图图标——那个图标既不说明发生了什么，也没给下一步。

#### 插图片 / 视频 / GIF

`/` 菜单的「媒体」组，或者**直接粘贴、拖进来**（截图 `Ctrl+V` 是这类编辑器最常用的一条路）。

- 文件落进 vault 的 `99 - 个人工作台/07 - 附件/<年-月>/`（`DIRS.media`），正文里只留相对路径。
  选这里是因为这些是用户自己的素材，Obsidian 那边也该看得见、也该能自己整理。
- ⚠️ **代价要说清楚：只存本地的图，稿件发布到平台时取不到。** 发布链路要单独处理一次，当前还没有。
- ⚠️ **上传成功之前正文一个字都不写。** 失败时留下一个指向不存在文件的 `![](…)`
  比什么都没有更糟——它看着像插成功了。
- 视频走 `/api/vault/media-file`（带 Range），**不能并进 `/api/vault/image`**：
  那条的后缀白名单是「能被读走什么」的最后一道防线（第一道是 `safeJoin`），不能为省一条路由掺东西。

#### 结果层

**「改已有的字」和「产出新的字」是两件事，呈现方式也是两种。** 这是这一层唯一的判据：

| 触发 | 呈现 | 为什么 |
| --- | --- | --- |
| 预设技能（润色 / 纠错 / 缩写 / 扩写） | **就地 diff + 决策栏**（六之一） | 有原文可比，要判断的是「改得好不好」 |
| 空行输入条的自由指令 | **回答卡** | 没有原文可比 |
| `/` 建议组的续写这一段 / 想一想 | **回答卡** | 同上 |
| 选区面板底部的自由指令 | **回答卡**，原选区留浅灰底 | **无从判断它是不是一次改写** |

最后一条是这条规则真正的理由：选区上那句自由指令可能是「翻译成英文」，也可能是
「这段在讲什么」。**默认成改写就会用答案顶掉用户的原文**——用户只是想问一句，正文却被改了。
卡片里正文一个字不动，是替换还是插入由用户说了算。

回答卡（`AiAnswerCard`）是正文里的一个**块级 widget**，不是浮层——它要停留到用户做决定为止，
浮着会盖住下一段。**它就是一条回复**，所以只有三颗图标：重试 / 在下面插入 / 对话。

- **点别处 = 看完了**，卡片直接关掉，正文一个字不动。没有「丢弃」按钮——
  那是这张卡最常见的结局，不该占一颗键。
  ⚠️ 和决策栏的「点别处 = 采纳」**方向相反，这不是不一致**：那边用户按下润色时
  就已经表达了要改，默认结果是「接受」；这边用户只是问了一句，默认结果是「读完就算」。
  两个默认值都跟着「用户十次里做九次的那个选择」走。
- 「在下面插入」→ 走续写底纹（`cm-ai-draft`），插入后点别处即落定。
  **插在这一块下面**，不是插在光标那个字符位置上——生成出来的是一个新段落，
  塞进句子中间只会把原来那句劈成两半。
- 「对话」→ 把**用户自己的那句指令和选中的原文**送进右栏助手真的跑一遍。
  不在卡里伪造一段对话历史塞进会话记录——那段对话必须是真的发生过的。
- **没有「替换所选内容」。** 改写走预设技能那条路（有原文可比，就地出 diff）；
  自由指令那条路产出的是一条回复，要放进文章就是「插入」。
- ⚠️ **服务端的真实性 gate 在卡片上同样是硬闸。** 卡片是一条**新的**落地路径；
  不看 `grounding.gate` 就等于给 gate 开后门——候选那条路拦下来的东西，从卡片照样能写进正文。
  被拒时只留「重试 / 丢弃」，并原样显示服务端给的理由。
- ⚠️ **grounding 要先 `normalizeGrounding` 再进卡片。** 服务端回的是原始结构，
  `skipped[].nextStep`（「去核验」那颗按钮）是归一化补出来的；直接渲染会在读
  `nextStep.label` 时抛异常，React 把整棵子树卸掉——现象是「卡片一闪就没了」。
  候选那条路一直是对的（`createCandidate` 内部会归一化），只有这条新路漏过。

内容改动的呈现见六之一。

#### 三层共有

- 中文输入法 composition 期间一律不触发。
- 菜单根据真实矩形自动上下翻转，并限制在编辑器可视区域内。
- 滚动、resize、选区变化时重新定位。
- Esc 关闭并恢复光标或选区。
- 只读 Reading 不出现写作动作。
- ⚠️ **聚焦必须等位置算出来。** 面板在拿到 `position` 之前是 `visibility: hidden`，
  而浏览器不会把焦点给一个 `visibility: hidden` 的元素——`focus()` 静默失败，
  现象是「唤起了输入条但打字打进了正文」。`useInlineAiMenu` 的 autoFocus 因此挂在
  `position` 上，不是挂在挂载上。
## 六、统一 AiResult

统一结果类型只有四种：

| kind | 含义 |
| --- | --- |
| `answer` | 解释、建议、访谈追问等对话结果 |
| `candidate` | 可审阅的正文候选 |
| `report` | 结构化检查结果 |
| `action` | 需要确认的副作用动作 |

### 6.1 Candidate

Candidate 状态为：

`generating → ready / edited → adopted / discarded`

并允许进入：

- `stale`：正文版本已变化。
- `failed`：生成失败或服务端 Grounding gate 拒绝。

共同规则：

- 原文在采纳前不修改。
- 候选可采纳、弃用、重跑，并显示第 N 版和变更摘要。
- **默认结果是「接受」：点正文别处即采纳。**
  上一版必须点「采纳」才落地，于是每一次小改写都要额外一次点击，而那次点击几乎总是「是」——
  十次里九次用户读完 diff 就想接着写下一句。现在移开注意力即落定，
  `✓` 只是显式确认，**`弃用` 才是那个需要主动做的动作**。
  实现是决策栏自己在捕获阶段听 `pointerdown`（`RevisionDecisionBar` 的 `adoptOnClickAway`）。
- ⚠️ **四种情况绝不被「点别处」带走**，这是硬闸不是手感：
  `generating`（还没有东西）、`stale`（正文已变，落地会覆盖新内容）、
  `failed`（服务端真实性 gate 拒绝过），以及**专注审阅**（章节 / 全文——
  那一屏整个就是候选，点进去读和滚动都是审阅动作本身；而全文替换必须明确确认，
  「移开注意力」在那儿不构成同意）。这四种情况下点别处只关掉注意力，候选留在原地等决定。
- `Ctrl/⌘+Enter` 采纳，`Ctrl/⌘+Backspace` 弃用。**快捷键挂在编辑器的 keymap 上**，
  不只挂在决策栏上——候选生成完之后焦点还在正文里（人正在读那段 diff），
  上一版只在候选卡的文本框里生效，文案写着能按、实际按下去没反应。
- 采纳后走编辑器已有的合法撤销路径。
- 句子、选区、段落在**正文原位置画 diff**：删掉的字带删除线，新增的字带底色，
  **没动的字一个装饰都不加**。读下去就是改完之后的文章。
- 大章节或全文进入专注审阅，折叠协作右栏；结束后恢复原会话和滚动位置。
  专注审阅是**单栏 diff**，不再上面压一块原文——那等于同一段读两遍，
  而这一屏本来就是为了少读一遍才存在的。
- whole-document candidate 必须明确说明会替换全文并由用户确认；没有审阅能力时不得直接替换。

⚠️ **inline 形态不提供可编辑 textarea。** 上一版给候选配了一个文本框，理由是「万一想手改」。
实际用下来那个框把「读改动」变成了「读一坨新文字」；而手改的需求，采纳之后在正文里改就是了，
**正文本来就是编辑器**。要退回去的话，退路是在决策栏上加一颗「改一改」，不是把框请回来当默认。

决策栏一条只回答三个问题：**改了多大**（`+N / −N`）、**凭什么**（证据回执）、
**要不要**（重试 / 弃用 / 采纳）。「调整要求重新生成」收进「重试」——十次审阅九次是直接决定，
常驻一个输入框等于每次都要跳过它才看得到那两颗决定键。

样式上是**一张普通白卡片**，不是薄荷绿：正文里被改动的那几行已经是绿的
（`.cm-diff-ins` / 续写底纹），栏也铺同一个绿的话，一屏上两块同色的面读不出
「哪块是文章、哪块是控件」。弃用和采纳收成**圆形图标键**（Notion 的 ↺ / ✓），
名字进 `aria-label` 和 tooltip 不进视觉——默认结果已经是采纳，这两颗只是「改主意」和「确认」。

⚠️ **不挂恒定脚注。** 上一版常驻一行「内容由 AI 生成 · 待审阅 · 采纳前不会写入正文」，
三句话都是恒定值而且都被别的东西说过了：AI 图标 + 动作名说了是 AI 生成的，
正文里的 diff 说了还没写进去，状态说了在等审阅。只有真出事时（候选历史没存上）才出现一行。

diff 的实现真源是 `src/lib/text-diff.js`：

- CJK 按单字、拉丁按词、标点和空白各自成 token（改一个「的」就只有那个「的」变色）。
- 先剥公共前后缀再做 LCS，**并且有成本闸**（`DIFF_BUDGET = 4_000_000`，
  实测 2000×2000 = 33ms/15MB，4000×4000 = 127ms/61MB）。超了退化成整段替换呈现，
  界面上明说「整段替换」，不装作逐字比过。全文重写必然走这条，而全文重写本来也没有可对齐的东西。
- ⚠️ **新增只能是零宽 widget**：采纳前正文一个字节都不能改，`ins` 在文档里没有对应区间。
- ⚠️ **流式生成期间不算 diff**，保持整段划掉。每几十毫秒重排一次的逐字上色读起来是花屏。

### 6.2 Grounding

Grounding 包含：

- `used`
- `skipped + reason`
- `unverified`
- `gate`
- `gateDetail`

Grounding 存在时必须可见；`skipped` 和 `unverified` 默认展开。每条 skipped 都提供下一步，例如“去核验”或“仍然使用”。

`gate: "rejected"` 时 Candidate 必须进入 `failed`，不得进入 `ready`。前端只展示服务端结论，不重新判断真实性。

### 6.3 Action

Action 状态为：

- `proposed`
- `applied`
- `rejected`
- `superseded`

确认和拒绝同样明确；拒绝不是“用户没有点击确认”。

### 6.4 Report

报告用户可见严重度是：

- 高风险
- 建议修改
- 可选优化

正面结果进入“值得保留”，不得把 `pass` 映射成“可选优化”。“需要处理”先显示；“值得保留”排在后面并默认折叠。

报告审阅时折叠协作右栏，只显示正文与报告对照。finding 与正文位置双向定位并高亮当前项。动作随 finding 类型变化；实际生成修改稿的动作叫“生成候选”，不会直接改正文。

AI 报告只作为参考。用户界面不出现“blocking”或“阻塞发布”；服务端真实性硬闸和确定性业务硬闸不受影响。
## 七、能力矩阵

| 场景 | scope | surface | target | 能力 |
| --- | --- | --- | --- | --- |
| 完整 AI 工作区 | global | page | none | answer、action、历史、模型与权限设置 |
| Quick Assistant | global | overlay | none | 与 global 同一会话；轻量呈现 |
| 项目协作右栏 | project | rail | editable draft | answer、candidate、report、action、项目上下文与历史 |
| 阅读协作右栏 | reading | rail | read-only vault-document | answer、阅读上下文 |
| Project 编辑器 | project | editor inline | editable draft | 选区改写、光标续写、按要求写 |
| Reading 编辑模式 | reading | editor inline | editable vault-document | 与 Project 相同的内联写作能力 |
| Reading 只读模式 | reading | editor inline | read-only vault-document | 不显示写作动作 |

同一个 scope 在不同 surface 上能力不变；同一个 target 的可编辑性变化会改变 Candidate 能力。
## 八、交互与无障碍

- `Ctrl/⌘+I`：统一召唤器；输入框内也生效。
- `Alt+Enter`：打开编辑器光标级 AI。
- `@`：在 Composer 输入后打开 Expert 菜单。
- `/`：在 Composer 输入后打开 Skill 菜单。
- `Ctrl/⌘+Enter`：采纳 Candidate。
- `Ctrl/⌘+Backspace`：弃用 Candidate。
- Esc：关闭当前浮层或内联菜单并恢复原焦点；不会丢 conversation、draft、光标或选区。
- 命令菜单和内联菜单支持方向键与 Enter。
- composition 期间不触发快捷动作。
- Quick Assistant 不做 focus trap；需要强制决策的确认弹层继续使用项目统一 dialog 契约。
- 动效只解释空间关系，约 160–200ms ease-out；reduced-motion 下取消位移和缩放，不使用 spring、bounce、stagger 或 glow。
## 九、正文审阅与协作右栏的关系

正文始终是项目工作区第一视觉主体。

- 普通对话、Context 和轻量历史留在右栏。
- 句子、选区和段落 Candidate 在正文原位置审阅。
- 大章节与全文 Candidate 进入正文专注审阅，并临时折叠右栏。
- Report 进入正文 + 报告双栏审阅，并临时折叠右栏。
- 退出 Candidate 或 Report 审阅后恢复原会话、对话滚动位置和正文位置。
- Report 首屏先呈现“需要处理”；“值得保留”随后且默认折叠。
- finding 与正文双向定位，当前项在两侧保持一致高亮。

右栏不是 mini ChatGPT，也不是状态 Dashboard。阶段、字数、素材数、报告数不重复堆放；只显示 AI 当前理解任务所需的上下文。

## 九之二、三个 surface 的共享版面（2026-08-27）

完整页、Quick 浮层、协作右栏用**同一套骨架**：一条头 / 消息流 / 输入器。
密度差别只由四个变量表达，真源在 `src/components/project-assistant.css` 顶部：

| 变量 | 管什么 |
| --- | --- |
| `--asst-measure` | 对话列宽。消息、空态、输入器、报错、Action 卡一律吃它 |
| `--asst-gutter` | 左右沟。保证消息和输入器左右边对齐 |
| `--asst-turn-gap` | 轮次间距。分组靠它 |
| `--asst-head-h` | 头部高度 |

下面每条都是**做过、看过、改过**的判断，不要凭「更整齐」改回去：

- **头只有一条。** 完整页的 58px 工具条、项目右栏的 39px 上下文行、Quick 的标题条 +
  上下文条，都是「同一档灰细字并列两三条」——占了高度却读不出主次。
  上下文并进头部当面包屑或芯片。
  **Quick 浮层没有自己的 header**：身份和上下文芯片通过 `headerLead` 交给 pane 那一条渲染。
  中途试过「浮层留一条 header、pane 那条退成右上角一排无边框工具」——更糟：
  那排图标悬在一片空白上，既没有边界也没有底色，看着像忘了做完。
- **浮层高度跟着内容走**（`height: auto` + `max-height`）。写死 680px 的话，
  空态只有六百像素内容，底下永远留着一截空白，看着像加载没完成。
- **一条头里不做两端分居。** 同一类动作（管理这段对话）排成一组，
  不要左端一颗、右端一颗、中间一千像素空。右端只留「这段对话产生了什么」。
- **模型选择器每个输入框都有**（完整页、全局侧栏、项目栏、阅读栏）。
  在哪儿写字，就在哪儿决定用哪个模型发出去，不该为了换模型先跳去完整工作区。
  ⚠️ 这推翻了原「Project / Reading 不显示模型」那条——**权限**才是留在完整页的那个
  （会话级、带后果、设一次管很久）。
- **左：附件 + 权限。右：模型 + 发送。** 权限菜单必须挂在**权限按钮自己的定位父级**上：
  挂在整个输入器上时 `bottom: 100%` 贴的是输入器顶边，而按钮在左下角，中间隔着整条输入框，
  看着就是菜单和按钮分了家。
  曾经把模型也挪到左边（理由是「两个低频开关不该分居两端」），看着整齐，用着不对——
  **权限是会话级**的（这一轮 AI 能碰什么，设一次管很久），**模型是发送级**的
  （「这一条用哪个发出去」，是发送动作的一部分，按发送前的最后一眼往往在确认它）。
  放左端就要在按发送前把视线甩到对面再甩回来。Codex 桌面端也是这个分法。
  模型菜单跟着触发器右对齐。
- **发送键三态用颜色说，不用 `opacity` 说。** 空 = `--border-strong` 浅底（**两个主题都要能看见**，
  `--surface-2` 和 `--border` 在其中一个主题下都会消失），有内容 = 实心黑，生成中 = 实心方块停止键。
  `×` 在这一屏是「关闭」，不能当停止用。
- **只有完整工作区页把输入器提到中间；侧栏一律贴底。**
  侧栏是「一边看正文一边问」的地方，输入器的位置必须像正文里其它常驻控件一样稳定；
  窄栏里居中也省不下多少距离，却让「第一条消息发出去」时输入器整个往下跳一次。
  项目/阅读栏的入口卡因此排在**贴底输入器的上方**（跟着空态问候沉到消息区底部）。
- **一屏只能有一个 AI 侧栏。** 全局侧栏开着时切到项目页或阅读页，那两页自带协作右栏，
  会并排出现两个「AI 助手」，各自一段对话、各自一个输入框。
  判据不另写：`assistantSummonDestination` 已经决定了「这一页的 AI 归谁管」，
  不归 `quick` 管的页面就把全局侧栏收起来。
- **侧栏的消息区不铺 `--sunken`。** 那是整页工作区的底色；侧栏的头部和输入器都是白，
  中间夹一段灰会在栏里留下一道不对应任何边界的横向接缝，读起来就是「这块颜色不对」。
  三个侧栏一起改，否则它们之间又有色差。
- **完整页空态：输入器居中，入口卡在它下面；发出第一条后输入器回到页底。**
  顺序是 问候 → **输入器** → 入口卡。这一屏用户要做的第一件事是打字，
  输入器必须落在视线中心；入口卡是「不知道说什么时的备选」，优先级低于直接开口，所以在下面。
  （更早一版是「问候 + 入口卡在上、输入器钉底」，中间空两百多像素，首屏被撕成两块。）
  实现上：`.assistant-pane__dialog[data-empty]` 用**首尾 auto 外边距**把中间那一组顶到剩余空间中央——
  ⚠️ 不要用 `justify-content: center`，那会把**头部**也一起挪到中间。
- **`.assistant-pane__dialog` 用 flex，不用固定行数的 grid。**
  子元素数量会变（项目右栏多一个上下文锚点，空态多一排入口卡），
  固定行数就得为每种组合各写一份，而写漏一份**不报错**——只是某一行悄悄分到 `1fr`。
  同理，外层 `.project-assistant` 必须是单行 `1fr`：它那个 `auto minmax(0,1fr)`
  是页签时代的遗留，页签撤掉后 pane 落进 `auto` 行，空态内容一少整栏就塌半截。
- **输入器和入口卡共用同一个宽度表达式**（`min(--asst-measure, 100% - gutter*2)`）。
  写成两套的话差几像素没人说得出哪里不对，但一眼就是「没对齐」。
- **消息之间不画分隔线。** 横线把「谁说的」让位给了「第几条」。分组交给间距和身份行。
- **身份行先说是谁。** 「AI 助手」在前，模型和耗时退到行尾灰字，且只在完整全局页出现。
- **同宽的容器长同一个样。** 阅读右栏和项目右栏同宽，空态、间距、输入器高度必须一致；
  上一版两边各写一份 padding，于是同一套组件在同宽容器里长成了两个样。
- **AI 给的候选（markdown 引用块）用蓝，不用灰底。** 蓝在这一屏只有系统标注在用，
  一眼分得出「它给的」和「它说的」；灰底和白面板只差一档，一屏几条会糊成一片。
- **复制必须有回执。** 就地换图标和文案（`--ok`），不弹 toast——视线此刻就在那颗按钮上。
- **历史列表一条一行。** 预览和标题都来自首条消息，写两遍等于行高翻倍、信息量不变；
  第二行只留给真信息（还在后台跑）。按时间分段（真源 `src/lib/conversation-groups.js`），
  时间戳格式跟着段走：今天/昨天显示时分，其他段显示日期。
- **`>` 子选择器和「包一层」是这套 CSS 最容易踩的组合。**
  这一轮同一个坑连踩三次：模型选项包进 `.assistant-model-group`、权限按钮包进
  `.assistant-permission-picker`、窗口动作包进 `.assistant-context-window`——
  每一次都让一批 `A > B` 规则**静默失效**：行叠在一起、圆 pill 变直角方块、
  图标退回 tabler 默认的 24px 和默认线宽。**CSS 不会为此报任何错**，
  只有截图或布局断言看得出来。

- **模型菜单按厂商分组，同一家连着排，并用各家标志的单色简化形。**
  换模型时用户找的几乎总是「同一家的另一档」，穿插排列等于每次把整列读一遍；
  而用通用图标凑品牌（字母 A 代表 Claude、一条鱼代表 DeepSeek）等于图标那一列白占位置。
  组名已经写了厂商，选项里就不再重复 provider，一行只放模型名 + 当前项的一枚勾。
  真源：`src/lib/model-brands.js`（谁是哪家、分组顺序）+ `icons.jsx` 的 `IconModel*`（怎么画）。
  **能拿到官方 path 就别自己照着画。** 手工近似过两版：第一版腰太细，缩到 15px 是一根发丝；
  第二版加粗后能看了，但射线数量和长短分布仍然是猜的——**近似形在小尺寸下和别家的通用图标
  区分不开**，而图标那一列存在的全部意义就是「不用读字也知道是谁」。
  自己画时**唯一要盯的数是笔画在 15px 下的实际宽度**：Anthropic 那枚星芒第一版
  腰宽只有 0.8/24，缩到 15px 就是一根发丝，整枚糊成一团灰。这个尺寸下认得出比数得对重要。
  ⚠️ 分组后选项不再是菜单的直接子节点，`.assistant-command-menu > button` 那批规则会**静默失效**，
  两个层级都要写——漏了不报错，只是行叠在一起。
- **历史栏顶上不写「历史对话」，也不放第二颗「新对话」。**
  「新对话」在页头已经有一颗，同一个动作两个入口只会让人先想它俩是不是一回事
  （上一版两颗的 aria-label 甚至一个叫「新对话」一个叫「新建对话」）。
  省下的那一行给**搜索**——会话攒到几十条后靠翻标题找不回来。
- **窗口动作（展开 / 关闭）和会话动作之间一道细线分组**——同样大小的图标连成一排时，
  读不出哪两颗是关这一栏的、哪几颗是管这段对话的。

### 九之四、标题即入口（2026-08-29）

⚠️ **完整页那条 248px 的常驻历史列撤了，别加回来。**

照 [ln-dev7/circle](https://github.com/ln-dev7/circle) 的 agent 页

页头：  ✦ AI助手  /  当前对话标题 ⌄            ＋

  没有读成「临时盖上来的一层」，读成了「这块渲染坏了」。

  ⚠️ **`outsideIgnore` 要排掉的是「开它的那颗按钮」，不是某个固定的类名。**

- ⚠️ **标题不套在 `.assistant-context-actions` 里。** 那个类上挂着一条

### 九之十一、抽屉通顶、三颗页头图标等大、发送键（2026-08-30）

⚠️ **抽屉通顶会把开它的那颗 `≡` 盖住，所以抽屉自己在原位补一颗。** 两颗在屏幕上是

没有这一颗的话，开关在开着的时候消失了，只剩点遮罩或 Esc。

### 九之十二、空态收权重、抽屉换手、跳到底部（2026-08-30 第二轮）

**空态那一屏改了三处，都是同一件事：把权重让给「打字」。**

1. **注脚删掉。** 原文是「直接开始对话，或从下面挑一个更明确的入口」——它把屏幕上
   **已经看得见**的两件事（一个光标在闪的输入框、三张写着字的卡）又说了一遍。
   ⚠️ 阅读和项目那两档的注脚**留着**：它们说的是看不见的事（AI 会读到什么、
   它不会动你的正文）。**说明只在有东西要说明时才写**，不是每个空态都配一句。
2. **入口卡比输入框窄一档、轻一档**（92% 宽、去掉 `min-height`、字降一档）。
   上一版和输入框等宽等重，屏幕上是两块一样分量的东西上下叠着，而它们的地位差得远：
   输入框是这一屏要你做的事，三张卡只是「你也可以从这儿起头」。
   **等宽等重就是把可选项画成了必答题。**
3. **整组偏上，不再正中。** 两个 `auto` 外边距把剩余空间均分，于是这一组严格落在正中——
   而正中偏低：视线进这一屏是从上往下的，问候语出现在半屏以下时，
   上面那一大片白读起来是「还没加载完」。做法是给底下那一头加一段 `clamp(0px, 14vh, 140px)`
   的 padding，两个 auto 在**剩下的**空间里均分，整组因此上移约它的一半。

**历史抽屉换了三处：**

- **收起钮从左上角挪到右上角。** 上一版压在页头那颗 `≡` 的正上方（「屏幕上就是同一颗按钮」）。
  想法成立，但抽屉推开之后视线是从左边那一列标题**往右**走的，收起它的动作该在那条路的终点。
- **进场从 0.18s 放慢到 0.3s**（遮罩 0.26s）。140–180ms 在屏幕上是「啪」地换了一帧，
  用户说的「直接弹出来」就是这个。这一下要解释的是「正文被盖住了、这是临时的一层」，
  **说明性的动效需要被看见的时间**；而它不是高频操作，慢一点不拖手。
- **会话时间从右端挪到标题下一行。** ⚠️ 右端那一版有个说不通的地方：`⋯` 也在右端，
  所以**指上去的时候时间就消失了**（当时专门写了 `opacity: 0` 给它让位）——
  一条信息只在你不看它的时候存在。代价是每条从 34px 长到 50px，一屏少几条。

**发送键：34×34 的圆角方块（`--r-md`）、20px 图标、空态字色 `--text-2`。**

⚠️ **不是正圆。** 这一行左边全是 pill 和方角（＋、权限、模型），中间冒一颗正圆
读着像个头像或状态点；10px 圆角和输入器那圈 20px 是同一族。

⚠️ **几何要写到和容器规则同样长的路径上：**
`.assistant-composer > footer > div > button.assistant-send`。
`.assistant-composer > footer > div > button` 是 (0,1,3)，而 `.assistant-send` 只有
(0,1,0)——类数相同就比元素数，短的那条**全线落败**，一次丢掉四条：
`height: 26px`、`padding: 0 10px`、`border-radius: 999px`、`display: inline-flex`。
屏幕上是**一颗 34×26 的扁椭圆，回车符还偏右 4px**（`display` 被抢走之后
`place-items: center` 跟着失效，图标只能靠着左内边距排）。

⚠️ **而源码里 `height: 34px` / `padding: 0` 写得明明白白，`getMatchedStylesForNode`
也报 34px——只有 `getComputedStyle` 会说实话。** 排查这类问题别看 CSS 文件，量渲染结果。

这是「容器为常规成员定的规则，默默套到特例成员身上」的**第六次**
（前五次见「九之十一」）。两个惯犯是 `.assistant-composer > footer > div > button`
和 `.assistant-context-actions button`。smoke 里现在钉着发送键的长宽比和图标居中。

**新增「跳到底部」**：一颗浮在输入框正上方的圆钮。

- ⚠️ **只在离底 >120px 时出现。** 常驻的话它压着这一屏最贵的一块地方当噪音；
  阈值不能是「滚动过没有」——流式输出时 `scrollTop` 每几十毫秒变一次而人并没有动，
  按「滚动过」算它会在生成过程中不停闪。120px 约一行半，差这么点还弹按钮
  只会让人以为自己漏看了什么。
- ⚠️ **外层 `height: 0`**，按钮绝对定位挂上去。不然它的出现和消失会把输入框顶动一下——
  正在打字时输入框自己往下跳，是最惹人烦的那类抖动。
- ⚠️ **边框和投影都要比常规重一档**（`--border-strong` + `--shadow`）。
  它是白的、压在白底正文上，用常规那一档在屏幕上只剩一个孤零零的箭头穿过一行字。
  它是这一屏唯一**盖在内容上**的控件，得自己把自己和背景分开。
- ⚠️ **`scrollThreadToEnd` 加了参数之后不能再直接当回调传。**
  `requestAnimationFrame(scrollThreadToEnd)` 会把时间戳塞进 `behavior`，
  浏览器在流式输出的每一帧抛 `'13760' is not a valid enum value of type ScrollBehavior`。

### 九之三、侧栏收敛与回复排版（2026-08-28）

- **flex 消息流里的块必须显式给宽。** 侧栏的 `.assistant-thread` 是 flex 列（为了让空态
  那一组沉到底贴住输入器），而 **flex 项目一旦带 `margin-inline: auto` 就不再被拉伸**——
  它缩成内容宽再居中。于是气泡、等待条、报错块整排跑到栏中央，靠右的自己那条也不再贴右边。
  `.assistant-turn` / `.assistant-working` / `.assistant-error` 都补上 `width: 100%`：
  完整页仍靠 `max-width` + auto 外边距居中，侧栏铺满。
  ⚠️ 这是「换了容器的 display，选择器和盒模型假设静默失效」的第四次——前三次是 `>` 直接子选择器。
- **侧栏没有历史入口。** 项目栏和全局侧栏都不再有那颗时钟。这一栏是「现在这段对话」的地方；
  翻旧会话是另一件事，完整 AI 工作区那边有带搜索和时间分组的历史栏。
  代价写在这儿：**项目 scope 的旧会话目前没有别的入口**（全局历史只列 global scope）。
- **「项目检查」从上下文面板搬到输入框的 `@`。** 面板回答的是「这一轮 AI 读到什么」，
  检查是「去做一件新的事」——两件事塞进同一个抽屉，结果是每次想确认上下文都要先跳过
  三颗一年点不了几次的执行按钮。现在 `@审稿顾问` / `@素材顾问` / `@事实核查` 直接起结构化检查，
  和其他专家同一个入口；菜单里用 hint 写明「跑一次并出报告」，因为同一个菜单现在有两种结果。
  进度和报告入口收成 header 上一颗**只在有话说时出现**的状态芯片，看过即消失。
- **每一个点开的浮层都要能点空白收起。** 记不住「哪个能点外面关」的结果是每次都先试一下。
  判据统一写成「点的地方在不在这个锚点里」——触发器自己也在锚点里，必须排除，
  否则 pointerdown 先关、click 又开，看着就是「点它关不掉」。
  完整页的历史栏是**推开布局的一列**不是浮层，不适用这条。
- **`fixEmphasis` 曾经吃掉列表记号。** `*   **写作中：9 个**` 里第一个 `*` 会和 `**` 的前一半
  配成对，匹配到 `*   *`（中间全是空格）→ 整段被换成那几个空格，记号连同一个星号一起消失。
  结果是模型的结构化回复整块退回成带星号的纯文本。补上 CommonMark 本来就有的
  「开标记后面不能跟空白」，并跳过代码围栏。规则在 `src/lib/markdown.js` 和
  `server/lib/books.mjs` 两处，改一处要改两处。
- **回复正文用 `--fs-md`，不跟界面正文同档。** 这是全工作台唯一一处要连着读几百字的地方；
  界面文字是拿来扫的。只抬这一块，自己那条气泡不动（你刚打的字，不需要再读一遍）。
  流式阶段的 `__stream` 必须同字号同行高，否则每条回复收尾时整块字跳一下。

### 九之四、编辑器内联层（2026-08-28）

做过、看过、改过的判断，不要凭「更整齐」改回去：

- **`visibility: hidden` 的元素接不住 `focus()`。** 内联面板在算出位置前是隐藏的，
  autoFocus 挂在挂载上就会静默失败——现象是「唤起了输入条但打字打进了正文」。
  挂在 `position` 上。这是这一轮唯一一个**功能正确、测试却红**了半天的坑。
- **`/` 模式下方向键不能把焦点搬进菜单。** 那时候用户还在正文里打字（过滤词就是正文的一部分），
  抢焦点等于打断输入。块菜单在**捕获阶段**自己接管 ArrowUp/Down/Enter，
  否则 CodeMirror 先拿到 Enter，按下去是换行而不是「选中这一条」。
  `useInlineAiMenu` 为此多了一个 `arrowFocus` 开关。
- **行内 widget 会污染「读正文」的测试助手。** `.cm-line` 的 textContent 现在包含
  diff 的新增文字和光标行的灰字提示，两者都不属于文档。
  `tests/writing-assist.mjs` 的 `editorValue` 必须先把它们摘掉，
  否则「候选生成前后正文没变」会在功能完全正确时失败。
- **给 `+` 让位用 `.cm-content` 的 `padding-left`，不用 margin 挪正文。**
  margin 会把选区高亮和 `.cm-flash` 的底色一起挪出去，看着像整段错位了 2px。
- **`+` 平时不显形，鼠标进编辑器才出现。** 每行左边一直挂着一颗 `+` 会把正文的左边界搅乱；
  键盘用户看空行那句灰字就够了。
- **块菜单的高亮跟着同一个 `active` 下标走，不用 `:hover`。**
  两套并存的话，方向键走到第三条时鼠标底下那条也亮着，读不出选的是哪条。
- **续写底纹点走就算落定，没有确认键。** 插入这个动作本身已经是一次确认；
  上一版还要再点一颗 ✓，等于同一件事收两次。光标离开底纹区间时自动 `confirmAiDraft`。
- **`aria-label` 别无脑拼后缀。** `${label}候选` 在 label 已经是「AI 助手候选」时
  会读成「AI 助手候选候选」。
- **顶栏瘦身后回头搜了 `.md-editor__bar` 的 `>` 选择器**（`[data-readonly]` 那条）——
  按九之二的教训，凡是改了结构就要搜一遍，CSS 不会为此报任何错。

### 九之五、内联层的手感返工（2026-08-28 第二轮）

第一轮把机制做出来了，但**手感全是我们自己的老习惯**。对着 Notion 的实际界面逐条返工：

- **光标高度跟着行高走，不是跟着字高走。** `drawSelection()` 画的 `.cm-cursor` 高度等于
  整个行框；1.9 行高下它比字高出一大截，看着就是「光标很大」，而且和这个应用里其它
  所有输入框都不一样。**去掉 `drawSelection()`，用浏览器原生 caret 和原生选区**，
  选区颜色交给 `::selection`。行高同时从 1.9 降到 1.65——这是 Markdown **源码**，
  段落之间本来就隔着一个空行，1.9 叠上那个空行是双倍行距。段落透气改用
  `.cm-line` 的上下 padding（padding 不抬高光标，行高会）。
- **空行灰字要在行框里垂直居中。** `top: 0` 会让它比光标和正文都高出几像素，
  贴在上一段屁股后面——现象就是用户说的「行距很紧」。
- **同一句灰字，缩小字号不会让它变得不显眼，只会让它变成另一种字。** 用 `font-size: inherit`
  跟正文同号，只靠颜色（`color-mix` 到 58%）退到背景里。
- ⚠️ **`inset: 0` 会把灰字压成零宽。** 父元素 `.cm-line-affordance` 自己是 `right: auto`
  的零宽盒（两个孩子都脱离文档流），`inset: 0` 继承过来就是 0 宽——文字还在 DOM 里，
  但 Playwright 量出来是不可见的。只钉 `top/bottom/left`。
- **行内 AI 输入条要铺满正文列、落在这一行正下方，而不是跟着光标漂的 max-content 卡片。**
  漂着的那版横向位置每次都不一样，而它下面那行灰字还留在原地——屏幕上同时有「一个浮着的框」
  和「一行说按空格的提示」，看着是两件事。为此给 `placeInlineAiMenu` 加了 `stretch`，
  并在菜单打开时用 `.md-editor[data-inline-open]` 把灰字收起来。
- **那条 bar 就只是一条 bar。** 我们曾在它下面挂一排「续写这一段 / 想一想」，
  把「直接说要写什么」这条主路径挤成了三选一，还让它看着像个带工具栏的小面板。
  预设动作**只住在 `/` 菜单的「建议」组**里。
- **选区面板按 Notion 的竖排来：块类型一行 → 格式图标一行 → 「技能」竖排列表 → 底部指令行。**
  横排胶囊把技能读成「工具栏上的四颗按钮」；块类型和图标挤在同一行时，那颗下拉宽度不定，
  后面的图标每次换行的位置都不一样。底部指令行不放实心发送键——那颗黑块是这个白面板里
  最重的东西，而它只是三条路径中的一条；没输入时那儿写快捷键。
- ⚠️ **在行首插入记号后必须显式设置光标。** CodeMirror 默认把光标留在插入点**之前**，
  于是选完「标题 2」屏幕上是 `|## `，接着打的字跑到 `#` 前面，整行不再是标题。
  `setHeading` 和 `prefixLines` 都要在「光标在空行」时显式 `selection: { anchor: … }`。
  验这条要**真的打一个字**看落在哪：行里挂着 `+` widget，`anchorOffset` 数的是渲染节点
  里的位置，不是文档里的位置。
- **`/` 的触发判据是反着写的：默认开，只挡会误伤的前一个字符**（ASCII 字母、数字、`/`、`:`）。
  上一版「只在行首或空白后开」太紧——中文正文一句话以「。」结尾、紧接着敲 `/` 是最常见的用法，
  而那时候菜单不出来，看着就是这个功能坏了。
- **块菜单右边那一列只放记号**（`#`、`-`、`1.`）。给「建议」组也配上说明文字之后，
  三行说明并排排在标签右边，眼睛读的是说明，反而找不到自己要的那一条；说明进 tooltip。
- ⚠️ **`imeComposingRef` 这种长期布尔值会卡住。** 组合被点击、失焦或切走输入法打断时
  `compositionend` 不一定发得出来，那个值就永远是 true——**之后空格和 `/` 全部失效**，
  现象是「斜杠打进了正文但菜单不出来」，怎么试都不好，而且测试里复现不出来（测试不起组合）。
  空格和 `/` 因此改走 `domEventHandlers.keydown`：那里能读**这一次按键自己**的
  `event.isComposing`，不依赖历史状态。keymap 的 `run(view)` 拿不到事件，只能读那个会卡住的 ref。
- ⚠️ **零宽 widget 会让「这一行是空的」变成假的。** 插入型候选采纳前正文一个字节没改，
  所以 `line.text.length === 0` 仍然成立，而屏幕上那一行已经满满一段字——
  「按 space…」的灰字于是直接压在生成出来的文字上。凡是按 `line.text` 判断显示与否的东西，
  都要再问一句「这一行上有没有挂 widget」。
- **默认结果要和「用户十次里做九次的那个选择」一致。** 候选审阅原来的默认是「不动」——
  必须点采纳才落地，于是每次小改写都多一次几乎总是「是」的点击。改成点别处即采纳之后，
  需要主动做的动作从「同意」变成了「不同意」，而后者本来就少得多。
  代价是必须精确地列出**哪些情况不能这样**（见六之一那四条），漏一条就是静默改正文。
- **同一屏里不要出现两块同色的面。** 决策栏原来铺 `--ai-draft-wash`，而正文里被改动的
  几行也是这个绿——读不出「哪块是文章、哪块是控件」。绿留给正文里的改动，栏退成白卡片。

### 九之六、判据从「怎么唤起」改成「回来的是什么」（2026-08-28 第三轮）

- **同一个输入框里可以写「翻译成英文」，也可以写「把长句拆开」——唤起方式说明不了意图。**
  上一版按「预设技能 = 改字、自由指令 = 产新字」分流，于是「选中一段，输入『润色优化一下』」
  停在一张回答卡里：用户要看的是**文章变成什么样**，而卡片给的是「另一段字，要不要插到下面去」，
  连位置都不对。现在改成事后判据 `looksLikeEdit(原文, 结果)`——结果里保留了多少原文的字。
  翻译、提问、续写的重合度接近 0，润色、纠错、拆句的重合度很高。
  分母取较长的一边，判不准时**偏向回答卡**：卡片不碰正文，代价只是多点一下；
  而误判成 diff 时「点空白 = 采纳」会把答案落进正文，两边的错代价不对称。
  `grounding.gate === "rejected"` 的结果一律不走 diff 这条路。
- **「对话」是把已经发生的那一轮搬过去，不是重新问一遍。** 上一版把指令重新发给右栏，
  模型再答一次——用户刚在正文里读完的那段消失了，屏幕上是同一个问题的第二个答案。
  现在走 `/api/assistant/adopt`：服务端把那一问一答落成一段新对话（两条消息都带
  `origin: "editor"`），并打开 `replayHistory`，下一轮模型看得到这段前文。
  这不是伪造记录——那一轮真实发生过，只是发生在另一个界面上。
  **`promptRequest`（问一个新问题，要真跑）和 `handoffRequest`（搬一段已有对话，不跑）
  是两个 prop，不能合并**：划词「问 AI」走前者，回答卡的「对话」走后者。
- **正文里的按钮要能把它指向的地方打开。** 「对话」长在正文里而对话在右栏，
  右栏收着时点它从用户角度看就是「没反应」。`ReaderOverlay` 现在在搬运的同时把右栏
  展开并切到对话页签；右栏本来就开着时不动它，也不改用户存在 localStorage 里的习惯。
- ⚠️ **媒体路径必须在写进正文的那一刻就是合法 Markdown。** vault 目录名带空格
  （`07 - 附件`），而 CommonMark 的链接目标不允许裸空格——`![](07 - 附件/x.jpg)`
  在 `marked`、别的编辑器和发布后的平台上**全都不是图片**，只是一行文字。
  编码在 `markdown-path.js`（只编码有语法含义的字符，中文原样留着——正文是给人读的）；
  `api.imageUrl` 自己还会 `encodeURIComponent` 一次，所以拼 URL 前**必须先解码**，
  否则是双重编码，服务端拿到字面量 `%2520`，图片静默 404。
  已经写进 vault 的老路径由 `renderMarkdown` 的 `encodeImagePaths` 兜一次。
- ⚠️ **原生控件的 `mousedown` 不能 `preventDefault`。** 内联面板靠 `preventDefault`
  防止按下时丢掉正文选区，上一版只放行了 `input`——于是块类型那颗 `<select>`
  **浏览器根本不展开它的下拉**，现象是那个角标点了没反应。原生控件的展开、聚焦、拖选
  都发生在 mousedown 上，`input, select, textarea` 一律放行。
- ⚠️ **class 名对不上是沉默失效。** JSX 里 10 处写 `className="spin"`，而 CSS 只定义了
  `.spinning`——**所有转圈全是静止的**，包括回答卡的「正在生成…」，看着就是卡死。
  这类错不报错、不留痕，单测里钉了一条「用的名字在 CSS 里真的定义了」。
- **选区还在 ≠ 此刻要对选区动手。** 回答卡会把源选区留在选中态（灰底标出它在说哪一段），
  于是编辑器每来一次 update，选区面板就又弹一次，和卡片叠在一起。
  `visibleSelectionMenu` 在有回答卡时直接返回 null。

### 九之七、插入不是审阅、面板减项、正文列宽（2026-08-28 第四轮）

- ⚠️ **光标处插入不是候选审阅。** 右栏那颗「插入」原来一律走 Candidate，而候选审阅回答的是
  「改成这样好不好」——它得有原文可比。光标处插入时原文是空串，diff 全是新增，
  一条 250 字的回复于是被 `candidateTargetKind` 判成「章节」，弹出**整屏「章节审阅」**：
  一次插入被当成一次全篇改造，而屏幕上根本没有第二个版本可比。
  判据和 `looksLikeEdit` 是同一条：**在改用户写下的字才审阅，产出新的字就插入**。
  有选区（`from !== to`）才走候选；否则走续写底纹，插到光标处、点别处即落定，
  和空行生成、回答卡「在下面插入」完全同一条路。
- **每段回复下面那排动作只留图标。** 这条 footer 在一栏对话里重复十几次，
  配上文字之后「复制 / 作为候选插入 / 重新生成」比它上面那段要读的话还抢眼，
  而这三件事的图标都是通用符号。说明进 tooltip 和 `aria-label`，无障碍不受影响；
  按钮同时从「图标+文字」的胶囊改成 26px 正方形，否则撤掉文字后按钮间距读起来是随机的。
- **选区面板里的块类型下拉撤掉。** 它占整整一行，做的事 `/` 菜单里已经有，
  而且那儿是按下去就变，这儿要展开、找、选三步。更要命的是它**答非所问**：
  面板因为「选中了一段字」才出现，而这颗下拉作用在**光标所在那一行**上——
  选中跨三行时它改的不是你选的东西。
- ⚠️ **正文有固定列宽并居中；开合右栏只改两边留白，不改行长。**
  上一版稿件正文铺满整个网格列，收起右栏后一行能排到 90 多个汉字，
  眼睛回到下一行行首要横扫大半个屏幕；而且开合右栏时**每一行都会重新断字**，
  正在读的那句会跳到别的位置。宽度取 860px，和阅读页 `.ws-edit` 一致——
  「读」和「改」用同一套排版参数是选 CodeMirror 时就定下的。

### 九之八、面板开着时选区必须还看得见（2026-08-28 第五轮）

⚠️ **浏览器的原生选区高亮只在拥有选区的那个元素有焦点时才画。**

选区面板底下那条「使用 AI 编辑」是个真的 `<input>`——点进去打字，正文失焦，
那片黄当场消失。屏幕上只剩一个浮着的面板和一个输入框，而「我刚才选的是哪一段」
没有任何痕迹：**用户正要为那段字写一条指令，却看不到那段字。**

修法**不是**把 `drawSelection()` 装回来——那个扩展会顺带把光标画成整个行框的高度
（见九之五第一条），等于为了解决一个问题换回另一个。改成 `editor-held-selection.js`：
面板开着期间给那段区间挂一个自己的底色装饰，它是文档装饰，和焦点无关。

⚠️ 同时必须把这期间的原生选区关掉（`.cm-selection-held ::selection`）。
两层都画的话，编辑器还有焦点时那段字被同一个半透明黄叠了两次、明显更深——
同一段字在「面板刚弹出」和「点进输入框后」是两种颜色，看着像状态变了，而其实什么都没变。

**这条要推广到所有「浮层接管焦点、但正文里还有它指着的东西」的地方**：
回答卡的 `.cm-answer-source` 早就是这么做的，选区面板漏了。凡是靠原生选区
表示「说的是这一段」的界面，只要焦点会离开正文，就必须自己画一层。

### 九之九、浮标与上下文落位（2026-08-28 第六轮，L4 起头）

**浮标（`AssistantOrb`）不是第二个 AI 入口。**

顶栏那颗 AI 键（`Ctrl+I`）一直在，而且按当前页面路由（项目页→协作栏、阅读页→对话页签、
其它→浮层）。再挂一颗常驻浮标就是给一扇已有的门再修一扇门——这个项目已经否过同类的
「一个动作两颗按钮」（见十五）。所以它只在**一种**情况下出现：

> **本屏本来有一列 AI，而它现在收着。**

今天只有项目页符合：协作栏收起是「整列消失」，那片区域于是没有任何东西标着
「这儿本来有 AI」，想要回来只能抬头去顶栏。浮标让**收起和展开成为同一处的两个状态**。
栏开着时不画；阅读页不用它（顶栏已有右栏开关，再加就重复）。它调用的是
和顶栏那颗键**同一个** `focusAssistant`，没有第二条路径。

- ⚠️ **浮标必须挂在 `<aside>` 外面。** 那个 `aside` 收起时是 `display: none`，
  挂在里面等于画了个看不见的东西，而且不报错——现象只是「按钮没出现」。
- 浮标的说明文字**指到才出现**（hover 或键盘聚焦）。常驻过一版：那行字一直浮在正文
  右下角，而它只是给「第一次见到这个圆圈」的人看的，之后每一屏正文都要绕开它。
  ⚠️ 不能只挂 `:hover`——Tab 走到这颗按钮上的人就永远看不到它是干什么的，
  所以 `:focus-within` 一起。读屏走按钮上的 `aria-label`，这段标 `aria-hidden` 免得念两遍。

**「这一轮 AI 读到什么」搬进输入框。**

上一版它在 header：视线在最下面写字，而「读的是全文还是我选中的那段」写在一栏之外
的最上面，每次都要抬头确认一次。现在四个 surface 统一落在输入框顶部
（`assistant-composer__context`）——项目栏交出去的是可点的触发器加它的面板，
其它 surface 是两颗不可点的事实芯片，但**位置只有一处**。

- ⚠️ **面板要向上开。** 触发器搬进输入框之后，`top: 100%` 指的是输入框下沿，
  那是屏幕最底下，面板整个落在视口外面——现象是「点了没反应」。
  `.project-context-panel` / `.project-materials-popover` / 报告错误提示三处都要翻。
- ⚠️ **芯片上写这一篇的名字，不写「当前稿件」。** 分类名对任何一篇都成立，看了等于没看；
  这颗芯片要回答的是「AI 这一轮读的是哪一篇」，能回答这个问题的只有标题。
  同时撤掉了「已用素材 N / 暂无素材」——清单在面板里就有，而「暂无素材」在这儿
  是一句每次打开都在提醒你少干了件事的废话。
- 面板的定位父级也跟着从 header 变成了 `.assistant-composer`（它本来就是
  `position: relative`，因为 `@`/`/` 菜单挂在它上面），锚点仍然 `position: static`。

### 九之十、行首 `+` 与空行光标（2026-08-29）

- ⚠️ **`.cm-line` 的一「行」是整个逻辑段落，不是一行字。** 开了自动换行之后，
  一段两行时它有两行那么高。行首 `+` 原来写 `top: 50%`，算的于是是**整段的中线**——
  两行的段落里它卡在两行之间，三行的段落里卡在第二行上。
  改成让 `.cm-line-affordance` 自己只占 `1lh`（这一行真实的行高，前面留一条 `em` 兜底），
  并且 `top` 要跳过 `.cm-line` 的 padding-top。
- `+` 从 18px 放大到 22px、字号跟正文走：它是行首的一个动作，比字小一圈时读着像个没对齐的点。
- ⚠️ **原生光标的高度等于所在行的行框高度，CSS 管不到它。**
  正文行高 1.65 是为了自动换行后段内不挤——**而空行没有第二行**，那份行距在这儿
  一点用都没有，只是把光标拉成一根比字还高的竖条。所以只对**光标所在的空行**
  把行高压到 1.2，多出来的高度用 padding 补回来：总高度一个像素没变
  （不会因为光标移进移出空行而抖），光标变回字的高度。
  「padding 不抬光标、行高会」在这个编辑器里是第二次用到。
- ⚠️ **`.cm-line` 的 padding 是 CodeMirror 用 `EditorView.theme` 注进来的**，
  选择器是 `.ͼx .cm-line`（两个类）。只写 `.cm-empty-caret-line` 权重更低，
  padding **静默失效**——行高压下去了、高度没补回来，现象是光标移到空行时整段往上跳一下。
- ⚠️ **CodeMirror 会在 widget 旁边塞一个 `<img class="cm-widgetBuffer">`**，
  它是 15px 高的替换元素、按基线对齐，基线下面那点降部把行框从 18px 顶到 20px：
  行高压了，光标还是比字高一截。`vertical-align: top` 让它整个待在行框顶部以内。
  **只改这一行**——这个 buffer 是 CM 用来给光标定位的，全局动它是在改编辑器的光标行为。
- **光标的粗细改不了。** 没有任何 CSS 属性能设置原生 caret 的宽度（`caret-color` 只管颜色），
  它由操作系统和缩放比例决定。要控制粗细只能装回 `drawSelection()` 自己画一根，
  而那个扩展会把光标高度重新钉成整个行框——正是九之五第一条拆掉它的原因。
  这条取舍留在这儿：**宽度不值得用高度去换。**

## 十四、已关闭的产品决定

- **访谈**：作为普通 Skill 进入同一项目会话；结果只使用 answer 或 candidate。
- **整篇正文**：正文为空时可产生 whole-document candidate；正文非空时不提供整篇起稿快捷动作。用户明确要求重写整篇时不得降级为续写，必须进入全文专注审阅。
- **scope**：由语义上下文决定，不由是否可编辑决定。
- **Quick context**：默认只传 page/object reference，不自动传正文、DOM 或页面数据。
- **项目右栏**：采用轻量协作栏，不做三 Tab、mini ChatGPT 或状态 Dashboard。
- **低频设置**：**权限**只在完整 global page；**模型**在所有 global 会话（完整页 + 侧栏）都可切换——
  权限是会话级的「AI 能碰什么」，模型是发送级的「这一条用哪个发出去」，两者不同级，别再合成一个开关。
  Expert 与 Skill 仍只由输入字符触发。
## 十五、明确否决的结构

以下结构与当前产品不兼容：

- 访谈专属页面、Tab、按钮、会话、结果类型或前端分支。
- `if (skill === "interview")` 一类专属渲染。
- 根据 callback 是否存在、编辑模式或页面位置推测 Assistant 能力。
- 让 surface 增加或削弱能力。
- 旧 WritingAssist、ExpertTaskPanel 外壳。
  （**Global Assistant Dock 已不在否决之列**——2026-08-28 起全局 AI 就是并排的一列，见 5.2。）
- CreationDialog 的 interview / material 起稿流程。
- Project / Reading 常驻模型、权限、风格、`@`、`/Skill` 控件。
- 把完整 Candidate 或 Report 压进 336px 右栏。
- Report 同时展示正文、完整报告和完整对话右栏。
- 未经确认修改正文或业务状态。
- 为使用设计参考而引入第二套 UI 基础设施。
- **编辑器顶栏常驻排版工具条**（加粗、标题、列表改的是「此刻选中的那段字」，
  位置必须跟着选区走；顶栏只放对整篇的动作）。
- **把候选放进一个文本框让人和原文并排比**（审阅的信息单位是变化，不是版本）。

  而换内核会让 `[[双链]]`、脚注、`> [!note]` 这些 Obsidian 专有语法在每次保存时被重写）。
