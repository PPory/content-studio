# AI 协作体验

这份文档定义 Xenho OS 现役 AI 体验。存储和端点以 [`design.md`](design.md) 为准，视觉规则以 [`design-system.md`](design-system.md) 为准。

## 核心边界

- SQLite 工作区是正文、关系、状态、版本和审计的唯一真源。
- Pi Agent 负责对话、检索、分析和候选生成，不替代本地域规则。
- AI 不静默改正文、业务状态、发布记录、文件或命令结果。
- 任何有副作用的动作都先显示影响，再由用户确认并交给应用或领域接口执行。
- 个人经历、事实、数据和引语继续受服务端真实性与证据闸门约束。

## 四种表面

### AI 工作区

用于跨项目检索、较长对话和管理历史会话。默认只带用户明确选择的对象，不抓取页面 DOM。会话、附件和候选动作都保存到当前本地工作区。

### 项目协作栏

与当前内容项目并排，读取项目简报、已采用素材和主稿版本。它可以回答问题、给下一步、生成候选，但不能自行推进阶段或替换主稿。

### 编辑器内联协作

处理当前正文或明确选区。适合解释、改写、扩写、压缩、访谈整理和检查。结果先成为候选；用户点击插入、替换或采用后才进入正文。

### Quick Assistant

从任意页面召唤的轻量浮层。默认只有当前位置和明确对象引用，不发送页面正文或 DOM。关闭后保留会话和输入草稿；需要深聊时可继续到完整 AI 工作区。

## Scope 与 Target

`scope` 表示 AI 可以理解的业务范围：

- `global`：当前工作区的通用对话；
- `project`：一个内容项目；
- `reading`：一份书籍、知识或阅读对象。

`target` 表示本轮明确操作对象，例如 draft、selection、workspace-document。是否可编辑由服务端策略和对象状态共同决定；只读对象不能因出现在编辑器或协作栏就获得写权限。

## 上下文原则

1. 默认最少：只发送当前任务需要的字段。
2. 明确引用：正文、素材、附件和外部目录都要由用户选择或由当前对象关系给出。
3. 真实读取：图片必须传真实字节；文本附件必须读取真实内容。失败就说明失败，不按文件名猜测。
4. 来源可见：候选内容要说明使用了哪些项目素材、附件或检索结果。
5. 版本绑定：候选记录生成时的正文版本。正文变化后候选进入 stale，不能直接覆盖新内容。

## 输出类型

### Answer

解释、分析或建议，不带直接落地动作。

### Candidate

可编辑的正文或选区候选。显示原文、候选、生成依据和版本；用户明确采用后才写入。

### Report

审稿、素材、风格、事实核查等检查报告。统一分为：

- 高风险：可能导致事实错误、真实性问题或明显误导；
- 建议修改：影响清晰、结构、证据或读者价值；
- 可选优化：不影响成立，只是表达选择。

AI 报告是建议，不使用 `blocking` 代替真实代码闸门。真实性硬闸和输入校验仍由服务端执行。

### Proposed Action

涉及状态、发布、删除、文件写入或命令的待确认动作。卡片必须写清对象、影响、可恢复性和执行入口；确认前不产生副作用。

## 对话与历史

- 会话支持新建、重命名、置顶、归档、恢复和进入回收站。
- 删除是 SQLite 软删除，保留恢复数据和审计。
- 模型与权限模式属于会话设置，不改变业务对象本身。
- 关闭浮层或刷新页面不丢失已保存会话；运行中请求随连接关闭中止。

## 权限模式

- daily：工作区只读与日常搜索；
- creative：增加创作候选能力，但不开放命令执行；
- developer：可提出受控文件和 PowerShell 动作，仍需确认。

权限由服务端白名单执行。工具接受 mountId 和相对路径；用户授权的外部目录只在对应会话生效，每次访问重新检查越界、链接和数据流。

## 等待与身份

- 等待态分三档，各有专属记号（`components/assistant/loaders.jsx`，用 `thinking-orbs`），不许混用：
  `composing` 等模型开口（还没有一个字）、`working` 已经在出东西或仍在后台跑、
  `weaving` 正在生成候选。同一记号表示两件事，用户就学不会它。
- ⚠️ **尺寸只有 64 和 20 两档，而且是两套独立设计、不是缩放**（各带自己的点数、
  点径和速度）。要一个中间尺寸的做法是**按 64 画、用 CSS 显示成那个尺寸**：
  缩小 canvas 是安全的（下采样只会更锐），放大才会糊。
  等待那颗按 64 画、显示 38——量过 64 / 44 / 38 / 32 / 20 五档，
  38 和它右边那两行文字差不多高，最稳。
- ⚠️ **不给这几块 canvas 设 `color`。** 它自己按主题选墨色（读 `data-theme`，
  读不到退到 `prefers-color-scheme`），`currentColor` 对它无效——
  设了只会让下一个人以为改得动。同理不要手动传 `theme` 把它钉死。
- 面向用户的阶段文案里**不出现运行时实现名**（如「Pi」）。这几句画在等待那一屏上，
  要回答的是「进行到哪一步、跑了多久」，不是「用的哪个运行时」。
- 回复上方不画身份标签。排版已经说清谁在说话：你的话靠右成气泡，它的话靠左占全宽。
- 模型和耗时是**回执**不是标题：挂在该条回复的动作条上、**排在按钮后面**、
  指到才现形（触摸屏一律显示），只变透明度不改布局。
  ⚠️ 排在按钮前面的话，它即使透明也占宽度，会把动作按钮推到整段回复的正中间——
  透明的东西不占位置，只有当它在末尾时才成立。生成中的状态一直可见，那是状态不是回执。
- 空态里问候语和输入框之间留 64px：留白要被感知，得和周围尺度成比例——
  这一屏光输入器就有 105px 高，二三十像素的间距在上下几百像素的空白里读不出来。
- 空态的问候按当前时段说话。固定文案在凌晨两点读起来是错的，
  错在它证明了没人在听；但只分到「早上 / 中午 / 下午 / 晚上 / 夜深了」为止，
  再细就是在替用户下判断。
- 空态不放纯装饰的记号：页名、侧栏项和问候语已经说明了这是哪儿。

## 上下文回执

- 「当前全文 / 选中 N 字」那颗芯片是**回执**：判据是「这一轮**真的带了**什么」，
  不是「这一档**允许**读什么」。⚠️ 按后者写过一版，于是文档没接上时它照样写着
  「当前全文」，而模型回「您尚未开始编写正文」——**界面在替一件没发生的事打包票**，
  用户会照着这条回执去判断模型为什么答错。没带上就不画。
- ⚠️ **正文在请求里的字段名是 `document.body`。** 阅读这条路上游叫 `content`，
  两边的翻译只在 `SideRail` 那一处做。名字对不上不会报错，只会让模型收到空文档。
- 浮层（Quick Assistant）里没有可带的对象时，整颗芯片和图标都不画，
  也不画「后台任务」——那是完整 AI 页该管的事。浮层是「问一句就走」的地方。

## 交互规则

- AI 入口没有明确落点时不展示动作。
- 高频的选区操作必须即时，不为装饰动画等待。
- 运行中显示当前步骤；失败说明具体原因和下一步，已保存正文不受影响。
- 候选采用后给明确回执，并保留修订记录。
- 报告与正文支持双向定位；进入专注审阅时可折叠协作栏。
- Quick Assistant 是 non-modal，不给背景强制 inert；关闭和 Escape 行为必须可预测。

## 验收

- 页面、项目、阅读和 Quick Assistant 使用同一套服务端权限边界。
- 默认请求不包含页面 DOM 或未明确引用的正文。
- 附件按真实字节或真实文本进入模型输入。
- 候选不会自动改正文，过期候选不会覆盖新版本。
- AI 无法绕过真实性、状态机、版本冲突和软删除规则。
- 会话关闭重开后仍在，删除后不出现在活动列表但可恢复。
- 所有持久化测试只使用系统临时目录中的隔离工作区。
