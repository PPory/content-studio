# 中文站内探针

洞察报告的**内容供给审计**怎么补上「小红书/抖音站内」这条腿。

这是一份**操作手册和方法论**，不是改工作台代码时的约束——所以不放在 `CLAUDE.md` 里。要跑探针再读它。

---

## 它解决什么

洞察报告的内容供给审计原来只有 Brave 搜公开网页这一条腿，而小红书站内搜索引擎抓不到——
报告里那句 `coverage_limit: 「不代表微信/小红书站内全量」` 就是这个洞的自白。

**它不是第四个洞察源。** 洞察源答「这周发生了什么」，探针答三件别的事：

| 面 | 答什么 |
|---|---|
| 供给面 | 这话题被切成了哪几个角度？哪个挤哪个空？写透了没？读者买账吗？ |
| 需求面 | 读者卡在哪？谁的话引爆了讨论？他们自己摸出了什么解法？ |
| 对标面 | 我盯的这些人在发什么、什么反响？ |

所以输出落 `tmp/insight-work/<week>/web/`（核实工件）而**不是 `洞察/_material/`**——
放错地方 skill 会把它当第四份周材料读，而它的采样方式根本不是「本周」。

## 两条腿：Museon 选，MediaCrawler 取

两个数据源不是二选一，它们的短板正好互补：

| | Museon CLI | MediaCrawler |
|---|---|---|
| 小红书正文 | ⚠️ **只有 60 字预览** | ✅ 全文，免费 |
| 小红书评论 | ❌ 不支持 | ✅ 唯一来源 |
| 抖音 | ❌ 枚举里没有（TikTok ≠ 抖音） | ✅ |
| 作者身份 | ✅ 真实昵称 + user_id | ❌ 硬编码脱敏 |
| 数字精度 | ✅ 精确整数 | ⚠️「1.6万」缩写，比率误差 ±6% |
| 时间筛选 | ✅ `day` / `week` / `six-months` | ❌ 做不到 |
| 账号风险 | ✅ 服务端跑，不碰你的号 | ⚠️ **跑挂过两次** |

所以正确用法是**串联**而不是并列：

```bash
# 1. 发现：Museon 扫出候选（精确反响 + 真实作者 + 按周筛），并打印下一步命令
node scripts/social-probe.mjs --source museon --keywords "词1,词2" --vision 5

# 2. 深取：只抓选中的 8–10 条（在 MediaCrawler 目录，要扫码，用小号）
#    命令由上一步直接打印出来，含拼好的 xsec_token
python main.py --platform xhs --type detail --specified_id "<url1>,<url2>" \
  --get_comment true --max_comments_count_singlenotes 15

# 3. 合并：全文和评论并回 Museon 的结果，重新出报告
node scripts/social-probe.mjs --merge tmp/insight-work/<week>/web/xhs-museon-search-<date>.json
```

**这比原来盲扫的请求量低一半以上**——账号被盯上过两次，那是请求量堆出来的。
第 2 步**脚本不代跑**：它用你的小号发请求，什么时候跑、跑几条应该是你按一下回车的决定。

其余用法：

```bash
node scripts/social-probe.mjs                                    # MediaCrawler 小红书（老路子）
node scripts/social-probe.mjs --platform dy                      # 抖音（只答「爆没爆过」）
node scripts/social-probe.mjs --source museon --type creator --creators "<user_id>,<user_id>"
```

## 代码结构

采集器产出 IR，渲染器消费 IR，两边互不认识。**加数据源 = 新写一个采集器，渲染层不动。**

```
scripts/probe/ir.mjs                所有数据规则的唯一真源（比率、中位数、四象限、IR 契约）
scripts/probe/from-museon.mjs       museoncli → IR（含读图）
scripts/probe/from-mediacrawler.mjs jsonl → IR（含深取命令生成、合并）
scripts/probe/render.mjs            IR → md + json
scripts/social-probe.mjs            CLI 编排
```

**IR 里最重要的不是数据，是数据的可信度标记：**

```js
body: null                       // 这个源不给正文
body: { text, complete: false }  // 只有 60 字预览，不能用来判断深度
body: { text, complete: true }   // 全文
comments: null                   // 未采集（不等于没有评论）
comments: []                     // 采集了，确实没有
```

**「没有」和「没取到」必须是两个值。** 合成一个的那天报告就开始说谎了——
60 字钩子被当成正文，skill 判出「这个角度写得浅」，而人家写了三千字。
报告顶部那张「这份数据能支撑什么判断」表就是这套标记的出口。

## 方法论（这部分和数据源无关）

- **「这选题有没有人写过」是个会得出错误结论的问法**，答案几乎永远是「有」，
  于是审计退化成恒等于「别写」的函数。产出必须是一张**角度地图**：
  角度 × 密度 × 深度 × 反响 × 新鲜度。而**最值钱的一格不是「没人写」**——
  没人写往往意味着没需求——**是「有人写了但读者没买账」**：角度对、执行不对，最好切入。
- **反响只能用比率，不能用绝对值。** 不同时间发的内容进的流量池不是一个量级。
  用 `收藏率 = 藏/赞` 和 `评赞比 = 评/赞`，且只和**同一批**的中位数比。
  落地是「反响」那一列的四象限：`存`（高赞高藏）/`刷`（高赞低藏，刷过就走）/`冷存`/`冷`。
  实测同一批里搞笑视频 ♥2721/藏32（1.2%）和方法论图文 ♥2406/藏1651（68.6%）点赞是同一量级。
- ⚠️ **不能用 `--sort collects` 取样本。** 按收藏降序拿回来的 20 条全是收藏头部，
  再算它们的中位数，等于拿高收藏的跟高收藏的中位数比——**「刷」和「冷」两格必然为空**，
  而那两格正是最值钱的位置。要看收藏头部就另跑一次，别混进统计样本。
  代码里靠 `representative` 标记挡住：不满足时不算四象限、不画那一列，并说明原因。
- **三面分开呈现，因为它们回答的不是同一个问题**。混在一起需求面会被供给面淹掉，
  而它往往才是选题角度的直接来源。
- **角度、覆盖层级、评论四分类三张表脚本一律留空**，由 skill 填。脚本一旦开始猜，
  「这个角度没人写」就可能是脚本自己造出来的。
- **评论按回复数排，不按赞排。** 赞 = 有多少人有同感；回复数 = 有多少人有话要说。
  - **按赞筛会筛掉最值钱的**：188 条里最直接指向选题的那条（楼主追问「我发现依赖 ai
    之后代码能力变弱了…我不知道怎么办」）只有 ♥27，而点赞过千的几乎全是「太真实了」。
  - **回复数跨帖不可比**：3000 条评论的帖子回复数天然在几百。第一版全局排序，
    结果前 13 有 8 条来自同一篇玩梗帖——**它排的是「哪篇评论多」，不是「哪句话引爆了讨论」**。
    改成每篇先取前 2 条再合并。
- **求助迹象不能只认问号。** 上面那条最值钱的评论**一个问号都没有**。
  所以 `ASK_WORDS` 是问号 + 一张求助词表。它是**标记不是筛子**，标错不丢东西。
- **标出「楼主追问」**。楼主自己补的那条常常才是这篇真正想问的问题。
- **画一个填不满的分区比不画更糟。** 所以「怎么读这份文件」的规则按分区有无条件渲染，
  完整度表里没有图片的源不显示「图内文字」那一行——讲一套本文件里没有的规则，
  读的人会去找那个并不存在的东西。
- **覆盖边界跟着数据走**（写进 json 的 `coverage_limit` 和 md 的头部），不等写报告时再补。
  **「没搜到」和「不存在」差着一整个结论。**
- **供给审计的窗口默认是常青的**：三个月前写透的文章今天照样占着那个位置。
  但「这周有没有新东西」是另一个问题，Museon 的 `--time-window week` 专门答它。
  两个问题都合法，别用一个的答案回答另一个。

## Museon 那边的事实

- **小红书在 schema 里写作 `XHS`。** 数平台关键词时搜 `xiaohongshu`/`小红书` 会得到 0，
  据此判定「不支持中文平台」是错的——踩过。
- ⚠️ **`--content-chars` 对搜索结果无效，`desc` 硬顶 60 字。** 传 4000 也是 60。
  全文只能走 `--intent post`（1 credit 一条）或交给 MediaCrawler（免费）。
- ⚠️ **`--time-window` 只有 `day` / `week` / `six-months` 真生效。**
  `month` / `three-months` / `year` **静默失效**：不报错、照样返回，但混着 5 个月前的笔记。
  推测因为小红书原生筛选只有「一天内/一周内/半年内」三档。代码里直接挡掉，
  **宁可跑不起来，也不要跑出一份你以为筛过其实没筛的数据。**
- ⚠️ **`image_urls` 会把同一张图的不同尺寸当成两个 URL 返回**（`w/576` 和 `w/1440`）。
  实测 20/20 条都受影响，不去重的话读图前 3 张里有 1–2 张是重复的——**少读真正的内页，
  还照样收 2 credits**。按 `?` 前的路径去重并留高分辨率那个。
- **只有一张图的笔记不值得读图**：那张是封面，写的是标题的变体。实测一批 20 条里 14 条属于这种。
  所以 `visionCandidates()` 先按去重后的图片数筛，再在有内页的里面取头部；
  图够多时**跳过第 1 张封面**。
- **读图是这条链路上唯一能读「图文笔记正文在图里」的能力。** 实测一条 60 字预览是
  「你有没有遇到过这种情况…」的钩子，图里是一份 5 页的 Context Window 结构化讲解——
  这个差距用任何别的手段都看不到。
- **计费**：search / creator-posts / post 各 1 credit，**visual-analyze 2 credits**。
  Free 档 1000 credits 是**终身**的，用完不再生（付费档才每月刷新）。
  CLI 里查不到余额，只能去网页 Settings → Billing & Usage。
- **不要拿它替代 Brave + Firecrawl**：那两个有自己的 key、可续费，用终身额度换已经买过的东西。

## MediaCrawler 那边的事实

- **「低粉高赞」做不了，不是难做是关掉了。** 笔记表里作者是 `anonymize_user_id()` 的
  SHA256 截断 + `mask_nickname()` 的「首字\*\*\*尾字」，没有粉丝数字段；creator 模式的
  `save_creator()` 整个函数是 `return`（注释：「创作者个人资料…不再落库，防骚扰」）。
  **这是作者主动加的合规措施，绕它性质就变了。** 要真实作者身份走 Museon。
- **`--specified_id` 接逗号分隔的 URL 列表**，XHS 下写进 `config.XHS_SPECIFIED_NOTE_URL_LIST`。
  所以深取**不需要改它的配置文件**——「不 fork、不改它一行」这条守得住。
  URL **必须带 `xsec_token`**，token 来自 Museon 的搜索结果，这是两条腿唯一的接口。
- ⚠️ **抖音的落盘目录是 `data/douyin/`，不是命令行那个 `--platform dy`。** 两处名字不一致，
  猜错了脚本直接报「找不到目录」——这类只有真跑一次才知道。
- **抖音只值得用来问「这个选题在短视频侧爆过没有」**：`douyin_aweme` 只有标题/文案/互动数，
  视频里讲了什么拿不到。文案长度实测 `[22,32,48,52,61,94,138,223,971]`，知识类账号会把整个
  脚本贴进去，所以文案照显示，但**角度地图不画**。要中文视频侧的文字，**先接 B 站**
  （有官方 AI 字幕接口，零算力），而不是给抖音上 ASR——60–180 秒口播转出来两三百字
  还含钩子和引导关注，**密度才是障碍，不是算力**。
- **抖音一样有 `collected_count`**，所以收藏率在两个平台都能算、能横着比。
- ⚠️ **搜索模式下 `--crawler_max_notes_count` 小于 20 会被无声改写成 20**
  （`core.py` 里 `if config.CRAWLER_MAX_NOTES_COUNT < xhs_limit_count: ... = 20`）。
  creator 模式不改写，那里是真上限——**不设的话它会一路翻到该博主全部笔记**，
  这是最容易一次把账号跑进风控的操作。
- ⚠️ **`--max_comments_count_singlenotes` 从 10 提到 30 会把账号跑挂。**
  实测请求量翻三倍后直接 `DataFetchError: 登录已过期`。**15 是踩出来的上限。**
- **能拿到的只有公开数据**（赞/藏/评/转）。播放量、曝光、完播率、涨粉、粉丝画像全在
  创作服务平台的后台接口里，MediaCrawler 不碰——那半边归 `douyin-data` 那类浏览器自动化。
- **时间戳按量级判断秒/毫秒**，不按平台写死（小红书给毫秒、抖音给秒）。写死的话换个源就静默差 1000 倍。
- **数字要过 `num()`**：平台返回可能是「1.2万」，`Number()` 得到 NaN 会静默变成空值。原始串也留一份。
- 许可证是 **NON-COMMERCIAL LEARNING LICENSE 1.1**，明确禁止商业用途。
- **本地改过它一行**：`config/base_config.py` 的 `CDP_CONNECT_EXISTING = True → False`。
  意思是启动本机 Chrome 但开**独立 profile**——拿到真实浏览器指纹，又不需要在日常浏览器上
  打开远程调试。`git pull` 时注意这一行。
- ⚠️ 它启动 Chrome 时带 `--remote-debugging-address=0.0.0.0`，调试端口绑在所有网卡上。
  用的是一次性 profile、跑完自动关，但**别在公共网络下跑**。
- **一定要用小号。** 风险落点和 Bright Data 完全不同：那边打在代理池上，这边打在你自己的账号上。
  第一次登录撞验证码是常态（全新 profile 无历史 cookie），要人工过一下。
