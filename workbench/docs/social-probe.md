# 中文站内探针

洞察报告的**内容供给审计**怎么补上「小红书/抖音站内」这条腿：`scripts/social-probe.mjs` + MediaCrawler。

这是一份**操作手册和方法论**，不是改工作台代码时的约束——所以从 `CLAUDE.md` 搬到这里。要跑探针再读它。

---

洞察报告的**内容供给审计**原来只有 Brave 搜公开网页这一条腿，而小红书站内搜索引擎抓不到——
报告里那句 `coverage_limit: 「不代表微信/小红书站内全量」` 就是这个洞的自白。
`scripts/social-probe.mjs` 把 MediaCrawler 抓下来的 jsonl 转成探针报告补上这条腿。

```bash
# 1. 抓（在 MediaCrawler 目录，要扫码，用小号）
uv run main.py --platform xhs --type search --keywords "词1,词2" \
  --get_comment true --max_comments_count_singlenotes 30
# 2. 转（在工作台目录）
node scripts/social-probe.mjs --week 2026-W33                 # 小红书搜索
node scripts/social-probe.mjs --platform dy --week 2026-W33   # 抖音
node scripts/social-probe.mjs --type creator --week 2026-W33  # 对标博主
```

- **它不是第四个洞察源。** 洞察源答「这周发生了什么」，探针答三件别的事，所以输出落
  `tmp/insight-work/<week>/web/`（核实工件）而**不是 `洞察/_material/`**——放错地方 skill
  会把它当第四份材料读进去，而它的采样方式（按关键词搜历史热帖）根本不是「本周」。
- **「这选题有没有人写过」是个会得出错误结论的问法**，答案几乎永远是「有」，
  于是审计退化成恒等于「别写」的函数。产出必须是一张**角度地图**：
  角度 × 密度 × 深度 × 反响 × 新鲜度。而**最值钱的一格不是「没人写」**——
  没人写往往意味着没需求——**是「有人写了但读者没买账」**：角度对、执行不对，最好切入。
- **反响只能用比率，不能用绝对值。** 不同时间发的内容进的流量池不是一个量级。
  用 `收藏率 = 藏/赞` 和 `评赞比 = 评/赞`，且只和**同一批**（同关键词/同博主）的中位数比。
  落地是「反响」那一列的四象限：`存`（高赞高藏）/`刷`（高赞低藏，刷过就走）/`冷存`/`冷`。
  只看点赞会把「存」和「刷」排在一起——实测同一批里搞笑视频 ♥2721/藏32（1.2%）和
  方法论图文 ♥2406/藏1651（68.6%）点赞是同一量级。
- **三面分开呈现，因为它们回答的不是同一个问题**：供给面（笔记）、需求面（评论）、
  对标面（creator 模式）。混在一起的话需求面会被供给面淹掉，而它往往才是选题角度的直接来源。
- **角度、覆盖层级、评论四分类三张表脚本一律留空**，由 skill 填。脚本一旦开始猜，
  「这个角度没人写」就可能是脚本自己造出来的。
- **评论按回复数排，不按赞排。** 赞 = 有多少人有同感；回复数 = 有多少人有话要说。
  两条踩出来的：
  - **按赞筛会筛掉最值钱的**：188 条里最直接指向选题的那条（楼主追问「我发现依赖 ai
    之后代码能力变弱了…我不知道怎么办」）只有 ♥27，而点赞过千的几乎全是「太真实了」。
  - **回复数跨帖不可比**，和赞同理：3000 条评论的帖子回复数天然在几百。第一版直接全局排序，
    结果前 13 有 8 条来自同一篇玩梗帖——**它排的是「哪篇评论多」，不是「哪句话引爆了讨论」**。
    改成每篇先取前 2 条再合并。
- **求助迹象不能只认问号。** 上面那条最值钱的评论**一个问号都没有**（「我不知道怎么办，
  求解答」）。所以 `ASK_WORDS` 是问号 + 一张求助词表。它是**标记不是筛子**，标错不丢东西。
- **标出「楼主追问」**（`creator_hash` 与笔记作者相同）。楼主自己补的那条常常才是这篇
  真正想问的问题。脱敏哈希认不出「是谁」，但认得出「是不是同一个人」。
- **抖音适配器 `showBody: true` 但 `angleMap: false`。** 它的 `title` 和 `desc` 完全相同
  （实测 41/41），而**视频里说了什么拿不到**。但「文案里什么都没有」是错的——实测长度
  分布 `[22,32,48,52,61,94,138,223,971]`，知识类账号会把整个脚本贴进文案。所以文案照显示，
  但角度地图不画：多数文案是钩子加标签，拿它判断深度会得出假结论，而**画一个填不满的分区
  比不画更糟**。同理**「怎么读这份文件」里的规则也按分区有无来条件渲染**——讲一套本文件里
  没有的规则，读的人会去找那个并不存在的东西。
- ⚠️ **抖音的落盘目录是 `data/douyin/`，不是命令行那个 `--platform dy`。** 两处名字不一致，
  猜错了脚本直接报「找不到目录」——这类只有真跑一次才知道。
- **抖音一样有 `collected_count`**，所以收藏率在两个平台都能算、能横着比。
- **时间戳按量级判断秒/毫秒**，不按平台写死（小红书给毫秒、抖音给秒）。写死的话换个源就静默差 1000 倍。
- **覆盖边界跟着数据走**（写进 json 的 `coverage_limit` 和 md 的头部），不等写报告时再补。
  探针只看到搜索第一页、排序还是平台给的——**「没搜到」和「不存在」差着一整个结论**。
- **供给审计的窗口是常青的，不是本周的**：三个月前写透的文章今天照样占着那个位置。
  所以用「最热」排序而不是限时间——而小红书那个「发布时间」筛选走的是接口的 `filters` 字段，
  **MediaCrawler 压根不发这个字段**，要限时间只能改它源码。唯一的杠杆是 `SORT_TYPE`。
- **数字要过 `num()`**：平台返回可能是「1.2万」，`Number()` 得到 NaN 会静默变成空值。原始串也留一份。

### MediaCrawler 那边的事实（决定了能做什么、不能做什么）

- **「低粉高赞」做不了，不是难做是关掉了。** 笔记表里作者是 `anonymize_user_id()` 的
  SHA256 截断 + `mask_nickname()` 的「首字\*\*\*尾字」，没有粉丝数字段；而 creator 模式的
  `save_creator()` 整个函数是 `return`（注释：「创作者个人资料…不再落库，防骚扰」）。
  **这是作者主动加的合规措施，绕它性质就变了。** 好在供给审计和需求发现都不需要知道作者是谁。
- **抖音同一套脚本能跑，但只值得用来问「这个选题在短视频侧爆过没有」**：
  `douyin_aweme` 只有标题 / 文案 / 互动数，视频里讲了什么拿不到。要正文只能下载 + 本地 ASR
  （这台机器有 GTX 1650，faster-whisper small 约 10–20 倍实时，**算力不是障碍**），
  但抖音 AI 内容是 60–180 秒口播，转出来两三百字还含钩子和引导关注——**密度才是障碍**。
  真要中文视频侧的文字，**先接 B 站**（有官方 AI 字幕接口，零算力）而不是给抖音上 ASR。
- ⚠️ **搜索模式下 `--crawler_max_notes_count` 小于 20 会被无声改写成 20**
  （`core.py` 的 `if config.CRAWLER_MAX_NOTES_COUNT < xhs_limit_count: ... = 20`），
  小红书一页固定 20 条，所以**最小采样单位就是 20 条**。creator 模式不改写，那里是真上限——
  而且**不设的话它会一路翻到这个博主的全部笔记**，这是最容易一次把账号跑进风控的操作。
- **creator 模式要带 `xsec_token` 的主页 URL**（裸的 24 位 id 代码接受，但平台多半拒）。
  可靠做法是在浏览器打开博主主页直接复制地址栏。**抓自己的号也用小号登录**——公开数据谁都看得见，
  于是发布账号从头到尾不进入任何自动化流程。
- **能拿到的只有公开数据**（赞/藏/评/转），**播放量、曝光、完播率、涨粉、粉丝画像全在
  创作服务平台的后台接口里，MediaCrawler 不碰**。后台那一半归 `douyin-data` 那类浏览器自动化。
- 许可证是 **NON-COMMERCIAL LEARNING LICENSE 1.1**，明确禁止商业用途。
- **本地改过它一行**：`config/base_config.py` 的 `CDP_CONNECT_EXISTING = True → False`。
  意思是启动本机 Chrome 但开**独立 profile**——拿到真实浏览器指纹（比 Playwright 自带
  Chromium 抗检测好），又不需要在日常浏览器上打开远程调试。`git pull` 时注意这一行。
- ⚠️ 它启动 Chrome 时带 `--remote-debugging-address=0.0.0.0`，调试端口绑在所有网卡上。
  跑的时候同局域网设备理论上能控制那个实例。用的是一次性 profile、跑完自动关，但**别在公共网络下跑**。
- **一定要用小号。** 风险落点和 Bright Data 完全不同：那边打在代理池上，这边打在你自己的账号上。
  第一次登录撞验证码是常态（全新 profile 无历史 cookie），要人工过一下。
