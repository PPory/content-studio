# 知识库：Living LLM Wiki

工作台里的知识库遵循 Karpathy 的 LLM Wiki 核心思想：

> AI 不在每次提问时从 Raw 重新发现知识，而是持续把读过的资料编译成一个会增长、互相连接、持续更新的 Wikipedia。

SQLite 是唯一业务真源。Markdown 是 Wiki 页面正文的内容格式，但不建立文件与数据库双向同步。

## 1. 不可偏移的核心

以下条件同时成立，才算 LLM Wiki：

1. Raw 原始资料只读保存，是事实来源。
2. Wiki 的正式产物是完整、可长期阅读的页面，不是 chunk、关键词或事实碎片。
3. 新资料优先修订已有页面，同时可以建立新的概念、人物、组织、方法、主题、比较、总览和综合页面。
4. 每次编译都保留来源引用、页面连接、完整版本和更新原因。
5. 查询优先复用已经整理好的 Wiki；需要核实时才回到 Raw。
6. 有复用价值的比较、分析和新连接可以经用户确认归档回 Wiki。
7. Lint 持续检查矛盾、陈旧认识、孤页、缺页、缺链、缺引用和知识空白。
8. Schema 是运行时真实生效的维护规则，不只是说明文档。

以下情况不能冒充 LLM Wiki：

- 只有 Raw 与全文搜索；
- 每个来源只生成一个孤立摘要；
- 只有词条、事实和关系行，没有完整页面；
- 新来源只新增记录，从不修订旧页面；
- 查询答案只留在聊天里；
- AI 每次重新搜索 Raw、重新总结同一结论。

## 2. 三层架构

    Raw Sources
    books / book_documents
    原文、章节、作者、原链接、发布时间、内容指纹
    只读，不因编译、查询或体检而改变
                     │
                     ▼
    Living Wiki
    wiki_pages / revisions / sources / links
    概念、人物、组织、方法、主题、比较、总览、综合、作品、我的理解
    完整 Markdown 正文、持续修订、互相连接、可回到 Raw
                     ▲
                     │
    Runtime Schema
    wiki_schema_versions
    约束 Ingest / Query / Lint、页面类型、引用、冲突和确认边界

旧的 entries、entry_facts、entity_relations 不再充当最终知识产物。它们作为结构化证据底座保留，并通过独立实体迁入 Wiki 初始页面；后续编译不会被旧词条的全文索引刷新覆盖。

## 3. 页面与版本

wiki_pages 保存当前页面：

- 稳定 ID、标题和页面类型；
- 一两句话摘要；
- 当前完整 Markdown 正文；
- 当前版本号和 Schema 版本。

wiki_page_revisions 保存每次完整页面版本。更新不是在旧正文末尾追加一条事实，而是形成一篇吸收新资料后的完整新版本。

wiki_page_sources 保存 Raw ID、逐字原文、原文位置、内容 SHA-256，以及这段来源对页面的贡献。

wiki_source_snapshots 会在 AI 开始编译时冻结它实际读到的 Raw 全文；wiki_revision_sources 再把每个页面版本绑定到当时的快照与逐字证据。即使原资料随后修订，历史版本仍可回到原证据；审阅期间 Raw 已变化时，旧候选必须重新编译。

wiki_page_links 保存有方向、有含义的页面连接。反向链接由查询生成，不重复保存。

wiki_change_sets 是一次完整的多页变化；wiki_operation_log 是追加式演化记录。

## 4. Ingest：把 Raw 编译进现有 Wiki

    导入一份 Raw
          ↓
    阅读全文
    长文按段读取，但仍属于同一份来源
          ↓
    读取全库紧凑目录
          ↓
    读取相关页面完整正文
          ↓
    生成多页变更集
    新页面 + 既有页面新版本 + 引用 + 连接
          ↓
    服务端逐字证据校验、重复页校验、链接校验、版本校验
          ↓
    用户查看整页前后版本并确认
          ↓
    同一 SQLite 事务写入页面、版本、来源、连接和 Log

长文不再截取前 60,000 字。超过模型单次阅读范围时，会按自然段分块阅读全部正文，先形成带逐字引文的分段阅读记录，再把所有记录编译回同一个多页变更集。分块不会变成多篇来源或多张孤立摘要。

Raw 本身已经是可追溯证据，不在 Wiki 中再建立“来源：……”摘要页。一份来源可能同时影响概念、人物、组织、方法、主题、比较、综合和上层总览；没有知识增量的目录或致谢可以标记为已读但不产生页面，不得为凑页数制造空页面。

来源可通过上传 PDF / Markdown / TXT、粘贴公开网页链接或粘贴一段完整文字进入 Raw。网页链接由服务端读取正文并自动识别标题、作者和站点；本机、内网和云元数据地址会在请求前拒绝。书籍与课程仍从书架导入，避免把章节边界误当成多篇资料。

知识编译模型与聊天模型分开配置；未单独指定时默认使用 `gemini-3.7-flash-high`。

## 5. Query：优先使用已经编译的知识

助手的 knowledge_search 返回顺序：

1. Living Wiki 页面；
2. SQLite 中的 Raw、素材和其他工作台正文；
3. 本轮明确授权的本地文件。

回答应优先复用 Wiki 中已经形成的综合、连接与冲突记录。只有页面证据不足或需要核实精确原文时，才继续读取 Raw。

当一次查询产生可长期复用的比较、综合或新连接时，助手可以用 propose_wiki_page 生成完整页面候选。候选必须基于至少一个现有 Wiki 页面，包含完整正文，继承 Raw 来源并建立页面连接；用户确认后才写入并追加 query Log。

普通聊天不会直接改 Wiki。

在 AI 助手中输入 `@知识库` 会明确触发 Living Wiki 检索；“存入 Wiki”只生成完整页面候选，用户确认后才写入。

## 6. Lint：维护知识网络

确定性检查实时计算：

- 没有任何连接的孤立页面；
- 没有来源引用的页面；
- Raw 内容指纹变化导致的失效引用；
- 尚未完成编译或明确判定无知识增量的 Raw。

全库 AI 体检检查：

- 跨页矛盾；
- 已经过时的综合结论；
- 多次出现但仍然缺页的重要概念；
- 缺失的交叉连接；
- 值得建立的比较页或综合页；
- 需要补充来源的数据空白。

体检先生成报告，不直接改正式知识。处理分成两条明确路径：

- 缺页、缺链、矛盾和缺少综合：AI 只能依据现有 Wiki 页面和已冻结的 Raw 证据生成整页修订候选；旧迁移页面缺少证据快照时，只能从其关联 Raw 重新定位逐字原文并冻结快照，不能伪造引用。用户逐页对照并再次确认后才写入。
- 来源不足和陈旧认识：用户明确同意后，系统只把所选页面名称和通用检索词发给搜索服务，不发送 Wiki 正文、体检描述或私人笔记；搜索结果先形成可查看原文、可逐项勾选的来源候选。确认后才导入 Raw 并进入普通 Wiki 编译，编译结果仍需再次审阅。

来源显示“待审阅”但候选已经不存在时，启动维护会把它改成带原因的失败状态，允许重新编译；模型服务返回 502、503、504 或 524 时会明确说明是上游超时，Raw 不会因此损坏。

## 7. 界面

| 页面 | 路由 | 用途 |
|---|---|---|
| Wiki | #/entries | 当前认知总览、页面索引、健康状态、待审阅变更、最近演化 |
| Wiki 页面 | #/entries/:id | 阅读完整正文、沿连接浏览、查看 Raw 依据和版本历史；明确确认后可移入回收站 |
| 来源 | #/sources | 通过文件、公开链接或文字导入 Raw，批量排队编译，查看每份来源影响的 Wiki 页面数，并从“待审阅”直达对应候选 |
| 书架 | #/shelf | 阅读原始书籍和课程，不承担 Wiki 知识组织 |

## 8. 用户确认与真实性

AI 只生成候选。应用来源带来的多页变更、把探索归档成页面、根据体检修复正式页面，都必须由用户确认。

删除 Wiki 页面也必须在页面详情中再次确认。删除只软删除页面，不删除 Raw、引用、关系和历史版本。

每个由新 Raw 改变的页面必须包含至少一段当前来源中的逐字引用。服务端重新读取 SQLite Raw 校验；引用过短、拼接不实或不存在时，整个页面变更被丢弃。

审阅期间页面若已产生新版本，旧候选会以版本冲突拒绝，必须重新编译，不能覆盖较新的认识。

## 9. 核心验收

1. 重启应用或换会话后，页面、链接、冲突、版本和综合结论仍存在。
2. 编译、查询和 Lint 前后 Raw 正文及哈希不变。
3. 一份有价值的来源能同时创建或更新多张相关页面，但不会复制成“来源”Wiki。
4. 第二份同主题来源会修订已有页面，不制造另一套孤立摘要。
5. 新旧来源冲突时，双方说法和依据都保留，不静默覆盖。
6. 多页变更在一次事务中应用；页面、链接、引用、版本和 Log 同步成功或同步失败。
7. 查询主要读取 Wiki，并能回到 Raw 核实。
8. 有价值的探索能经确认归档，并在之后的查询中被复用。
9. Lint 能发现孤页、缺引用、来源变化、跨页矛盾、陈旧结论、缺页、缺链和知识空白。
10. 新 agent 只读取当前 Runtime Schema，也能遵循相同规则完成 Ingest、Query 和 Lint。
