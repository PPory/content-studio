# 工作台产品重设计提案

状态：待通过核心场景验证的产品方案，不代表现有功能已经完成迁移。
依据：用户反馈、两份创作方法文稿、当前首页和创作入口实现。当前默认起点暂按“继续已有工作”设计；用户的真实使用频率尚待确认，不把假设当作调研结论。

## 1. 产品承诺与边界

帮助个人创作者把零散输入变成自己的理解，并在愿意表达时完成有依据的作品。让上次的思考接得上，让需要的资料找得到，让文章写得下去。

第一阶段服务以文字和知识表达为主的个人创作者。支持持续研究、经历记录、文章及视频文稿；不扩展拍摄、剪辑、团队审批或自动运营。

用户购买的不是更多生成按钮，而是减少三个成本：重新回忆自己想到哪里、在不同库之间寻找材料、为了使用工具而管理分类与状态。

两份文稿是方法参考，不是产品功能清单。知识连接受众问题只是可选方法；研究不必产出文章，创作也不必先经过研究。

## 2. 核心场景与优先级

| 优先级 | 用户处境 | 应提供的结果 |
| --- | --- | --- |
| P0 | 上次研究或写作被打断 | 一次打开恢复原位置、已有内容和相关资料 |
| P0 | 有一句话、一段经历或一份原文，尚未想好用途 | 直接记下并保存，不要求命名、分类或承诺产出 |
| P0 | 已经想写，或已有半篇文章 | 直接进入正文，随时调用材料与协作 |
| P0 | 想弄明白一个问题 | 有可持续积累的研究记录，区别讨论、理解与依据 |
| P1 | 有理解但不知道怎样表达 | 对比少量实质不同的讲法，用户决定采用哪种 |
| P1 | 已完成文章，准备发布或查看效果 | 在这篇作品内完成导出、发布记录和反馈查看 |
| P2 | 想系统寻找可写方向或分析多篇效果 | 从真实积累与发布记录中调用辅助分析 |

## 3. 产品对象与用户语言

“研究、内容、资料库”是找回工作的入口，不是创建时必须选择的三种模板。

- 随手记：统一捕获入口。原话先留下，可补来源；用途未定是正常状态。进入资料库最近记录，不产生待处理任务。
- 研究：围绕一个问题，关联多次讨论、多份资料、用户确认的理解和未解之处。聊天记录只是其中一部分。
- 内容：一份准备对外表达的作品。正文为主体，构思、来源、候选、版本、发布和反馈附着于同一作品。
- 资料：原文、真实经历和用户保存的知识笔记。浏览时允许统一检索，但显示来源与性质；绝不把原始记录和 AI 概括混成同一份事实。

关系：一项研究可以支持多篇作品，一篇作品可以引用多项研究。开始写作只带入用户选中的内容并建立引用，不删除、搬走或覆盖研究。研究之后改变，也不静默改写已引用正文。

合集是内容列表的组织方式；长期方向是创作偏好。两者不成为每篇必填信息。

## 4. 首页：接着做，不经营仪表盘

首页只显示最近进行的研究和内容，用户置顶优先，其次按最后实际编辑时间排序。不给 AI 一次访问或后台任务当作活跃度，不自行判断“这篇最重要”。

每项显示标题、内容片段、最近实际动作与时间；只有用户写过下一步时才显示下一步，不伪造进度总结。点击恢复原工作位置。

固定提供“写一篇”和“记一下”，研究入口在侧栏清晰可见。首次空态简短说明可以写、记或研究，不弹出账号定位向导。

不展示无意义的零计数、自动生成待办、长期积压提醒。搁置不是失败，用户可以从最近工作隐藏，仍能找回。

侧栏以研究、内容、资料库为主要入口；首页承担恢复，不再增设功能分组树。搜索和快速记录全局可用。

## 5. 研究：问题可以长期未解

研究页主区域先呈现当前研究笔记，包含用户自由记录的理解；相关讨论和资料按需打开。没有笔记时可从提问开始，不同时铺出空笔记、空聊天和空资料三块。

用户可以新开讨论、读资料、记录理解，随时往返。AI 回答不会自动写入研究笔记；“整理目前的理解”产生可审阅候选，标明来源与尚未证实的推测。

研究不设置强制完成率或“已搞懂”状态。用户可以记下未解问题，结束这次讨论，之后继续。

“写成一篇”先选择要表达的理解或记录。可以直接使用用户选中的文字；如由 AI 帮忙整理，必须先展示结果。新作品建立后，原研究及原始资料仍在。

研究空间必须支持多次会话，否则只是聊天入口改名，不能算实现。

## 6. 写作：正文只有一个主要工作面

默认布局：文章标题与正文居中；上方少量保存与完成操作；右侧按需打开一个辅助区。构思不再铺在正文之前。

辅助区可切换“构思、资料、协作”，同一时间只展示一种。构思允许自由记录，受众、意图等为可选补充；不提供一排必须填写的策略字段。

空白页允许直接输入。需要协助时再打开协作，不以强按钮催促 AI 起稿。编辑已有正文时，优先保留光标、选区和阅读位置。

比较讲法只在用户提出需求时出现，通常给 2—3 个实质不同的方案：要表达什么、从哪里进入、如何展开、依赖哪些真实依据。选择后回到正文；未选方案保留为历史候选，不常驻正文上方。

采用构思不覆盖正文；替换正文先预览并由用户确认，保留可恢复版本。写作中补充问题，可关联已有研究或新建研究后返回当前篇，无需复制粘贴整段上下文。

内容列表默认“进行中、已发布”，另有归档入口。写完但尚未发布是进行中的可识别状态。底层已有细分状态先保留，由产品视图映射；不为简化菜单破坏发布规则。

## 7. 资料库：减少整理负担，保留事实区别

同一搜索入口找原文、经历和知识笔记；结果通过轻量标记告诉用户它是什么、来自哪里。来源类型和书籍是筛选或阅读方式，不要求用户穿过多级导航。

新增资料先保留原文和出处。标题、标签或分类建议可稍后确认；保存成功不产生“待 AI 处理”的必做任务。

在文章中打开资料，默认查找当前篇已关联的材料；用户主动搜索时再查全库。推荐必须能解释相关性，点开能核对原文。没有依据时显示没有找到，不用生成内容填空。

已有 Wiki 修订与来源追踪继续保留。统一入口不代表合并底层数据，也不建立 Markdown 与数据库双向同步。

## 8. AI 的职责

AI 帮助用户提出问题、找真实资料、比较表达、检查依据和修改候选。它不能替用户宣布已经形成观点、批准事实、决定发布或把研究改造成待办。

每次调用优先使用当前篇或当前研究中明确关联的上下文；跨库查找由用户调用。引用标明来源，不能把其他会话中 AI 说过的话当作真实经历。

保留已有统一协作入口及 /Skill 能力，不再新增全局聊天、专家大厅、采访助手等并列入口。用户发起动作后必须有明确落点：候选、关联资料或可定位的讨论。

后台失败只影响当前操作：资料加载失败仍可写字，AI 不可用仍能保存，保存失败则明确保留本地输入并阻止无提示丢失。用户手动输入沿用原有保存规则，不增加逐次确认；AI 写入正式内容继续确认。

## 9. 旧能力如何处理

| 当前入口或概念 | 目标去向 |
| --- | --- |
| 灵感、想法、种子 | 统一捕获与查找入口，原数据保留，关系和类型在需要时显示 |
| 来源、书架 | 资料库内的筛选和阅读方式 |
| Wiki | 资料库中的知识笔记及其修订、引用能力 |
| 研究聊天 | 研究记录中的讨论；旧会话可直接读，不强制批量升级 |
| 内容机会、构造讲法 | 创作辅助与候选历史，不再要求管理独立流程 |
| 热点、发现方向 | 用户主动寻找方向时调用，退出默认任务清单 |
| 排版 | 作品准备发布时调用，保留旧深链 |
| 复盘、数据 | 单篇发布详情与按需跨篇汇总 |
| 长期议程 | 创作偏好，按需关联，不默认套用最近一个 |

入口下沉先保留深链与数据。未知用途的旧对象不批量转成文章或研究；不删历史来源，不在这次产品调整中重写存储系统。

## 10. 落地顺序与验收

第一步：实现首页恢复与正文优先的创作页，保留现有数据与编辑能力。目标是旧文章打开即写，连续完成“记一下、找材料、写完”，无需学习新名词。

第二步：实现可跨会话的研究记录，完成“提问、看资料、留下理解、隔天继续、选一部分写成文章”。原研究与作品双向可找回，正文和原始来源不被覆盖。

第三步：统一资料入口与搜索，逐项下沉旧入口，再接入作品内的发布和反馈。每次迁移提供记录数量、关系与可恢复性验证，不一次隐藏全部旧功能。

验收采用相同真实任务比较改版前后：记录一段话、恢复半篇文章、从研究产生文章、找到一条引用、记录一次发布。记录导航跳转、重复输入、分类选择、返回后丢失位置及误解对象含义的次数。减少这些成本是目标，不以模块数量或生成次数衡量成功。

必须覆盖：不调用 AI 完成文章；未配置模型仍可记录；空资料库；无研究结论；候选不采用；保存失败后恢复；误操作撤回；多处编辑冲突；旧深链；手机与键盘使用。持久化测试只用系统临时独立工作区。

待用户输入验证：日常最常见起点、研究与写作的实际频率、旧入口中真正高频的能力。未得到输入前采用“继续已有工作”默认，不把这项假设写成已证实事实。
