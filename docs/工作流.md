# content-studio 的工作流

这份文档回答一个问题：**从"看到一个东西"到"发出去并知道效果"，中间发生什么，哪几步是自动的、哪几步必须你出现。**

⚠️ **这份写的是目标状态，不是现状。** 2026-08-23 从第一性原理重新梳理过一遍，
和当前代码有距离；每一节末尾标了「现在有什么」。**加功能之前先回答它属于哪一个动作**。

⚠️ **这份是意图，不是实现说明。** 字段、端点、状态值以 `worker/CLAUDE.md` 和
`workbench/CLAUDE.md` 为准；两边对不上以 worker 为准，并回头修这份。

---

## 使用者与目标

一个**刚起步**的自媒体创作者，主题围绕 AI 但不局限，**目标是每天发一篇**——
长文、短文、图文都算。

⚠️ **「每天一篇」是整份设计最硬的约束，比任何功能都硬。** 它决定了三件事：

1. **决策成本必须极低。** 每天花半小时决定写什么，这事第二周就崩了。
2. **大部分日子写的是短的。** 篇篇深度长文的节奏撑不住，也没必要。
3. **不能有"攒够了才能写"的环节。** 任何让你停下来补料的设计，在这个频率下等于让你停更。

**卡点是两个，而且是同一件事的两面**（使用者原话）：

- 不知道写什么
- 看到一个观点想写，**但不知道自己能加什么**

第二个是根子。因为如果每次看到东西都立刻知道自己要说什么，第一个自动就没了——
**你每天都会看到东西。**

## 三个动作

| | 你在干什么 | 系统在干什么 | 花你多久 |
| --- | --- | --- | --- |
| **反应** | 看到东西，说一句你的看法 | 把它变成一颗能下笔的种子 | 30 秒 |
| **挑一个写** | 从种子里挑今天写哪个 | 摆出它手上有什么、够写多长 | 1 分钟 + 写 |
| **看效果** | 读结论 | 算哪类反应你写得最好 | 每月一次 |

**任何新功能，先回答它属于这三个里的哪一个。三个都不属于的，多半不该做。**

## 中心对象：种子

> **种子 = 你看到的东西 + 你对它的一句话**

不是素材（那是别人的话），不是选题（那要你已经想清楚才有）。**是触发物加上你的判断。**

⚠️ **为什么中心对象不是「素材」也不是「选题」：**

- **素材不会自己变成文章。** 一句金句、一个数据躺在库里，等着被某个判断调用。
  光攒素材不解决"不知道写什么"——**攒种子才解决**。
- **「选题」是个结论，你得先想清楚才有。** 而卡住的那一刻恰恰是还没想清楚。
  种子是个开口：你只需要有反应，不需要有答案。

### 种子和素材的分工

| | 种子 | 素材 |
| --- | --- | --- |
| 是什么 | 触发物 + **你的判断** | 可复用的零件 |
| 回答 | **我要说什么** | **凭什么信我** |
| 时效 | 有（是你某一刻的反应） | 无（长期资产） |
| 归宿 | 变成一篇 | 被很多篇引用 |
| 短文 | 必须有 | 可以没有 |
| 长文 | 必须有 | 必须有 |

⚠️ **素材库不是必经的一层，是一个你写的时候去问的地方。** 它从"关卡"变成"资源"——
这是这次梳理最要紧的一处转变。空着不用焦虑，满了也不用非得用掉。

## 反应：把"我能加什么"问出来

⚠️ **「不知道自己能加什么」的答案，几乎总是同一样东西：你自己的经历、你踩过的坑、
你的工程师背景带来的那个角度。而这些只存在你脑子里，除非有人问你。**

所以「选反应」这个动作真正的价值**不是分类，是把你脑子里的东西问出来**。

人对一个观点的反应就那么几种，**可以穷举、可以提示**：

```
□ 同意，而且我有个例子
□ 不同意，因为…
□ 这让我想起另一件事              ← 连接
□ 这解释了我一直没想明白的 X
□ 这个说法有个前提没说出来
□ 我以前也这么以为，后来发现…
□ 说得对，但只在 X 情况下成立
```

一旦选中一条、补上后半句，**文章的骨架当场就有了**——
「我不同意，因为___」本身就是一篇短文的全部结构。

### 反应会长出素材

```
反应：不同意 —— 卡住不是因为没归到本质，是归到本质后不知道下一步
  ↓ 这个判断你有例子吗？
去素材库找「个人经历」…… 0 条
  ↓ 那你说一句
「我搭工作台时就是——架构想得挺清楚，每天坐下还是不知道先改哪个文件」
  ↓
✓ 存成一条「个人经历」素材   ← 永久资产，下次别的篇还能用
✓ 这颗种子现在有：判断 + 亲身例子 → 够一篇短文
```

**你为这一篇说的那句话进了库。补料这个动作产生复利**——这是素材库存在的全部理由。

## 收：四个入口，三条出口

### 四个入口，同一个动作，形态必须不同

| 在哪看到 | 怎么产生种子 |
| --- | --- |
| **手机刷到** | 飞书发一句。⚠️ **不弹清单**——你随手打的那句话本身通常就带着角度，系统事后归类，你可以不管 |
| **电脑看文章** | 浏览器扩展划词 → 弹反应清单 |
| **干活时想到** | 没有触发物，只有判断。**这是最纯的种子**，也往往是你最有话说的，直接记一句 |
| **AI 情报 / 热榜** | 工作台那一页，每条旁边一个「我有反应」 |

⚠️ **手机那条绝不能加选择步骤。** 那一刻你在刷手机，多一步就等于这条永远不会被记下来。

### 三条出口，判据是"你有没有话说"

| 你的反应 | 去哪 |
| --- | --- |
| **有话说** | → 种子池（主路） |
| 没话说，但是好资料 | → 素材库（等着被某个判断调用） |
| 没话说也没用 | → 扔 |

⚠️ **顺序要反过来。** 现在是「扔进来 → AI 判价值高/中/低 → 拆素材 → 躺着」，
应该是「扔进来 → **先问你有没有反应** → 有反应就成种子 → 顺带拆素材备用」。

理由：**"这东西值不值得留"，你的反应比 AI 的价值判断准得多。**
你有话说就是有价值；你没话说，它再重要也不是你的。
**AI 的价值判断退居二线**，只在你没表态时给个默认。

**现在有什么**：飞书/Telegram 两个 Bot 入口、浏览器扩展、初筛自动拆素材、
逐字保真（金句/数据）、核验闸门 —— **这一段的机制都在，缺的是"先问反应"这一步**。

## 挑一个写

```
从种子池挑今天写哪个 —— ⚠️ 按「你话最多的」排，不按「最重要的」排
        ↓
看它手上有几格
```

### 四格是尺子，不是门槛

```
核心观点     ← 你要说什么
个人经历     ← 凭什么是你说
案例 / 数据  ← 凭什么可信
反直觉点     ← 凭什么读完
```

⚠️ **这不是新发明的分类，就是 `schema.sql` 里的素材类型白名单。**
一篇立得住的文章需要什么，这个产品早就知道，只是从来没拿它来回答"这个现在能写吗"。

| 手上有几格 | 写什么 |
| --- | --- |
| 1 格 | 一条短文 / 一条推 |
| 2 格 | 图文 |
| 3–4 格 | 长文 |
| 几颗种子指向同一件事 | 长文（它们长到一起了） |

⚠️ **缺什么决定写多长，不决定能不能写。** 上一版设计过一个「先补料」的出口，撤了——
**对每天要发的人，那意味着天天在补料、永远发不出去。**

⚠️ **长文不是"更用力地写一篇"，是几颗种子长到一起。** 你会发现某三颗都在说同一件事，
那就是长文的时候到了——而这件事系统能替你看出来（同样的标签、指向同一个判断）。
**这样每天一篇就不靠意志力：大部分日子发短的，攒够了发长的。**

## 写：种子 → 框架 → 草稿

**种子定下来就等于选题定了**，往下是两步，**每一步都能选手写或走 AI**：

| 步 | 手写 | 走 AI |
| --- | --- | --- |
| **框架** | 自己列 | AI 出一版，你改 |
| **草稿** | 自己写 | AI 按种子 + 素材出初稿 |
| 润色 | 自己改 | 划词 AI |

⚠️ **不是一开始选一条道走到底。** 每一步你都可以说"这步我自己来"——
AI 出的每一步都必须**可改、可跳过**。

⚠️ **框架这一步只在长文出现。** 短文强行插一步框架是纯负担：
一个判断加一个例子，直接写就完了。

⚠️ **AI 起稿走的是带真实性闸门的那条路**（`POST /wb/draft/material`）：
只传素材 id 不传正文、模型写出第一人称经历时必须在「个人经历」素材里找到依据，
否则整篇拒绝。**别为了让某条路跑通而绕开它。**

**空白文档仍然在**，它是「一颗空种子」——你就是想写、不想被问。
**它是逃生口，不是主路。**

**现在有什么**：编辑器、按素材起稿（带闸门）、划词 AI、引用标注。
**缺的是框架那一步，以及「种子」这个对象本身。**

## 发 · 看效果

```
排版（公众号走内嵌的 typeset）→ 发出去 → 回填链接
```

⚠️ **「发布后记录链接」是整条链上最要紧的一颗按钮。** 填了 url + 时间，
项目才进「待复盘」，数据回流才有得谈。不填的话这一篇在系统里永远停在"写完了"。

每月看的**不是"哪篇数据好"，是"哪类反应你写得最好"**——
不同意型？连接型？经历型？因为下个月你要决定的是往哪个方向找种子，不是复制哪个标题。

结论回到「每天推给你什么」。

`data/posts.csv`（一条已发布内容一行）和 `data/metrics.csv`（账号级周录）
**是两份东西，不要合并**：发布量、渠道分布从 posts 聚合，metrics 只管粉丝数。

## 哪些自动、哪些必须你出现

| 环节 | 谁 | 花你多少 |
| --- | --- | --- |
| 收进来 | 你 | 几秒 |
| 拆素材 · 逐字保真 · 核验闸门 | **全自动** | 0 |
| **说一句你的反应** | **你**（AI 给清单和追问） | **30 秒** |
| 挑今天写哪个 | 你（AI 排好序） | 1 分钟 |
| 素材伴随 / 梳理想法 | 你按需调用，AI 只给候选 | 不增加新建前表单 |
| 写 | 你 | 本职 |
| 排版发布 | 半自动 | 几分钟 |
| 回填链接 | 你 | 一次点击 |
| 算表现 | 自动 | 0 |

⚠️ **AI 只摆材料，不下结论。** 它该说"你手上有这三格、缺这一格"，
不该说"建议优先级 A / 传播潜力：高"。

理由：**下结论要用到只有你知道的东西——你想成为谁、你最近在琢磨什么、
这件事你是不是真的有感觉。这三样素材库里一条都没有，模型再聪明也是猜。**
而**一个分数会让你放弃思考，一张清单会让你想起来自己知道什么。**

## 明确作废的旧概念

⚠️ **写在这儿是为了防止有人照着旧文档把对的东西改回去。**

| 撤掉的 | 为什么 |
| --- | --- |
| **「灵感 → 素材 → 选题 → 成稿」四层流水线** | 那是制造业隐喻，隐含承诺是"底下喂够了上面就出货"。而写作的因果是反的：**先有想说的话，再去够库存**。 |
| **「选题库要永远有存货」这个目标** | 存货不解决"不知道写什么"。**"哪个现在能下手"才解决。** |
| **三条并行的选题路径（素材/需求/规划驱动）** | 不需要三套流程。它们只是同一个对象的三种信号：素材驱动＝攒着的种子突然够格了；需求驱动＝"有人问吗"有了证据；规划驱动＝种子聚类后的空白。 |
| **「先补料」这个出口** | 每天一篇的频率下，它等于让你停更。改成「缺什么决定写多长」。 |
| **三个并列的创作入口** | 「从素材开始」＝种子已经挑好素材了；「访谈起稿」＝把你脑子里的东西问出来（现在是"说一句"那个动作）；「空白文章」＝一颗空种子。**它们是同一条路上的三个位置，不是三条路。** |
| **「待诊断」阶段** | Worker 里没有任何实现。**没有工具的闸门只是一个多出来的状态。** |
