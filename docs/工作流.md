# 工作流

工作台围绕积累、创作、复盘组织。今日提供继续已有工作的入口；AI 与排版是随时调用的工具。

## 积累

收件箱和素材保留原始触发物、经历与摘录；来源和书架用于阅读原文；Wiki 保存持续修订的知识。研究对话可以跨天继续，不要求先有判断，也不要求每次研究都产出文章。

研究中的「从这次研究发展成一篇」先让用户整理准备带入的原话，再创建内容。AI 回答不自动成为事实依据。知识归档继续走已有 Wiki 候选审阅。

## 创作

一篇内容从最初构思到写作、发布和复盘拥有稳定的项目地址。

- 空白、已有正文、种子和素材起稿继续进入同一个项目页。
- 「发现方向」是可选辅助方法。选择方向后直接创建可写的项目，并把连接保存为未确认探索，不先经过保存机会、再建项目。
- 构思可以只有一句疑问。读者、意图、未解问题、依据和长期方向都可留空。
- 用户编辑的构思自动保存到 SQLite。不同讲法单独保存为候选；采用为构思也不替换正文。
- 构思和正文可以反复调整。AI 辅助写作按需展开，无需先完成简报或绑定 Wiki。
- 材料在项目助手旁直接打开。构思中的说法不算证据，AI 引用的材料必须回到服务端实际来源。

合集负责组织文章；创作方向描述希望读者形成的认识，按篇可选，不因最近编辑过某个方向就自动套用。合集不引入独立的发布状态。

## 发布与复盘

发布仍由用户在外部平台完成，再记录平台、链接和时间。发布数据、读者反馈和复盘关联回原内容，区分事实、判断与假设；已有小实验与反馈回流继续使用。

## 保存与兼容

`project_notebooks` 保存构思、备选讲法及探索状态；版本号防止多处编辑静默覆盖。保存探索不等于采纳 AI，不修改正式正文或 Wiki。

旧内容机会、项目、来源和历史版本均保留；旧机会关联项目时提供只读初始构思。旧路由继续可用，新增探索不必创建机会记录。

SQLite 是唯一业务真源。Markdown 只用于导入导出，正式正文、知识变更、发布和删除继续遵守确认与真实性边界。
