# content-studio 的工作流

这份文档只回答：从看到一个东西，到写完、发出并知道效果，中间应该怎样走。

## 使用者与目标

它服务一个每天需要持续表达的个人创作者。真正的卡点不是“缺一个万能写作按钮”，而是：

- 今天写什么；
- 看到一个观点时，自己能加什么；
- 写过、发过之后，哪些判断值得继续。

## 三个动作

| 动作 | 你做什么 | 系统做什么 |
| --- | --- | --- |
| 反应 | 对一件事留下一句自己的判断 | 保存来源，形成种子或素材候选 |
| 挑一个写 | 选今天要推进的一篇 | 展示相关素材、版本和下一步，AI 只给候选 |
| 看效果 | 记录发布和数据，确认复盘 | 汇总事实，保留下一篇可验证的小实验 |

任何新功能都先判断属于哪一个动作。三个都不属于时，默认不加。

## 中心对象

种子 = 触发物 + 你的判断。

素材回答“凭什么”，种子回答“我想说什么”。短内容可以没有外部素材，但必须有判断；长内容需要更多证据。素材不是流水线关卡，而是写作时按需调用的资源。

## 反应

入口可以是：

- 工作台直接记下一句话；
- 浏览器扩展保存链接、选区或网页正文；
- 热点与已有材料旁的“我有反应”；
- 无触发物的个人判断。

出口由用户决定：有话说就形成种子；值得复用就保存素材；没用就放弃。系统可以给反应清单和追问，但不能替用户下结论。

## 挑一个写

从种子或空白项目开始。项目始终是一条链：来源和判断 → 创作简报 → 可选素材 → 正文版本 → 发布记录 → 复盘。

写作过程允许随时选择：

- 自己写；
- 与 AI 对话理清判断；
- 让 AI 生成可编辑候选；
- 从当前工作区搜索并明确采用素材；
- 对选区做解释、改写或核查候选。

AI 生成的内容不自动进入正式正文。个人经历必须有真实素材依据；事实、数据和引语保留来源与核验状态。系统信息只进结构化字段，不写进正文。

## 发布与复盘

发布由用户在外部平台完成，再回工作台记录平台、链接和时间。只有真实发布记录存在时，项目才进入复盘。

复盘区分事实、判断与假设：先记录数据和反馈，再留下一个下一篇可执行的小实验。历史数据不回写、不美化。

## 数据落点

- SQLite 是状态、正文、关系、版本、审计、发布和复盘的唯一真源。
- 图片、图书原件和附件属于同一个本地工作区，由 SQLite 记录引用。
- Markdown 只用于导入、导出和携带，不参与双向同步。
- AI 模型、翻译、网页读取和本机工具是可选能力；缺失时相关模块独立失败，已保存内容不受影响。

## 当前实现

现已具备本地采集、素材和种子、内容项目、编辑与自动保存、书架、热点、发布数据、复盘、备份恢复、浏览器扩展和 Pi Agent 协作。当前改进重点是减少旧术语和重复入口，让“反应 → 挑一个写 → 看效果”成为唯一清晰路径。
