# content-studio 的工作流

这份文档回答一个问题：**从"看到一条有价值的东西"到"发出去并知道效果"，中间到底发生了什么，哪几步是自动的、哪几步必须你出现。**

写它是因为 2026-08-22 那次梳理：产品有九个状态、四个入口、两条互不知道的选题路径，而**用户说不清自己的工作流是什么样**——那不是用户的问题，是产品没把它说清楚。

⚠️ **这份是意图，不是实现说明。** 具体字段、端点、状态值以 `worker/CLAUDE.md` 和 `workbench/CLAUDE.md` 为准；两边对不上时以 worker 为准，并回头修这份。

---

## 三个动作，不是九个状态

整条链上你只做三件事。**任何一个新功能，先回答它属于哪一件；三件都不属于的，多半不该做。**

| | 你在干什么 | 系统在干什么 |
| --- | --- | --- |
| **收** | 看到东西，随手扔进来 | 判价值、拆素材、归档 |
| **拍板** | 决定这个值不值得写 | 把候选端上来、算好依据 |
| **写** | 写、发、看效果 | 生成初稿、归档、算表现 |

**「收」几乎全自动，「写」几乎全手动，而「拍板」是唯一一处系统和你必须交替出手的地方——所以它最容易做坏，也最值得做好。**

## 收

```
飞书 / Telegram ──┐
浏览器扩展 ────────┼──▶ 灵感库·待初筛 ──▶ [Worker 每 5 分钟] ──▶ 判价值 + 拆素材
工作台「收集」─────┘                            │
                                    高 → 待选题   中 → 存档备用   低 → 已弃用
                                                 │
                                            素材库（拆出来的可复用素材）
```

- **直接发链接或一段话（不带 `/`）= 进灵感库**，5 分钟内自动初筛。
- **带命令的直接进素材库**，跳过初筛：`/金句` `/数据` `/概念` `/案例` `/框架` `/经历` `/素材` `/收藏`。
  这条路存在的理由是**逐字保真**：金句和数据不能让模型转述一遍。
- 初筛会给每条素材算 `核验状态`。⚠️ **金句和数据默认「待核验」，核验之前不进成稿**——这是代码层面的闸门（`assertGroundedGeneratedText`），不是提示词里的叮嘱。

**这一段是好的，不要动。** 它满足"看到就扔，剩下的别烦我"。

## 拍板 ⚠️ 目前最弱的一环

选题**应该**是一次决定，而不是一个仓库。现状是它被当成仓库，而且候选来自两条互不知道的路：

| | 每日整理（在 Worker/D1） | 洞察 Write Queue（在工作台/vault） |
| --- | --- | --- |
| 吃什么 | 20 条「待选题」灵感 + 它们自己的素材 | Reddit / X / AI 日报 / **小红书站内探针**（同类内容有没有人写好、读者在评论里问什么） |
| 出什么 | 标题 + 角度 | 标题 + 读者问题 + 核心主张 + 供给审计 + 证据准备度 + 下一步 |
| 频率 | 每天 14:00 自动 | 每周，你点「跑一次洞察」 |
| 落在哪 | 选题库（状态＝待写） | `tmp/insight-work/<week>/candidate-registry.json` |
| 实际产出 | 5 个选题里 **1 个** | 6 个候选/周，**一个都进不了库** |

**结论：真正符合「选题」这两个字的那一条，产物躺在一个写着「用完即删」的目录里。**

⚠️ **它们没接上不是漏了，是架构上隔着一堵墙**：Worker 有 D1，工作台有 vault 和热点数据，**选题需要两边**。要接的话走已有的先例（`POST /wb/pick/materials`：工作台把材料端上桌，Worker 决定并落库），而不是把数据规则搬去工作台。

**应该长成的样子**（未实现）：一个「待拍板」队列收三个来源——洞察候选、存货聚类、你自己想到的——每条只有三个出口：**写 / 存着 / 不要**。拍了「写」才进选题库。

`candidate-registry.json` 是结构化的，可以直接消费：`title` · `queue_status`（ready / needs_research / weak_signal / watch）· `primary_action` · `priority_score` · 七项评分依据 · `fact_status`。

## 写

```
选题·待写
   │  ⚠️ 你手动改成「撰写中」 ←── 这是整条链上唯一的自动化闸门
   ▼
[Worker 5 分钟内领走] 按主平台生成一篇初稿
   │
   ▼
稿件·在写 ──▶ 写完了 ──▶ 发出去了 ──▶ 复盘
```

⚠️ **「自动成稿」不会自己发生。** 它只领取 `选题状态 = 撰写中` 的选题，而选题默认落在「待写」。**你不动它，它永远不会写。** 这道闸门早就存在，只是界面从没说过——2026-08 那次梳理时，库里 5 个选题全是「已成稿」、0 个「撰写中」，**自动成稿一次都没跑过**。

工作台还为这一步单独做了平台闸门（`PlatformGate`）：勾几个平台就各跑一遍 LLM，**勾五个就是五份 token**。

### 另一条路：手工起稿

工作台「新建内容」三个起点，最后都进同一个编辑器、建同一种稿件：

| 起点 | 做什么 |
| --- | --- |
| 空白文章 | 直接开编辑器 |
| **从素材开始** | 挑素材 → Worker 带真实性闸门生成初稿。**这是这个产品最值钱的一条路** |
| 访谈起稿 | 和 AI 聊出初稿。⚠️ 它绕开了真实性闸门 |

⚠️ **这条路和流水线共用同一张 drafts 表和同一套状态机，但语义不同。** 后果实测过：「建立空白主稿」建的是 `body=''` 的空壳，而空壳照样能被推进后面的状态——**界面会要求你审阅一篇不存在的文章**。所以状态推进必须校验正文非空（Worker 侧，2026-08-22 加）。

### 稿件只有三档

**在写 → 写完了 → 发出去了。**

⚠️ **曾经有第四档「待诊断」，撤了。** 它在 Worker 里**没有任何实现**：没有功能、没有提示词、没有端点，全部含义就是"发出去之前你自己再读一遍"。而屏幕上同时有三种说法指着它（流程线一处、右栏「下一步：开始诊断」一处、按钮「诊断通过，进入发布」一处），其中一个指向一个不存在的动作。

**要加一道审查闸门时，先回答：它有工具吗？没有工具的闸门只是一个多出来的状态。**

### 发出去之后

⚠️ **「发布后记录链接」是整条链上最要紧的一颗按钮。** 填了 url + 时间，项目才进「待复盘」，复盘和数据回流才有得谈。不填的话，这一篇在系统里永远停在"写完了"。

复盘要的两样：表现判断 + 下一篇实验。两样齐了才算「已完成」。

## 反馈

`data/posts.csv`（一条已发布内容一行）和 `data/metrics.csv`（账号级周录）是两份东西，**不要合并**：发布量、渠道分布从 posts 聚合，metrics 只管粉丝数。

⚠️ **这一环目前和「拍板」是断的**：你写过什么起量、哪类内容有效，没有任何地方回流到选题。这是继"洞察候选进不了库"之后的第二个断点。

---

## 已知的断点（按值得修的顺序）

1. **洞察 Write Queue 进不了选题库** —— 每周白白浪费一份高质量候选
2. **选题库是仓库不是队列** —— AI 建议的和你确定要写的混在一起
3. **复盘数据不回流选题** —— "什么起量"影响不了"下次写什么"
4. **访谈起稿绕开真实性闸门** —— 和「从素材开始」抢同一件事，而且少一道保护
