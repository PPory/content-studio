# 情报：现役实现与验收边界

2026-09-07。情报以关注方向驱动主动调研，通用平台热榜不作为来源或失败回落。

## 三个入口

- **选题发现**：查看少量有原文依据的候选，包含研究问题、读者、表达角度、缺口、来源与 Wiki 连接。可以观察、忽略或采用。
- **收集箱**：记录灵感、疑问和参考资料；可检索已收集来源，展开时读取完整正文。
- **关注与调研**：保存主题、来源、账号/社区、采集条数及手动/每日/每周频率；查看进度、失败和恢复入口。

采用卡片会创建选题空间并关联实际来源与 Wiki；重复采用返回同一选题。之后沿用笔记、AI 讨论、文章保存与导出，不自动写入正式正文或 Wiki。

## 来源及执行

| 来源 | 当前实现 | 边界 |
| --- | --- | --- |
| 个人记录 | 从本地资料及手工情报中取相关内容 | 有数量上限，不承诺完整扫描个人知识库 |
| 公开网页 | 复用搜索及原文读取，可用时回落到 Firecrawl | 摘要不作为逐字证据；时间未知只作背景 |
| AI 行业信息 | 先按关注词筛线索，再取原始网页 | 不是通用热榜 |
| X / Reddit | Bright Data 定向账号/社区采集 | 保存前确认付费范围；变更范围重新确认 |
| 小红书 / 抖音 | 限定站点的主题搜索与公开原文读取 | 不承诺登录内容、完整评论或平台全量覆盖 |

运行记录、来源快照、分步进度和候选保存在 SQLite。失败保留成功部分；已有 snapshot 的重试继续查询同一采集，触发结果不确定时要求补回供应商 snapshot ID，禁止盲目重复收费。取消停止后续步骤，已经发出的外部请求无法保证撤销。

日/周调度随本地应用运行。关闭时不运行，重新打开对到期配置补一次；不逐天补齐离线期间所有任务。未开启计划不会自动采集。

AI 最多提出五张候选，可为空。服务端核对来源 ID 和逐字引文；不通过的候选丢弃并显示部分完成。同一关注方向的规范化问题重复时更新原卡，保留采用/忽略状态；不保证所有近义问题都能自动合并。

## 实现位置

- `workbench/server/domain/intelligence.mjs`：配置、调度、状态、来源、卡片与采用。
- `workbench/server/domain/intelligence-runner.mjs`：采集、断点、模型整理与证据校验。
- `workbench/server/routes/intelligence.mjs`：本地接口。
- `workbench/src/pages/Intelligence.jsx`：三个页面。
- `.agents/skills/intelligence-research/SKILL.md`：对话中按需调研；不冒充后台计划工具。

旧素材拼接洞察和素材直接映射候选已退出执行入口。历史报告保留供已有引用读取；不使用旧 vault 输出流程。

## 验收

新增隔离领域/API、浏览器及真实本地任务队列端到端测试，覆盖记录→调研→证据卡→采用→文章保存→刷新→Markdown 导出。测试不写真实用户业务数据。

单次真实公开网页调研已验收：读到一篇原文，保留一张含两处原文证据的候选，另一张因逐字校验不通过丢弃并标为部分完成。X/Reddit 的恢复与防重复触发使用模拟供应商响应验收，未启动真实付费采集；小红书/抖音登录内容未验收。
