# 情报：现役实现与验收边界

2026-09-08。目标是减少无效浏览，让用户遇到值得阅读、能自然讨论的情报。暂不以文章产出为验收目标。

## 页面与数据

- 今日精选：一致结构的卡片；最近更新、较早未读、收藏；可靠内容与值得观察分开。详情先解读，后原文，技术细节折叠。可保存、反馈、屏蔽来源网站。
- 持续讨论：每条精选使用 intelligence:<id> 独立会话；只默认附带解读和公开来源短引文，不附带本地资料全文。阅读不创建选题。明确汇入才关联原文、Wiki 及讨论到新/已有选题。
- 每周回顾：基于实际精选写连贯 Markdown 报告，结合明确反馈及讨论中的问题，附来源及实际日期；资料不足不假装完整周趋势。同一批版本复用报告。
- 我的灵感：保留手工想法、问题及资料，提示真实 Wiki 关联。
- 关注方向：明确兴趣打底，结合真实反馈动态理解。当前只能手动获取一批，持续采集关闭。

精选与旧选题候选独立存储。旧业务数据不删除；同事件沿用 storyKey，更新需要新证据和明确 changeNote，历史版本与阅读版本保留。最多 10 条，最多 2 条待观察，允许少给。服务端验证实际来源及逐字引文；本地笔记不能单独支撑外部情报，推荐理由必填。

## 来源与限制

沿用既有来源清单，AI 按关注方向发现公开来源；测试主题不限制长期兴趣。覆盖大模型发展、概念和使用，个人创造，以及认知学习表达。

| 来源 | 获取路径 | 限制 |
| --- | --- | --- |
| 公开网页 | 主题搜索、原文读取与可用的 Firecrawl 回落 | 摘要只是线索，未知日期不当作新消息 |
| AI Hot 行业线索 | 从 AI Hot 信息流按关注方向选取，再读取原始页面 | 不引入通用平台热榜 |
| X / Reddit | 未授权时公开搜索；已开启原生采集时 AI 从既有清单按方向选择 Bright Data 目标 | 原生采集需已确认范围，不能仅凭密钥假定免费额度；登录与反爬可能失败 |
| 小红书 / 抖音 | 已有指定平台公开读取能力，按需使用 | 不承诺完整正文、评论或登录内容，非默认本次试跑来源 |
| 本地笔记 / Wiki | 相关线索与知识连接 | 不伪装外部新变化，不完整扫描本地知识 |

运行、来源快照、分步进度都在 SQLite。失败保留成功部分；snapshot 重试继续取原任务，触发结果不明确时不盲目重复。屏蔽按网站域名生效。取消不保证撤回已经发出的外部请求。

## 综合分析与来源去重

生成分为资料整理与解读两个步骤：先去除同链接同正文的重复读取，再按事件、共同问题、互补信息或相反观点组织资料，最后每组生成一张卡。平台仅作来源元数据。模型输入按资料平均分配长度预算，避免前面平台耗尽预算；分组会记录在本次运行中。服务端约束引用必须来自对应组，综合组至少采用两个原文链接，同一组不能拆成多张卡。独立文章与单一讨论允许单篇解读；转载不意味着独立证实。

阅读时资料按原文链接归并。同一原文的多段引文各保留原编号；同一帖子里的不同评论保留各自作者、正文和引用，完整原文只显示一次。引文与来源不再一对一生成重复入口。旧正文及版本不重写，展示端将旧“来源N”引用转为“引文N”，已有聊天、收藏、选题引用均保留。
