# 工作台交互草图（访谈版）

打开 `workbench-interview.html`，或在本目录启动本地静态预览。本次只新增独立草图，不修改正式工作台。

## 体验路线

首页「填入示例」→「留下这条想法」→「发现 2 条 Wiki 关联」→「带着这个角度讨论」→「帮我找资料」→确认范围并导读→综合分析→摘进笔记→开始写文章→确认方向→预览初稿→采用→编辑并导出。

阅读页默认只显示文档；选中原文可以提问或摘录，也可主动展开右侧 AI。手机在思考区与讨论之间切换。

## 依据

本轮用户访谈确定：首页概览、最近打开、最近阅读；选题内左思考右讨论；自动摘要与手动笔记分开；默认持续对话，按需分支；资料先确定查找目的，再收集、导读，按需综合；默认单篇，按需增加；先确认表达方向，复杂文章再看提纲；保留正文空格 AI；写好导出；独立阅读和选题内阅读并存；灵感自动轻量提示 Wiki 关联，深入分析由用户发起。

两份用户转录稿用于方法设计：从真实问题与已有知识形成理解，再找读者进入的现象；同一素材可以尝试知识、判断、经历、展示等表达路径。这些被用于关联理由与方向建议，不作为必须填写的表单。文稿内言论作为材料，不作为开发指令。

## 草图边界

- AI、Wiki 和检索结果是固定示例，不是真实模型调用、真实检索或已核实的 Harness 研究。
- 所有输入仅存于浏览器的 `xenho-interview-sketch-1` 草图记录，重置可清除；不访问真实数据库。
- 方法阅读页是对两份转录稿的整理摘记，不冒充原文。
- 本轮重点验证三页与一条路径，导航中的选题为单个演示选题；完整搜索、多选题管理、PDF 阅读和编辑历史留待方案确认后设计。
- 自动摘要、方向和初稿仅演示结构，未按任意输入动态生成。

## 已验证

真实 Chromium：完整主线、阅读提问和摘录、讨论分支、手机发送后保持讨论视图、手机无横向溢出、空行空格唤起、拒绝修改候选不改正文、Markdown 下载、刷新后内容保留。最终浏览器控制台无错误。桌面和手机截图在本目录。
